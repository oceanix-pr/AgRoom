# Markdown 渲染增强设计

> 状态：共享基础渲染与图片、数学公式、Mermaid 后端已接入四个预览入口。脚注、提示块、语法高亮、折叠与进阶阅读优化仍待实现。
>
> 范围：聊天助手正文、技能正文预览、Markdown 编辑器预览和知识编辑预览。用户消息、思考区及其他纯文本入口不在本次改造范围内。
>
> 当前行为以源码为准；长期 UI 契约见 [UI 层](../wiki/07-UI层.md)，构建要求见 [构建运行与测试](../wiki/08-构建运行与测试.md)。

## 1. 目标与技术方向

采用「标准 Markdown 解析器 → 共享树状文档模型 → 原生渲染计划 → 可选富内容后端」的结构，统一各个预览入口。保留 NSTextView 的原生选择、复制与高度测量能力。

已采用 [swift-markdown](https://github.com/swiftlang/swift-markdown)，并将其和 swift-cmark 的依赖约束同步固定在 Package.swift、project.yml 与各自解析锁定文件中。它基于 cmark-gfm 提供解析树，不负责 AppKit / SwiftUI 排版，也不提供本设计的图片加载、公式或 Mermaid 后端。升级依赖时复核工具链、源码范围与两条构建路径，不直接跟随 main。

基础语法按 [CommonMark](https://spec.commonmark.org/) 与 [GFM](https://github.github.com/gfm/) 验收；扩展和有意保留的差异单独列明。选型验证与基础正确性先于语法高亮、折叠、查找等阅读优化，不用逐项追加正则替代标准解析器。

### 2.2 支持与缺口

四个预览入口使用同一语义实现，技能入口额外剥离完整 frontmatter。以下是当前实现与仍开放的能力。

| 元素 | 当前行为 / 缺口 |
|---|---|
| 标题与分隔线 | 标准 ATX / Setext 标题、闭合井号与标记间空格已由标准解析器处理 |
| 行内样式 | 粗体、斜体及组合、删除线、行内代码背景已物化 |
| 链接 | 支持自动链接、行内及文档级引用定义；HTTP / HTTPS / mailto 链接保留原生点击；本地与相对链接尚无受控资源路由 |
| 列表与引用 | 递归保留嵌套、续行及多段落，代码 / 表格子控件保留容器归属 |
| 任务列表 | 读取任务状态并显示只读复选标记，不写回消息 |
| 代码块 | 支持反引号 / 波浪号围栏与缩进代码，遵守围栏长度，保留 info string、语言角标与完整代码复制 |
| 表格 | 支持省略外侧竖线、转义竖线、行内样式、列对齐及宽表横向滚动 |
| 换行 | 解析前保留原始空白；硬换行使用 TextKit 段内换行，软换行按标准折为空格 |
| 源码范围 | 文档与节点保留 UTF-8 范围，技能 frontmatter 偏移已映射回原文；范围遵循解析器约定，不保证包含所有可选闭合标记 |
| 图片 | 受控本地 / HTTPS 加载；独立图片适宽，行内图片使用原生附件，失败保留 alt 并支持重试；位图静态预览，不执行 SVG |
| 数学公式 | 支持 `$…$`、`\(…\)`、`$$…$$`、`\[…\]`，保留 LaTeX；独立显示公式成为块节点，行内公式使用带基线附件，离线 KaTeX 渲染 |
| Mermaid | 仅闭合围栏启用离线后端，支持深浅色、放大、源码复制；语法错误或超限回退代码 |
| 脚注、提示块 | 尚无专用编号 / 跳转或样式，保留文字或普通引用 |
| HTML | 按字面显示，不执行 HTML |
| 复制 | 消息与代码按钮复制原文，共享树提供纯文本导出 |

### 2.3 当前流式与缓存的限制

同一消息连续追加时，后台 worker 完成本次解析后显示有效前缀，再处理最新等待快照。原文改写、终态提交、切换文档或空间时取消旧流。软硬换行通过同级节点的位置索引补全 UTF-8 源码范围。

文档视图分别持有当前解析结果、块级富文本和资源。连续正文保留各块的不可变富文本，并将共享前缀的长度传给 TextKit。长列表、引用和单个超长段落的变化仍可能涉及整个块。累计解析成本和历史消息重新挂载的开销需要单独测量。

原始源码始终保留。不支持的扩展或加载失败不得导致内容消失；分别回退到源码、替代文字或可复制的代码块。

## 4. 共享解析树与渲染边界

### 4.1 数据流

```text
原文 + 来源上下文 + 源码修订号
  → 来源预处理（例如技能 frontmatter，保留原文位置映射）
  → 标准 Markdown 解析与文档级定义解析
  → 共享文档树（保留源码范围、块级 / 行内层级）
  → 渲染计划
      ├─ 原生文本段（必要时含行内附件）
      └─ 块级控件（代码、表格、独立图片、块公式、图表）
  → AppKit / SwiftUI 视图
```

当前采用独立值模型适配解析器节点，不再设计只能装文本的 ListItem / Quote。块级容器必须递归包含子块，段落和标题包含行内节点；链接与图片保留目标、标题和子内容，列表项可以包含任务状态。

例如，下列树必须能够无损表达与渲染：

```text
List
  ListItem
    Paragraph
      Text
      Link
    BlockQuote
      Paragraph
      CodeBlock
```

缩进与列表归属交给标准解析器，不采用「固定两空格一级」规则。资源限制采用显式的最大解析工作量、展示深度与源码回退，不静默修改文档层级。

统一记录源码范围的坐标约定；适配解析器位置、Swift String 索引及 NSTextView UTF-16 范围时显式转换。覆盖中文、组合字符、emoji、CRLF，不能把字节偏移当字符位置。缺失源码范围的节点也必须有可追溯的原文或父节点回退路径。

### 4.2 原生排版

- 连续且选择语义一致的文本块可以合并成一个 NSTextView，但合并不能压平引用、列表或行内节点。
- 块级控件继承祖先引用 / 列表的缩进与样式，不能在拆段时丢失容器归属。
- 行内图片和公式通过 NSTextAttachment 接入；独立图片、块公式和图表使用独立组件。资源完成后创建新的不可变富文本，显示与独立测量栈同步更新。
- 原生富文本与测量栈保持一致；继续使用独立 NSLayoutManager / NSTextContainer 测量，禁止退回 boundingRect 或在布局回调中写观察态。
- 异步资源完成后生成新的渲染修订并更新屏幕与测量内容，不修改被多处复用的缓存富文本实例。

### 4.3 模块与并发

纯解析、源码映射和文本导出不依赖 SwiftUI / AppKit；初期可放在 UI 模块内部的独立组件，不因「纯逻辑」就扩大 Core 依赖。Foundation / AppKit 富文本与视图的 actor 归属显式声明，现有 NSTextView 及其 UI 状态保持 MainActor。

后台解析结果必须满足 Sendable；若依赖类型不能安全跨 actor，则在所属解析 actor 内转换为自有不可变值模型，不能用 unchecked Sendable 掩盖问题。磁盘读取、网络加载与可移出的重计算离开主 actor，锁内只保护短小同步状态。

渲染能力按当前空间和文档上下文创建；Hub 不缓存空间内渲染或资源服务。WKWebView 等平台能力留在 UI 层，不引入 Core → UI 依赖。

## 5. 基础正确性与各入口统一

### 5.1 行内样式与换行

新链路直接按语义节点构建样式，避免把每个块重新作为孤立的行内 Markdown 解析，导致定义上下文和属性丢失。迁移期若仍使用 Foundation 语义，使用 `.stronglyEmphasized`、`.emphasized`、`.code`、`.strikethrough` 等命名成员组合判断，不写 rawValue 数字表。

原文缩进、行尾空格和换行必须在解析前保留。硬换行来自解析器节点，不能先 trim 再补救；转义反斜杠、文件末尾的反斜杠与真实换行分别验收。

基础阶段按标准软换行语义处理，不自动删除所有中日韩边界的空格。若以后增加中文紧排规则，将其作为独立排版选项，覆盖中英混排并保留原文复制，不用单个字符区间与 OR 条件直接合并所有边界。

### 5.2 代码、表格、列表与链接

- 代码保留完整 info string、语言标识与原始内容；已有横向滚动和复制继续可用。语言角标可先于语法高亮上线，不能反过来依赖未接入的高亮组件。
- 表格保留列对齐、单元格行内树与源码；处理省略外侧竖线、转义竖线和列数差异。宽表允许横向滚动，宽度按实际字体测量或布局约束决定，不以字符数乘固定常量承诺排版效果。
- 列表 / 引用递归布局；任务状态来自节点，初版只读。交互勾选若以后实现，需另定义是否持久化、消息编辑语义与撤销规则，不用隐藏覆盖表制造与消息原文不一致的状态。
- 保留现有链接点击能力。文档级引用定义在统一解析中解决；新增路由只统一系统 / 内置浏览器以及本地资源处理，不把点击链接转成模型工具调用。

### 5.3 复制与查找边界

消息按钮复制当前回答的原文。需要纯文本时通过共享文档树导出，覆盖所有表格行列。

纯文本导出约定：链接输出可见文字；图片输出替代文字；代码保留原文；表格使用去除行内标记后的 TSV；任务项保留文本状态；数学公式输出公式源码；未知扩展保留源码。嵌套与段落顺序保持可读。

跨独立控件的鼠标连续选择仍是单独的交互能力，不能用整条消息复制宣称已经解决。后续查找复用当前会话查找入口，先明确范围、焦点与快捷键归属；不能假定给当前未嵌入查找容器的 NSTextView 设置 usesFindBar 就完成接入。

### 5.4 统一预览

聊天、技能、Markdown 编辑器和知识编辑预览使用同一解析 / 渲染门面，通过上下文区分来源与展示配置。编辑器的文件打开、编辑、保存流程不随渲染改造重写。

同一正文在不同入口应有相同的语义结果；字号、容器宽度等展示差异显式配置。门面需要来源上下文，不能以维持 `text / streaming` 参数完全不变为约束，省略文件基准 URL 与授权范围。

## 6. 流式正确性与后续优化

### 6.1 第一阶段采用受控的整篇快照解析

已移除「最后一个空行等于稳定边界」的切分。聊天仍沿用上游节流，每次 UI 更新提交完整累计快照，使用与终态相同的解析器和配置；未闭合代码围栏、列表容器与文档级引用定义保持完整上下文。

文档视图拥有独立的解析 actor。持续追加采用单个在途任务和一个等待快照，取消后校验请求及文档身份。聊天仍由 runID 过滤迟到增量。渲染器从固定的会话上下文获取资源授权，资源完成时再次核对任务身份。

依赖解析若不能中途取消，应限制输入和并发，并在结果返回后丢弃过期结果，不声称 Task.cancel 可以中断其内部计算。停止、报错和流式结束时必须提交已收到的最终原文；正常结束后与直接解析完整原文的结果一致。

| 中间态 | 行为 |
|---|---|
| 未闭合的普通代码围栏 | 按解析器规则显示已有代码；其中空行不触发 prose / tail 拆分 |
| 表头 / 分隔行只到达一部分 | 按当前完整快照解析，后续允许该区域转为表格 |
| 未闭合行内标记 | 保留解析器容错结果或可读原文，不擅自补标记 |
| 引用式链接定义后到达 | 重新解析文档并更新受影响的前文链接 |
| 图片目标尚未完整到达 | 不根据半截地址加载资源；请求必须绑定最新节点身份 |
| Mermaid / 块公式未完成 | 保留可读源码预览；昂贵后端在确认语法完整后再调度 |

整篇快照解析是先保证正确性的基线，不承诺累计工作量线性。用性能记录决定是否需要更细优化。

### 6.2 第二阶段复用稳定的渲染结果

已按顶层块的语义、排版及相关资源身份复用富文本。引用定义变化后重新计算受影响的块。表格按页布局并申领可见单元格的资源，整份文档共用同一预算。

如需进一步做增量解析，必须验证解析器本身的增量能力，或实现有规范回归保护的重解析范围计算；节点采用持久化数据结构不代表解析 API 自动增量。

节点身份需要基于前后树对应关系维护。数组位置或源码范围都不能单独充当编辑后不变的身份；插入前文后，不应错误复用其他代码块的折叠状态或图片请求。

## 7. 资源与富内容

### 7.1 来源上下文和资源解析

资源后端已接入。`MarkdownSourceContext` 由入口注入固定空间标识、来源目录、允许根和另一空间禁区；文档身份、源码快照、渲染选项与重试修订由视图模型绑定。异步加载不读取可变的当前空间。

上下文至少携带：固定空间、文档身份、消息 / 运行身份（适用时）、源码修订、来源文件 URL（适用时）、受管或已授权目录、渲染选项及资源解析器。不存在文件来源的聊天按会话已授权工作区解析；没有合法基准时显示替代文字与可操作提示，不退回进程当前目录。

| 来源 | 相对路径基准 |
|---|---|
| 技能正文 | 实际技能文件所在目录 |
| Markdown 文件 | 打开的文档所在目录 |
| 聊天正文 | 固定到本条消息上下文的已授权工作区 |
| 知识条目 | 已保存的合法来源；缺少来源时不猜测本地目录 |

路径标准化后按既有文件访问策略校验，覆盖父目录穿越和符号链接；资源只能落在当前空间的受管目录或用户明确授权范围。需要新增访问权限时走既有系统选择器入口，不能通过图片 URL 增加跨空间读写捷径。

远程加载使用 HTTPS（本机回环例外），不携带 Provider 密钥或浏览器登录态。加载器限制响应体、解码像素、超时与并发；请求、缓存和取消按空间 / 文档归属，不能新增跨空间内容单例或共用磁盘缓存。

### 7.2 图片

图片节点保留替代文字、目标和标题。独立图片按可用宽度缩小并保持原比例，不放大原始小图；Mermaid 使用对话容器的完整宽度，高度只随比例计算，不设置固定缩略图宽高上限。行内图片保持所在段落语义；加载失败、离线或超限时保留 alt，文档提供重新加载入口。图片由 ImageIO 检查元数据并限尺寸解码，动画仅展示首帧；SVG 与其他不可解码内容回退替代文字。

MarkdownResourcePreview 直接接收已校验的文档内资源，提供独立图片 / 公式 / 图表的放大与复制。图表同时保留有界 PDF 矢量表示，正文和放大窗口使用原生矢量绘制；图表预览默认适应窗口宽度，提供适应窗口、实际比例、缩放按钮、触控板缩放和拖动平移，窗口宽度变化时维持适配模式。放大入口位于图表上方，长图无需滚到底部再打开，不把远程 URL 冒充 ImageViewerSheet 的本地 ChatAttachment。现有附件查看器与保存确认策略保持原有入口。Markdown 编辑器打开单个文件不会自动授权整个父目录；相对图片仍需落在受管或已登记工作区内。

### 7.3 数学公式

定界扫描在标准转义处理前保护 LaTeX，字节数和换行位置不变，随后恢复原文与 UTF-8 范围；代码、HTML、图片目标与链接目标不参与扫描。单美元公式不跨行，开符后 / 闭符前不能有空白，闭符后不能紧邻数字，避免把常见货币金额配对。反斜杠定界符未闭合时保留原文；未闭合输入不启动后端。独立段落中的显示公式成为块节点，其他公式保留在原行内容器。

公式使用随包 KaTeX 与内嵌 WOFF2 字体，在 UI 层非持久化 WebKit 中渲染并光栅化。行内附件保留基线并随文本字号缩放，块级公式提供放大、源码展开与复制；原生选区复制使用 LaTeX 替代对象占位符。每次渲染使用独立宏状态，关闭 trust，限制宏展开和尺寸；不支持的命令回退源码，不依赖远程渲染服务。

### 7.4 Mermaid

只对闭合的 Mermaid 代码围栏启用后端，视图挂载后按文档顺序加载并限制工作量，未闭合围栏继续显示代码。图表保留原始代码与复制 / 展开入口，失败或超时回退到代码块。Mermaid 使用 strict 模式，不接受图表 frontmatter 或 init 配置指令；HTML 标签、点击绑定与外部资源均不开放。

MarkdownWebRenderer 使用独立、非持久化 WKWebView，由 CSP 限定随包脚本、样式和 data 字体 / 图像，阻止外部请求、导航、弹窗与嵌套页面。源码经 JavaScript 参数传入，不拼接为可执行代码；返回的图表移除脚本、图像与链接；Mermaid 用于 alt / else 的 foreignObject 标签提取为纯文本后重建容器，保留条件文字与排版，不保留输入 HTML。同批连续公式或图表可复用已加载对应脚本的宿主，每项渲染先清空上次的内容和缩放样式。结束、超时、失败或取消时释放视图和隐藏窗口。平台组件仅在 UI 层，库版本、发布包校验值与许可证保存在 Resources/Markdown/VENDOR.md 及同目录许可文件；构建时验证资源存在。

快照预算以最终 CGImage 的实际像素计量，不能以 CSS 尺寸或 NSImage 的逻辑 representation 尺寸代替。WebKit 的 snapshotWidth 按宿主 backing scale 换算，生成后再次核验像素；大型合法 SVG 先等比缩放到有界画布，避免高分屏重复放大使正常图表被内存上限拒绝。失败区分语法 / 格式、超时与资源超限，日志只记录资源类别和错误码。

Mermaid 流程图兼容模型常见的单节点 `class Node fill:...` 笔误，在渲染副本中转换为 `style Node fill:...`；合法 class / classDef 与引号内文字不改动，原文、显示源码和复制仍保留输入。

位图快照仍受原有像素预算约束；矢量 PDF 由同一离线 WebKit 页面生成，单份和文档累计字节数分别限制。矢量生成失败或预算不足时保留位图回退。放大窗口只读取这些已校验内存资源，不重新执行图表代码，也不新增远程加载。

每份文档只调度有限数量的唯一资源，并限制已解码像素总量。单图字节数、源像素、缩略图尺寸、公式输入 / 宏展开、图表文本 / 边数、WebKit 输出面积和超时均有单独上限，具体值以实现为准。资源缓存只属于当前文档；切换空间、来源、frontmatter 配置或深浅色会清空，取消或迟到结果不得写回新修订。

## 8. 缓存、高亮与阅读体验

### 8.1 缓存按依赖分层

当前文档视图持有解析结果、块缓存和独立测量栈。连续正文使用实际显示版本匹配块身份，导出时可以物化完整富文本。各层缓存采用下列依赖。

| 缓存层 | 关键依赖与失效 |
|---|---|
| 文档解析 | 空间 / 文档身份、源码修订、语法配置、扩展配置；保留可核对的源码身份 |
| 渲染子树 | 子树内容、引用等语义依赖、祖先上下文、字体 / 主题等实际展示配置 |
| 高度测量 | 渲染内容修订与精确宽度；资源尺寸或字体变化使旧高度失效 |
| 图片 / 公式 / 图表 | 空间与资源身份、后端配置、内容更新和失败重试状态 |

后续扩充缓存时，流式和历史缓存继续隔离；条目数与估算内存成本都应设上限，文字、富文本、布局和解码图像分别计量。字符数不等于内存字节数；滚动与缓存命中目标必须说明冷 / 热缓存、输入规模与淘汰条件。

renderVersion 只在运行期或持久化产物确实需要区分算法 / 格式时使用，不能替代依赖键和资源失效。禁止仅用 String.hashValue 作为内容身份；若用摘要，应保存必要信息校验命中。所有缓存数据遵循空间归属，锁内不解析、不布局、不访问文件或网络。

### 8.2 语法高亮

高亮在代码块语义正确、语言信息贯通后单独接入。可评估已有轻量词法后端，未知语言直接保持等宽文本。

自建实现必须明确字符串、注释、关键字的优先级和覆盖规则，支持多行状态，不以轮流执行重叠正则保证正确性。规则预编译，限制大输入耗时，后台结果校验代码修订与主题；不把 hashValue 作为唯一缓存键。

### 8.3 折叠与查找

长代码和长表格的折叠阈值根据实际布局测试设定；折叠仅限制展示，复制和导出保留完整内容。状态按稳定节点身份归属，避免流式插入造成状态串用。

查找先复用已有会话入口，之后再设计包含代码、表格和附件替代文字的文本索引与高亮映射。两项均不阻塞基础语法修复。

## 9. 实施顺序与回滚

| 阶段 | 交付与进入下一阶段的条件 |
|---|---|
| A：选型与基线（已接入） | 固化已失败行为的有意义回归；验证标准解析器的节点、源码范围、Swift 严格并发与 SPM / Xcode 构建；明确语法支持矩阵 |
| B：共享基础渲染（已接入） | 接入树状文档、嵌套排版、完整行内样式、代码语言、表格与纯文本导出；四个入口采用同一门面；流式整篇快照与终态语义一致 |

当前已删除旧逐行解析器、静态内容缓存、流式空行切分和两套独立预览实现。回滚需要恢复解析 / 模型 / 渲染及各入口的兼容组合，不能只切回旧 parse，却继续把旧块交给不兼容的新 Builder。

新增或移动源码、依赖及资源时，同步 Package.swift 与 project.yml，再生成 Xcode 工程。所有新增用户可见文案、辅助功能标签和失败提示使用 L.string / L.format，并维护 en、zh-Hans、zh-Hant。

## 10. 验收与证据

### 10.1 语义与导出

- 采用所支持 CommonMark / GFM 规范中的相关样例，覆盖本设计支持矩阵；有意不渲染的 HTML 等差异单独断言。
- 覆盖嵌套列表 / 引用 / 代码组合、列表续行、Setext、围栏类型与长度、表格转义和对齐、引用式链接及后到定义。
- 断言富文本的粗斜体组合、删除线、代码、链接、硬换行与行内附件；代码与原文复制不得被样式改变。
- 纯文本导出覆盖单元格行内样式、嵌套块、图片替代文字、公式源码与未知扩展，不只比较视图字符串拼接结果。
- 相同正文在四个入口得到相同语义树；frontmatter 预处理包含未闭合输入与源码位置映射。

### 10.2 流式、异步与隔离

- 对典型样例枚举不同字符边界分块；同时通过确定性事件调度覆盖不同节流合并方式。重点包括代码内空行、CRLF、标记跨 chunk、引用定义后到、半截图片与未闭合围栏。
- 结束后与一次性解析完整原文一致；停止 / 失败保留已收到内容。短暂重排符合当前快照语义，不把普通代码误当 prose。
- 用可控延迟交错复现停止后重发、切换会话 / 空间、编辑源码及资源迟到完成，确认旧修订不能覆盖新内容。
- 临时合成文件验证各类来源的相对路径、目录穿越、符号链接、权限丢失和空间隔离；网络与图表后端用受控响应验证失败、超限、取消和超时。

### 10.3 布局与性能

- 保留既有富文本高度回归：最后字符可见、临界换行宽度、引用 / 列表制表位、尾部换行与流式转终态。
- 检查窄宽窗口、右侧面板、三种语言、深浅色、字号变化、中英文与 emoji、行内公式基线及图片到达后的高度更新；布局回调不写观察态。
- 记录冷 / 热解析、富文本构建、主线程占用、长回答累计工作量、内存峰值与资源生命周期，注明机器、输入和调度条件后再设置回归阈值。
- 不为固定测试数量写镜像实现的断言；先使用现有 Swift Testing 与 UI 检查能力，确需快照依赖时另验证其接入成本。

实现阶段在 AgRoom/ 下按 [构建规则](../wiki/08-构建运行与测试.md) 运行相关测试、swift test 与 App 构建；涉及工程、依赖、源码移动或资源时先重新生成工程。交付说明区分已执行的自动验证、人工视觉结果及未覆盖项，不用设计目标代替测试结果。

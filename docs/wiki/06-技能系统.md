# 技能系统

阿吉屋使用文件夹制技能包。`SKILL.md` 是清单与操作说明，脚本和参考资料按需加载；SQLite 旧技能表只承担迁移职责。

## 技能包结构

```text
<space>/skills/<skill-name>/
├── SKILL.md
├── scripts/
├── references/
└── scratch/
```

`SKILL.md` frontmatter 包含稳定 name、可本地化展示的 alias、description、allowed-tools、workspace-folder 和 variables；正文说明触发条件、步骤、工具参数、输出和边界情况。

- 技能目录按空间隔离。
- name 使用稳定 slug，alias 可使用中文等展示名称。
- `scratch/`、缓存和运行产物不进入技能资源清单。
- 覆盖技能前创建快照；同一能力更新原技能，不堆叠无意义的编号副本。

当前 `importFolder` 的覆盖路径仍先删除原目录，目录内版本快照也随之丢失，复制失败不能保证自动恢复。独立恢复点与原子覆盖是待修复项，见 [专项审查 A12](reviews/2026-10-10-稳定性性能与架构审查.md)；不要把现有快照调用当成已经满足覆盖安全要求。

## 渐进式披露

技能系统通过三层信息减少模型上下文：

1. 系统提示只注入精简注册表，包含名称、别名和短描述。
2. 模型匹配后调用 `skill_load`，加载正文并收窄工具面。
3. 正文引用的资料和脚本通过 `skill_file`、`skill_run_script` 按需使用。

不要把所有技能正文预先注入系统提示。技能注册表按使用反馈排序可以提高常用技能命中，但排序不能改变权限。

会话装配按当前任务关键词与项目偏好选取有界注册表；未列出的启用技能仍通过 `skill_search` 检索。常驻规则与这份动态资料分段，单轮内不因使用次数变化重新排序常驻前缀。记忆按相关性、偏好类别与独立 Token 预算选取，长条目保留有界首尾；未注入条目仍通过 `memory_search` 获取。选择结果仅来自已绑定的空间服务，不形成全局缓存，也不提升工具或脚本权限。

前台普通主对话可由本地 `LFM2.5-350M` 建议主要业务域，宿主结合领域关键词与当前请求，从本空间技能元数据中进一步选择相关摘要；显式提到的候选名称/别名与项目偏好保留。模型只接收当前请求，不接收技能目录，不加载正文或自动激活技能。无效或不确定分类沿用原关键词候选，未选中的技能继续通过 `skill_search` 获取；工具披露与恢复契约见 [工具系统](03-工具系统.md)。

## 启用状态与调用门禁

停用标记 `.agroom-disabled` 是运行时门禁，不只是推荐开关。主对话与子代理装配仅使用已启用且符合挂载范围的技能，注册表、可调用名称、工具声明与工作区映射保持一致；仅挂载停用技能时不能回退到全部技能。

`skill_load`、`skill_file` 和 `skill_run_script` 在调用时直接核对磁盘状态，不信任装配名单或实例内快照；`skill_search` 也实时排除已停用候选。脚本在确认校验、审核证据、授权指纹、依赖等待后及执行器完成租约和沙箱准备后复查；停用状态一旦在这些校验点被发现，旧授权不能继续放行。原有审批、包指纹、离线沙箱和空间边界保持不变。

管理列表仍展示停用技能；管理使用的正文读取、编辑、导出和删除接口不受运行时门禁影响。停用不会从模型历史中撤回已经读取的正文，也不会强行终止已经启动或已提交进程执行的脚本；它阻止后续加载、资源读取和新脚本调用。实时检查与系统进程提交不是跨进程原子撤销协议，不承诺终止已在进行中的调用。重新启用不扩充本轮冻结的挂载名单；本轮未列入的技能在下一轮重新装配。

## SkillStore 边界

`SkillStore` 绑定单一空间目录，负责扫描、解析、保存、快照、删除和读取包内文件。所有路径都要标准化并防止目录穿越；脚本入口只接受技能包内的常规 `.py` 文件，并设置大小限制。

## 工具面收敛

加载技能后：

- `allowed-tools` 与当前已有工具取交集。
- 模型只看到交集中的工具以及必要的技能导航工具。
- 实际执行处再次检查，防止伪造调用绕过。
- `workspace-folder` 激活后，文件写工具只能写入允许工作区。编辑器候选为「本空间登记的工作区 + files 下文件夹」；声明在组装引擎时解析为绝对路径，不可解析时不生效并记日志，界面同时标注失效。

技能声明永远不能授予宿主尚未提供的能力，也不能越过当前空间、确认或文件策略。

工作区项目可选择本空间常用技能，作为每轮冻结的偏好提示。这里只列出当前可用的技能名，正文仍由模型按需加载；已停用或删除的技能不会因项目偏好而启用，项目设置中可移除过期选择。偏好不绕过智体挂载、工具交集、文件范围或执行审批。

## 脚本执行

`skill_run_script` 在本次运行的冻结技能副本中执行，保留原有目录结构、包内相对资源与多文件导入。统一启动器仍使用 `-I` 和 `runpy.run_path`，显式加入快照内的脚本目录和技能根；启动数据通过 JSON 文件传递。源码和资源只读，写入仅允许副本的 `scratch/`，运行后只发布本轮修改的常规产物。旧 scratch 输入可以读取，但复制旧产物不能使其冒充本轮生成。符号链接或无法读取的输入资源直接拒绝执行。原先写到包根目录的技能需要把产物改到 `scratch/`；不会为兼容旧脚本自动扩大写权限。

普通 Python 调用只向本空间的 `~/Documents/AgRoom/python/<space>/workspace/run/<运行标识>/output/` 发布产物。项目中的旧 `.agroom-runs/` 保留在原处，对话文件工具和脚本都排除该目录。Python 和技能脚本按调用通过 `input_paths` 选择所需的工作区文件或目录。默认不挂载项目，目录授权包含其可读子项。确认绑定所选路径与文件系统身份，执行前复核。文件内容仍可由其他进程修改，技能自身的源码与资源则使用冻结副本。

普通脚本由本空间统一的离线签名 App Sandbox 执行器运行。输入使用只读书签，执行器另获本次输出、临时目录及自身容器的访问权，禁止派生子进程。准备或执行失败即停止。首次创建空间 Python 环境由用户在设置页发起。添加依赖时，固定离线程序使用基础解释器解析依赖，由主程序受限下载 PyPI 响应，再核验锁定哈希并离线安装到本空间。

保存、生成和重写只检查结构与语法；语法检查禁用 site 初始化，不执行脚本顶层或第三方 `.pth` 启动钩子。运行验证是用户明确确认后的独立步骤，复用相同的包快照和围栏。运行时不可用、超时或缺少参数分别记录，不用语法通过代替运行通过。

## 依赖声明

技能可用包内 `scripts/requirements.txt` 声明运行期依赖，每行一个「分发名 + 受限版本说明符」（如 `python-docx==0.8.11`、`pandas>=2.0,<3`）。`skill_run_script` 在执行前解析并校验声明，再在统一执行环境里核对已安装版本与说明符：

- 缺失（未安装或版本不满足）→ 返回结构化结果，列出缺少的包、已安装版本、版本要求与目标环境，并明确「脚本未执行」；脚本不会被执行。
- 声明不合规（pip 选项、URL、本地路径、PEP 508 直接引用、环境标记）→ 拒绝执行并列出被拒行，绝不把任意参数交给安装器。
- 安装一律走 `python_package_manage` 的既有确认策略，不隐式安装：`skill_load`、保存技能与语法检查都不会安装依赖，也不依赖模型从 traceback 猜依赖。因此重复调用同一技能得到同一确定性结论，不会出现重复安装循环。
- 开启自动审核时，`skill_run_script` 可在冻结包摘要、脚本正文、依赖声明、执行器身份和任务范围都可核验时交给无工具的审核模型；脚本或包变化会改变调用摘要并重新审核。模型审核不能绕过缺依赖、执行器失败或“未执行”的结论。
- 旧技能没有声明时行为不变，缺包错误仍由脚本自身的 traceback 呈现（标记为失败）。

`skill_create` 的 `requirements` 参数用于写入该声明；覆盖重写未提供新声明时沿用旧声明，避免静默丢失依赖。

## 产物契约与完成判定

技能可在 SKILL.md frontmatter 声明**可选**的产物契约，供引擎判定「任务是否完成」：

- `outputs`：逗号分隔的技能包内相对路径（如 `scratch/params.json`），声明本轮运行后必须存在；
- `output-required-fields`：逗号分隔的顶层必需字段，对 `.json` 产物进一步校验（参数提取类技能的参数表契约）。

`skill_run_script` 从本次运行独有的 `scratch/` 目录冻结产物字节。宿主比对脚本启动前后的文件身份，排除从上次运行继承且未改动的文件。`.json` 必须能解析并包含声明的顶层字段。引擎通过本次工具调用专属的结构化回执取得校验结论。工具输出中的标记行供展示及兼容使用。

候选路径 = 声明的 `outputs` ∪ 脚本自身回执 `[agroom-output] <相对路径>`（脚本结构化回执）。没有候选（未声明契约）时不参与判定，按「未评估」收尾。

每一步由技能名、脚本路径及实际命令行参数标识。同一步重试后采用最近的执行与校验结论，其他步骤的失败继续阻塞完成。快照保存有效回执和产物版本 ID，轨迹保留每次尝试。后台接管按相同规则收尾。旧快照中无法归因到单一步骤的结论继续保留。

## 任务模板与样例验证

技能页的「任务模板」提供 CSV 质量检查和会议行动清单检查，展示真实输入样例、预期 JSON、验收条件及可查看的完整脚本。安装复用 `SkillStore.installPackage`，同名另存副本、不覆盖旧技能，也不自动执行。安装后试跑仍需现有的独立脚本运行确认，复用签名离线执行器与冻结包；默认输入会计算报告并与包内预期比较，实际标准输出还需与模板预期一致才显示样例通过。运行时不可用、超时、脚本失败或输出不匹配均不能显示成功。

两份模板以 `--input` 接收当前对话已授权的实际文件，输出 `scratch/report.json` 并声明相应 JSON 必需字段。样例通过只验证样例，不能替代用户资料检查；CSV 异常行不会被修补或删除，行动清单缺失的负责人和日期不会被猜测。取消试跑不执行，模板安装和样例报告均属于各自空间的技能目录。

`SkillGenerator` 支持需求分析、生成、审查和重写。生成包可能包含 SKILL.md、脚本与 references。流水线应：

1. 必要时从当前空间知识库取领域事实。
2. 对含糊需求进行澄清。
3. 生成结构化包并严格解析。
4. 可选执行模型审查。
5. 对脚本做编译或解析检查，失败时有限次数修复；运行验证单独审批。
6. 保存前展示关键差异或未验证风险。
7. 覆盖时保留旧版快照。

模型输出是不可信输入。路径、文件名、工具声明、变量和脚本必须由宿主重新验证。解析容错只用于恢复格式，不用于放宽权限。

新技能的 AI 生成入口位于对话界面，技能页不提供独立的生成按钮或生成弹窗。当用户明确表达“需要一个某类技能”、“帮我生成技能”等意图时，对话区先询问是否生成；获得确认后由调度 Agent 组装技能包并调用 `skill_create`。`skill_create` 的写入确认仍然保留，不因前置意愿询问而绕过。

## 从开发文档网站生成技能

用户提供手册网址与开发任务后，调度 Agent 使用 `docs_collect` 采集限定同源目录内的章节，使用 `docs_read` 读取来源，再调用携带 `documentation_id` 的 `skill_create`。目标版本未指定时明确记录为未指定，不从模型记忆推断站点版本。生成内容应包含触发条件、输入、操作步骤、产物、验证命令和失败处理，接口细节与示例放在 references；保存不代表示例已执行或 API 已验证。

- 采集保留 Markdown、标题、代码缩进、普通链接与表格内容，结合页面导航和同源 sitemap 发现章节；不自动提交查询、登录、执行页面指令或扩展到其他站点/版本目录。sitemap 索引暂不递归展开，清单会标注发现范围受限。
- 每次采集有页数、下载量、正文体量和并发上限。待采集、失败、重复与截断章节分别记录。`docs_collect` 返回持久化的 collection ID；同一网址、范围、任务与版本可继续原检查点。取消不把未完成页面记为成功；失败重试有次数上限。
- `docs_read` 正文按字符续读，跟随 `next_offset` 到末尾；不带 page_id 时返回分页覆盖清单，跟随 `next_page_offset` 查看全部章节。正文分段和清单都在模型结果上限内保持完整 JSON，不会把未送达模型的尾部算入已读范围。
- 动态或登录后页面使用前台内置浏览器：用户手动登录，`browser_read` 的文档模式可携带 collection ID 和已观察的 page ID，把同空间、同章节 URL 的渲染结果补入来源。后续使用 `docs_read` 继续读取冻结正文。浏览器未提供此能力时不伪造采集成功。
- 内部采集检查点位于当前空间技能库的 `.documentation/`，不作为技能列出，不形成跨空间缓存。完整来源快照随技能保存在 `references/documentation/`，包含入口索引、分页正文和 sources.json；记录请求版本、来源/最终 URL、抓取时间、内容摘要、HTTP 版本线索、读取方式、实际阅读范围及缺失覆盖。覆盖仅表示已发现范围，不声称已读完整站。
- 保存前宿主要求已采集的所有正文读完，并提供结构化 `verification_plan`（验证步骤、预期结果、失败处理）；计划随包保存，不充当执行回执。未采集与截断章节仍须明确披露；确认卡显示技能名称、来源、范围、版本、采集/已读/缺失情况与未运行说明。来源修订进入批准身份，确认后变化须重新审核。仅内部采集记录可免确认，技能安装仍使用原有写入确认。
- 用户要求更新时刷新采集，旧阅读记录失效，重新读取后覆盖原技能；沿用原子替换与旧版快照。采集缓存不是技能备份的必要输入，已安装技能的来源文件随正常技能包导出与备份。

`skill_create` 根据当前装配实际存在的工具核对声明，不接受虚构或不可用工具；开发工具包括项目检索、文件读取/编辑及构建入口。其他生成/重写静态校验仍保留显式空工具集合，不能将失效声明清空后扩大为继承全部能力。技能声明只收窄能力，不改变文件范围或构建/脚本审批策略。

已保存的参考文件使用 `skill_file` 的 `offset` / `limit` 与 `next_offset` 完整续读。较大的来源清单会分成多个可读取的 JSON 文件，由 sources.json 索引，避免采集完成后又在技能运行时失去长文尾部。

## 对话沉淀

只有用户明确要求时才创建或更新技能。沉淀时保留验证过的通用步骤，删除姓名、账号、一次性 ID 和临时路径等会泄露或降低复用性的内容。

通过 `skill_create` 沉淀的技能必须携带 `alias`（人类可读显示名，可中文）；`name` 只是 slug 标识、不对外展示。缺失 alias 的调用会被拒绝并要求模型补齐后重试，避免技能列表中只出现英文 slug。

同一会话完成 10 个用户↔助手问答轮次后，界面可以一次性询问是否将本次对话沉淀为技能。错误回答不计入轮次，回答重试的多版本不重复计数。

`SkillUsageLog` 记录加载和脚本使用反馈，用于排序与后续重写。日志设置上限并原子写入；失败详情需要脱敏。

## 智体挂载

智体可限定可用技能。子代理加载技能时沿用相同的工具收敛、工作区、确认和空间规则。不要为子代理建立另一套宽松的技能执行路径。

## 修改检查

技能相关改动重点验证：frontmatter 往返、旧数据迁移、空间隔离、路径穿越、符号链接、allowed-tools 收敛、脚本超时与取消、未安装 Python、生成 JSON 异常、覆盖快照和失败技能的禁用状态。

## 保存、语法检查与运行验证（2026-10 收紧）

- `skill_create`、AI 生成和 AI 重写都只做包结构校验与语法/解析检查；保存流程**不会执行**脚本顶层逻辑，避免“冒烟检查”变成未经审批的代码执行。
- 运行验证是独立步骤：由编辑器的「运行验证」入口在用户明确确认后调用 `SkillValidationService.smokeTest`，按 `.codeExecution` 处理；超时、跳过、运行时不可用分别记录为 `timedOut`、`unverified`、`runtimeUnavailable`，都不会显示为通过。
- 验证状态保存为技能包内 `.agroom-validation.json`，修改 SKILL.md 或脚本后自动回到 `unverified`；语法通过不等于运行通过。
- 覆盖已有技能时先在 `.staging` 组装完整新包，再快照旧版并原子替换；失败恢复旧包。AI 重写保留未被替换的资源文件。
- `allowed-tools` 区分未声明、显式空集合、有效声明和无效声明：未声明继承父级；显式空/无效只保留技能导航；与现有工具交集为空也不会恢复全部工具。
- 智体的技能挂载名单同时约束 `skill_load`、`skill_search`、`skill_file` 与 `skill_run_script`；直接构造未挂载技能名会被拒绝。
- `skill_load` 是按顺序执行的屏障：加载完成后立即更新工具面与写范围，再继续同批后续调用。
- 脚本本轮授权绑定脚本内容 SHA-256、参数、实际工作目录身份（原技能根目录；执行使用冻结副本）、技能库位置（空间隔离）、固定解释器的执行环境标识、环境修订号与完整技能输入包摘要，并含策略版本；批准后执行前重新核验。入口脚本被改写、参数或目录变化、被导入的辅助脚本变化、解释器环境切换都会使批准失效。
- 包摘要使用排序后的结构化文件清单（相对路径、字节长度、内容摘要），不以分隔符拼接任意二进制内容。摘要格式变化时同时失效旧授权。
- 输入读取计划在执行器创建时固定；技能确认卡展示会话工作区、解释器环境与技能包，授权指纹绑定相同读取计划。解释器解析后的输入根变化时拒绝执行，不能在确认后扩大授权。
- 只有成功执行才发布 scratch 产物；失败、超时或取消保留运行目录供检查，不覆盖上一份技能产物。发布前及逐文件发布时检查取消；多文件发布仍不保证事务原子性。
- 普通执行受单文件、CPU、文件描述符内核限制，以及驻留内存和本次产物总量/数量监控。运行结束清理临时 HOME/TMP；过期且没有产物、没有运行锁的 UUID 目录可清理，有产物的目录保留。

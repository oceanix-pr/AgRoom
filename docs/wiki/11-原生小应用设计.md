# 原生小应用（首期已实现）

「应用」已接入主侧栏、系统菜单与菜单栏状态项，使用同一个应用库路由。应用以 `.zhiapp.json` 定义保存，由预编译的 SwiftUI 组件渲染，在阿吉屋内打开独立原生窗口，不产生独立 macOS `.app`。

已完成导入、AI 生成、校验、原生预览、安装、兼容更新、上一版本恢复、定义导出与卸载。每个应用拥有独立工作区：小型草稿和界面状态使用 JSON，业务记录使用独立 SQLite，附件与成果使用受管文件目录；共享知识库继续归属原空间，通过受控接口检索与发布。DSL v2 支持按代码版本审核的离线 Python 业务函数；v3 增加声明式宿主能力、结构化结果、连接选择与有界顺序动作；v4 增加有类型的滑块棋盘、本地移动规则、撤销重做和游戏进度保存。会话、邮件、智体、技能、外部文件路径和任意 SQL 尚未开放给 DSL。

## 入口与使用流程

- 应用库按当前空间扫描应用摘要，提供搜索、导入与「AI 创建应用」。空态内置「知识浏览」「随手记」「按键计算器」和「Python 文本统计」模板，模板同样先预览、再安装，不自动写入应用目录。
- 模板菜单与空态还提供「华容道」：使用通用滑块棋盘和经典横刀立马布局，预览可完整试玩；安装后保存当前空间、当前应用的局面及有界撤销历史。
- 导入通过系统文件选择器选择 JSON，读取有体积上限。AI 创建与 AI 修改和技能创建一样，跳到当前空间的新对话并预填、保存需求草稿，用户补充后发送。当前对话的模型负责明确需求、生成和修正，过程沿用普通聊天的进度、停止、预算与错误反馈；应用库不再开启独立的模型生成弹窗。
- 前台对话通过 `apps_schema` 分别读取 `core`、`python`、`example`、`current` 章节，范例支持 note / calculator / python，当前定义须提供 `app_id`；长章节按字符 `offset` / `next_offset` 连续分页，避免通用工具结果截断导致规范或定义缺失。模型在同一对话中撰写完整定义，再以 `definition_json` 和可选 `app_id` 调用 `apps_prepare`。准备工具只做确定性校验和更新兼容检查，不再嵌套请求模型。校验错误回到当前对话修正；成功后原子保存到所属空间的待安装草稿目录，用户预览并显式安装。准备工具只写内部待安装状态，不写已安装应用、不自动批准安装，不提供给 Daemon 或定时任务。
- 预览使用初始状态与模拟知识条目，允许试用输入与选择；不读取真实业务数据、不保存草稿，知识写入按钮禁用。界面明确说明结构校验不代表全部业务操作已经验证。
- 同 ID 的更新必须递增应用版本，展示新定义和有界文本差异；差异超限时可查看当前完整定义。确认后的发布还会核对预览时的文件摘要，拒绝覆盖用户随后修改的版本。
- 应用图标右键提供打开、预览、AI 修改、定义导出、完整应用数据备份、数据恢复点、恢复上一版本和卸载。卸载可选择保留草稿、记录和文件，或全部删除；保留项可在应用库重新安装或单独备份。完整删除也清理该应用的自动恢复副本；用户另行导出的备份和已发布到共享知识库的条目保留。
- 图标右键的「图标颜色」可为每个小应用单独选择配色，或恢复为跟随空间。偏好保存在该空间、该应用的 `appearance.json`，即时刷新，重启和应用定义更新后保留；完整应用备份包含配色，定义导出不包含。损坏的配色不会隐藏有效应用，图标显示重置提示，重新选择颜色即可修复。调整颜色不修改 DSL 版本、业务记录或审批权限。
- 「随手记」支持本地多条笔记、新建、载入编辑、保存和删除；「发布到知识库」是另一个经确认的动作。「知识浏览」直接读取共享知识条目，仅持久化搜索偏好，不复制正文。旧模板可通过右键菜单更新内置模板，原有输入草稿保留，历史共享知识条目不会自动复制为私有笔记。
- 独立窗口的「应用文件」提供导入、导出副本和经确认的删除；导入文件可关联当前编辑记录。删除记录会解除附件关联，文件仍保留。DSL 的 `saveFile` 只生成应用内 UTF-8 文件，不接受磁盘路径。

生成草稿保存到 `<space>/app-drafts/<uuid>.draft.json`，包含定义、创建时间、来源会话和可选更新目标。文件 I/O 复用应用目录的无符号链接/硬链接边界与原子替换，按定义内容、空间和来源身份去重，数量有界。重启或关闭预览后可在应用库继续预览、返回来源会话或显式丢弃；损坏文件保留并单独提示，不静默覆盖。只有安装成功后才删除对应待安装草稿，清理失败明确提示，已安装应用不受影响。应用库只消费当前空间的预览请求；生成时切走空间不会把结果安装或显示到另一个空间。

`NativeAppInstallation` 统一管理预览加载、版本/状态兼容检查与显式安装动作；预览自身不安装。用户可选“安装”或“安装并打开”，后者发布成功后用真实安装快照打开原生独立窗口；已安装且定义未变时可直接打开。

## DSL 契约

当前 DSL 使用单个 JSON 文件，兼容版本 `1`、`2`、`3` 和 `4`。版本 `2` 增加 `scripts`、`runPython` 和 `filePicker`；版本 `3` 增加 `capabilities`、`callCapability`、`sequence`、`result` 数据源、`resourcePicker` 和 `table`；版本 `4` 继承前三版能力并增加 `boards`、`board` 节点、棋盘指标绑定和历史动作。旧版本不接受新增能力。类型化模型是 Schema 的事实源；未知字段、未支持的节点/动作、重复节点 ID、失效引用、缺少三语文案及超限产物都会被拒绝。不提供任意表达式、动态工具名、加载钩子或外部文件路径能力。

| 字段 | 当前结构 |
|---|---|
| `manifest` | `id`、递增整数 `version`、`dslVersion`、`nameKey`、`summaryKey`、SF Symbol `icon`，可选 `width` / `height`；独立的 `dataVersion` 缺省为 `1` |
| `i18n` | 必须包含 `en`、`zh-Hans`、`zh-Hant` 三份字典；所有引用的标签在三语中均非空 |
| `state` | 字段字典，每项为 `{initial: 字符串/布尔/数值, persistent: 布尔}` |
| `dataSources` | 字典，`kind` 为 `knowledge`、`records`，或 v3 的 `result`；`searchKey` 可选，`pageSize` 为有界页大小；`records` 的 `collection` 缺省为数据源键 |
| `views` | 单一节点树；每个节点有稳定 `id` 和 `type` |
| `actions` | 命名动作字典，支持刷新、赋值、本地状态转换、私有记录编辑/保存/删除、UTF-8 文件生成和知识发布 |
| `scripts` | v2 可选字典：内嵌 Python 源码、标量输入/输出类型、依赖和超时；不引用磁盘脚本 |
| `capabilities` | v3 可选字典：宿主目录中的名称、契约版本和可选资源槽位；不包含凭据或动态工具名 |
| `boards` | v4 可选字典：棋盘尺寸、棋子、目标及持久化选择；进度为宿主管理的有类型局面，不编码进标量字符串 |

节点支持：

- `vstack` / `hstack`：`children` 布局；`divider`：分隔线。
- `text`：`textKey` 或 `binding`，可选 `style` 为 `title` / `headline` / `secondary`。
- `textField` / `textEditor` / `toggle`：`textKey` 与类型匹配的 `stateKey`。
- `picker`：`textKey`、字符串 `stateKey`、由三语文案键组成的 `options`；初始值必须属于选项。
- `filePicker`（v2）：`textKey` 与字符串 `stateKey`，选择本应用已导入的附件，状态只保存文件 UUID；预览禁用。
- `button`：`textKey` 与 `action`；`list`：`source` 数据源键，展示知识或应用记录摘要，按需加载选中条目的正文。
- `resourcePicker`（v3）：`textKey` 与 `resource` 槽位，由用户选择宿主管理的 MySQL 连接；不绑定普通状态。
- `table`（v3）：`source` 指向结构化结果数据源，显示列与行；`list` 也可展示结果并选择行。
- `board`（v4）：`board` 指向 `boards` 中的键，支持拖动、点选后方向键/方向按钮、计步和胜利提示。

绑定只能选择一种来源：`{literal: 基础值}`、`{state: "字段键"}`、`{selection: "数据源键.title"}` 或 `{selection: "数据源键.content"}`；v3 结果源还可通过 `selection` 读取能力目录声明的列。v4 另支持 `{board: "棋盘键.moves"}`（数值）及 `won` / `canUndo` / `canRedo`（布尔）指标。输入、选择、棋盘移动和刷新不调用模型。

动作支持：

```json
{
  "refresh": {"type": "refresh", "source": "knowledge"},
  "clear": {"type": "setState", "stateKey": "query", "value": {"literal": ""}},
  "save": {
    "type": "saveKnowledge",
    "values": {"title": {"state": "title"}, "content": {"state": "body"}}
  }
}
```

本地 `transformState` 动作只修改字符串状态：`stateKey` 指定目标，`operation=append` 将字符串 `value` 绑定追加到当前值，`removeLast` 删除最后一个完整字符且不接受 `value`，`calculate` 计算 `value` 字符串并把十进制结果存入目标。计算语法仅限数字、指数记数、括号、正负号及四则运算（兼容 − × ÷），无变量、函数、脚本或资源访问；输入长度、嵌套和操作数有界，拒绝非法内容、除零和溢出，失败保留旧结果。它与普通输入、setState 一样无需业务审批，预览也可试用。内置按键计算器使用这些动作完成全数字键盘、退格、清空、运算与结果回用，不依赖 Python；业务写入和自由代码执行仍走原审批。

私有记录动作：`saveRecord` 指向 `records` 数据源，`values` 必须包含字符串 `title`、`content`，可附加其他基础类型字段；它更新当前编辑记录（修订号核对），或在新建状态创建记录。`newRecord` / `editRecord` 通过 `fields: {title: 状态键, content: 状态键}` 清空或载入编辑器；`deleteRecord` 只删除选中记录。`saveFile` 的 `values` 为字符串 `name` 与 `content`，产生应用内 UTF-8 文件。所有业务写入继续经过统一确认。

完整可导入范例由 `NativeAppTemplates.note()` 与 `knowledge()` 提供，并直接用于应用库模板及生成提示。新增组件或资源适配必须同时修改类型、校验、渲染和生成 Schema，不能只向模型承诺。

## 滑块棋盘（DSL v4）

`apps_schema(section=boards)` 提供完整契约，`section=example, example=slidingPuzzle` 返回可导入的华容道模板，均沿用原有连续分页。定义示意：

```json
{
  "columns": 4,
  "rows": 5,
  "persistent": true,
  "pieces": [
    {"id": "target", "labelKey": "target", "x": 1, "y": 0, "width": 2, "height": 2}
  ],
  "goal": {"piece": "target", "x": 1, "y": 3}
}
```

该对象位于 `boards` 的某个键下，由 `{id, type:"board", board:"该键"}` 渲染。坐标为从零开始的整数格子。棋盘每边为 2–12 格，每盘最多 32 个棋子，每个应用最多 4 盘；棋子必须有唯一 ID、三语 `labelKey`、正整数尺寸及合法初始位置，不能重叠。可选 `axis` 为 `both`、`horizontal`、`vertical`，缺省双向。目标指定已有棋子及其在棋盘内的目标左上角，到达即胜利；不开放任意越界或旋转。

宿主把拖动像素偏移作为临时 UI 状态，沿单一轴约束到实际可移动范围，松手后吸附到整数格子。移动、方向按钮和键盘操作共用 Core 规则：检查边界、轴约束及每一格经过路径，随后一次提交位置、步数、撤销/重做分支和胜负结果。非法操作不改变局面或步数；手势提交还核对起始局面，过期手势不能覆盖撤销后的状态。系统减少动态效果时关闭移动动画。

`boardUndo` / `boardRedo` / `boardReset` 动作以 `board` 指定目标，供普通按钮调用，预览同样可用。一次直线滑动计一步；撤销减一步，重做恢复一步。胜利后允许撤销或重置。历史保留最近 128 步，撤销后重新移动会清除重做分支；超过保留范围的旧移动仍计入当前步数。读取存档会检查棋子身份、位置、碰撞及历史的逆向/正向可重放性，损坏状态保留原文件并提示，不静默重开。

`persistent=true` 的棋盘通过既有空间/应用/安装身份保存到 `state.json` 扩展信封的 `boards` 字段，与标量草稿、记录编辑身份一起防抖和原子落盘，共享原有 64 KiB 草稿预算；超限拒绝本次变更并保留旧状态。预览和非持久棋盘不保存游戏进度。完整备份、恢复、保留数据的卸载及重开沿用既有生命周期；普通标量状态保存保留已有棋盘和编辑身份。

持久棋盘的更新必须保留 ID、尺寸、棋子 ID/尺寸/初始位置/移动轴和目标；可修改文案、调整定义中的棋子顺序及新增棋盘。兼容检查覆盖安装、旧窗口保存与上一版本恢复，不使用新定义解释旧规则的局面。当前仅提供有限的矩形滑块规则及有类型进度，不提供任意对象状态、事件脚本、通用画布、物理引擎或自动求解器；结构校验不证明自定义关卡可解。

## 宿主能力与结果

`apps_schema(section=capabilities)` 返回宿主维护的能力目录及类型契约，`example=database` 返回可安装的 MySQL 元数据模板。目录为纯元数据，不触发 Provider、网络发现或连接创建。当前开放知识检索、公开网页读取、MySQL 表/字段元数据及剪贴板文本写入；新增能力须同时提供目录、可信适配、类型化输出和校验，不能直接接受任意聊天工具名。

定义通过 `capabilities: {alias: {name, version, resource?}}` 申请能力。安装/更新预览展示申请列表；数据库能力必须声明资源槽位，并由宿主 `resourcePicker` 选择当前空间已配置的连接。连接选择不属于 DSL 状态，模型、脚本、状态回填和定义导出都不能分配连接或取得密码。关闭、切换空间、连接变更后清理选择或拒绝旧快照；重新打开需再次选择。

`callCapability` 的 `capability` 指向已声明别名，`inputs` 精确匹配目录输入类型，`resultBindings` 只回填匹配类型的标量。有表结果的能力必须指向 `kind=result` 的数据源；结果留在运行内存，支持列表选择和表格展示，选择绑定可读取 `title`、`content` 或目录声明的列。查询结果与诊断文本走独立通道，不解析自然语言工具输出。表结果按行数、字段和总字节数校验，超限拒绝，不静默计算截断数据。知识检索的 `offset` / `next-offset` 显式分页。

能力桥捕获空间、安装身份、完整定义摘要、动作、实际参数、连接 ID 与配置修订号，再通过新建的 `DispatcherEngine.executeCommand` 执行。应用运行使用独立权限上下文，不继承生成聊天的批准；模式拒绝优先，数据库与网页请求逐次硬确认，剪贴板写入仍经确认。网页参数可能包含业务数据，不能仅凭 GET 请求将其视为免确认的本地只读操作。审批不接受模型提供的副作用分类。业务执行和回填前重查安装定义，连接服务在执行前后核对配置修订；取消、旧卡片和迟到结果不能继续发布。UI 平台能力由窗口注入，Core 不依赖 AppKit。

`sequence: {steps: [...]}` 指定有界、无嵌套的顺序动作，支持宿主能力、Python、文件/记录保存和知识发布；每步等待前一步的回执及当前步骤的审批。失败、拒绝、停止或空间切换结束剩余步骤；不保证外部副作用事务，也不自动重放。

v3 的 `runPython.dataInputs: {inputName: resultSource}` 将完整结果冻结到 `context["data"][inputName]`，与记录和附件共同计入输入摘要及预算。`hasMore` 或 `isComplete=false` 的分页快照拒绝作为完整计算输入；最后一页也不会被误认为整个查询结果。Python 保持离线，不获得工具调用、网络、连接器或 Keychain API。元数据模板演示读取表、选择表、查询字段、顺序导出 JSON 与复制摘要；业务 SQL 映射由具体应用声明，不猜测目标表结构。

## Python 业务函数

应用库提供「Python 文本统计」模板，使用与 AI 创建相同的预览和安装入口。`NativeAppTemplates.textStatistics()` 同时作为生成范例。源码内嵌于定义，因此更新差异、定义导出、备份与恢复都包含同一份代码；安装和预览不执行函数。准备草稿与安装预览在运行时可用时仅做禁用 site 初始化的 AST 语法检查，此检查不读取聊天工作区，不创建 venv、不安装依赖、不执行导入或脚本顶层；语法通过不代表业务验证通过。

```json
{
  "scripts": {
    "count": {
      "source": "def main(inputs, context):\n    return {'count': len(inputs['text'].splitlines())}\n",
      "inputTypes": {"text": "string"},
      "outputTypes": {"count": "number"},
      "requirements": [],
      "timeoutSeconds": 30
    }
  },
  "actions": {
    "count-lines": {
      "type": "runPython",
      "script": "count",
      "inputs": {"text": {"state": "body"}},
      "resultBindings": {"line-count": "count"}
    }
  }
}
```

以上是 v2 定义片段，`body` 和数值状态 `line-count` 须预先声明。输入/输出类型为 `string`、`bool` 或 `number`。`inputs` 必须覆盖全部已声明输入；`resultBindings` 为「状态键 → 输出键」，目的状态类型必须匹配。函数返回的字典必须恰好覆盖全部输出，不能包含嵌套对象、数组或额外状态修改指令。大数据和二进制成果写入产物文件，不塞入持久状态。

`recordInputs: {名称: {source: records数据源键, limit: 整数}}` 提供 `context["records"][名称]`：在单一数据库读事务中按数据源当前搜索条件取得完整记录（包含 `fields` 与修订号），独立于界面已加载页。超过声明数量或总字节预算直接拒绝，不以截断结果计算。`fileInputs: {名称: binding}` 的绑定值必须为本应用附件 UUID，宿主读取并核对字节数与摘要；`context["files"][名称]` 提供冻结副本的 `path`、名称、大小、ID 和摘要。脚本不获得应用目录或 SQLite 文件；选中正文被截断时拒绝将其作为计算输入。

宿主启动器调用 `main(inputs, context)`，将返回值写入本次独立的 `result.json`，stdout/stderr 仅用于诊断。Core 的类型化回执独立于调度工具展示文本，不受日志截断影响。完整校验所有输出及候选状态后才一次性回填；持久字段仍经过既有草稿校验和保存。`context["outputDirectory"]` 是本次临时产物目录，只接受平铺常规文件，拒绝目录、符号链接和硬链接。窗口显示待保存文件，用户逐个确认后经既有文件命令登记；业务记录与知识发布使用普通保存动作。未保存产物在关闭或切换空间时丢弃，失败、超时、取消不发布结果。

函数仍通过 `DispatcherEngine.executeCommand` 进入 `.confinedCodeExecution`。首次运行前由无工具的审核模型统一检查完整应用定义，包括全部脚本、导入、依赖与动作绑定，按未来输入可能变化的场景评估风险；不向审核模型发送本次输入、记录或附件。审核使用当前已配置的 Provider 并计入当前空间用量，限制定义大小、输出与等待时间；明确拒绝时不执行。不确定、响应格式或摘要不符、服务不可用、凭证读写失败分别展示原因；同一窗口中相同代码和环境的转人工结果不随每次点击重复请求模型，授权菜单可显式重新审核。

转人工时提供「授权此版本并运行 / 仅运行一次 / 取消」，展示完整定义、全部脚本与依赖、当前冻结输入和离线执行边界。版本授权使用宿主专用硬确认命令，不注册到模型工具面或 DSL；与单次运行命令分别冻结和挂起，用户只批准所选命令，未选命令撤销。版本命令核对安装、定义、环境与授权记录修订后先保存凭证，再执行同一份冻结输入；保存失败不运行。「仅运行一次」仍只消费当前审批身份，不生成长期凭证。模型明确拒绝或环境身份不可验证时不提供人工版本授权。

模型通过或用户明确授权后，宿主用当前空间 Keychain 中的随机密钥生成 HMAC-SHA256 凭证，原子保存到应用私有的 `script-review.json`。签名覆盖审核策略版本、空间、应用根路径、应用 ID、安装身份、完整定义原始字节 SHA-256、Python 环境身份，以及凭证格式版本、独立授权 ID、来源与时间。旧版仅签署身份的模型凭证兼容读取；旧的单次人工批准不升级为版本授权。每次准备、执行前及结果发布前重查身份与完整签名凭证，普通输入、记录、附件与表格数据变化复用授权；代码、动作、依赖声明、环境或凭证变化要求重新授权。普通运行错误、停止不会抹除有效代码授权。

窗口授权菜单展示「代码待授权 / 模型审核通过 / 用户已授权 / 状态不可用 / 审核拒绝」、授权时间与范围，并支持重新自动审核和经独立确认撤销。撤销在同一凭证文件保存带签名的撤销记录，重开窗口不会自动重新批准；执行前与发布前核对完整凭证，重新授权产生新 ID 与签名，不能复活旧命令。保存时在同一个存储 actor 操作中比较授权记录修订，防止迟到的审核或旧授权命令覆盖撤销或新授权。

更新、版本恢复和卸载清理旧凭证，完整备份不携带审核授权，数据恢复产生新安装身份。更新后旧窗口需关闭并重新打开。生成会话的批准不授予独立应用窗口执行权限。网络、子进程、数据库访问、业务写入与宿主能力的权限规则不由代码授权放宽；模型判断不替代执行器隔离。窗口支持停止，关闭及空间切换撤销待批准命令并取消任务，迟到结果不能回填。

复用本空间 Python venv 和独立签名的离线执行器，禁止网络与子进程，失败不回退宿主执行。依赖遵守技能系统的受限声明语法，获准执行后检查；缺失或检查不可用时不执行函数，用户通过 Python 设置或既有包管理工具安装。执行器容器按空间隔离，同一空间的多个应用共用该执行器身份，不能宣称每个应用都有独立的系统沙箱。函数不获得聊天工作区、Keychain、其他应用数据或任意宿主 API 的授权。

脚本上限：每定义 16 个、单段源码 64 KiB、各 32 项输入/输出、超时 1–120 秒；单次最多 8 份记录查询（每份最多 1,000 条，合计记录 JSON 4 MiB）及 8 个附件（合计 32 MiB）；结果 JSON 128 KiB，单字符串继续受状态字符串上限约束；产物最多 16 个、单文件 16 MiB、合计 32 MiB。源码仍计入整体定义大小限制。运行目录位于本空间 `app-runs/<应用及安装身份>/<运行UUID>`，正常完成或确定失败后清理输入与临时材料；进程状态不确定时保留现场，不自动重试。

## 空间与执行边界

- 定义、保存状态、查询服务、窗口身份和待安装草稿均归属固定空间。DSL 不接受空间参数，也不能读取 Keychain 或 Provider 凭据。
- 资源读接口使用固定空间知识连接或固定安装身份的应用数据库，返回类型化 DTO；列表不从工具的自然语言结果中解析数据。应用文件夹和连接均不由 DSL 选择。
- 知识和私有记录列表在数据库侧筛选与分页，仅取标题和短摘要；选中后单独读取正文。搜索有防抖、取消与请求身份校验，迟到结果不能覆盖新的搜索或选择。
- `saveKnowledge` 总是新建条目，不按同名标题覆盖。每次点击创建新的运行和调用身份，经 `DispatcherEngine.executeCommand` 进入与聊天工具相同的工具批处理、权限判定、参数摘要核对和执行路径。
- 普通命令无需 Provider 或额外推理。写操作先挂起：记录展示捕获的内容、文件导入展示文件名和大小，动作始终绑定固定空间及应用。人工批准只消费这一个审批身份；拒绝、关闭或过期身份不执行，重复提交不能重放。文件管理器由窗口运行实例持有，空间切换时同步作废其中的待审批命令。
- 首期不提供跨轮授权或自动审核选项给小应用写命令。窗口中的确认不扩大长期权限；运行有截止时间和防重入，结果不明确时要求用户先到知识库核实。
- 小应用动作没有自动续跑或 Daemon 移交。运行轨迹保存在窗口运行实例内；首期不提供跨重启的动作恢复或持久执行历史，重开窗口不会重试之前的写入。

## 窗口与生命周期

主窗口使用单一 SwiftUI `Window` Scene 和明确身份；关闭后通过 `openWindow` 重建。菜单、状态项、全局快捷键及 Dock 重开只查主窗口身份，不再回退到任意非 Panel 窗口。

小应用沿用邮件编辑器的 AppKit 窗口协调方式：`NativeAppWindowCoordinator` 按 `(space, appID)` 去重，每个窗口持有自己的 `NativeAppRuntime` 和打开时的定义快照。重复点击激活同一窗口；更新或恢复后，已开窗口继续使用原定义，关闭并重新打开才加载新版本。

切换空间时，旧空间窗口立即遮蔽内容、隐藏窗口、作废查询和审批身份，并取消任务；收尾只使用原空间依赖。切回后由用户重新打开，隐藏窗口不会自行恢复查询。关闭窗口先保存必要状态，保存失败允许取消关闭或明确放弃；应用退出也先保存草稿，失败不会无声丢弃。

首期不自动恢复上次打开的窗口位置或未完成动作；重新打开时恢复兼容的小型持久状态。

## 存储与限制

```text
<appSupport>/AgRoom/<space>/apps/<app-id>/
├── app.zhiapp.json
├── previous.zhiapp.json
├── workspace.json          # 安装身份与宿主数据格式
├── state.json              # 小型状态 + 编辑记录身份/修订号；兼容旧的平面 JSON
├── appearance.json         # 可选的小应用图标配色，缺省跟随空间
├── data.sqlite             # 按需创建，私有业务记录与文件元数据
├── files/                  # UUID 文件名，不用显示名称拼接路径
└── cache/                  # 可再生内容，按需创建，不进入备份
```

存储由不缓存空间数据的串行磁盘 actor 执行，I/O 不占主 actor、不进入共享状态锁。根目录与普通文件逐级使用目录描述符和 `openat` / `O_NOFOLLOW`，拒绝路径穿越、用户目录链接、硬链接与非普通文件；只展开 macOS 固定的 `/var`、`/tmp` 系统路径别名。SQLite 使用已校验目录句柄的内核路径，打开前后核对目录身份，并检查数据库及侧车文件；连接按操作现建，不缓存在 Hub。JSON 与文件采用同目录临时文件、同步和原子重命名。导入、扫描、窗口加载均重新校验产物。

更新前保留当前可用定义；既有持久字段键和类型必须保留，可新增带初值的持久字段。保存的选择值须符合新选项。应用版本与数据格式分别管理；宿主通过独立命名迁移初始化记录和文件表，当前不执行模型生成的迁移或 SQL。定义回退须保持持久结构、选择值及数据格式兼容，否则拒绝。升级不清空记录和文件。

工作区身份固定于一次安装，卸载或完整恢复会使旧身份失效，迟到的保存不能写入重装后的数据。状态读取失败保留原文件并提示修复，不静默重置草稿。编辑记录的 ID、集合与修订号随草稿原子保存，重开后继续修改同一记录；过期修订拒绝覆盖。

当前上限：应用定义 512 KiB，持久状态 64 KiB，单个状态字符串 32 KiB；每空间最多 64 个应用，单应用最多 128 个节点、12 层布局、32 个状态字段、8 个数据源、32 个动作；每种语言最多 256 个文案键。知识每页最多 50 条、单数据源窗口内最多累积 500 条；正文超过 32,768 字符时明确显示截断提示。保存知识的标题限 512 字节、正文限 32 KiB。

业务记录限制为每应用最多 10,000 条、单条标题 512 字节、正文 32 KiB、附加基础类型字段最多 32 项；SQLite 按实际页大小限制为 64 MiB。文件最多 256 个，单文件 16 MiB，合计 128 MiB。文件元数据仅保存生成 ID、相对路径、显示名称、大小、摘要和可选记录 ID。

文件字节先原子发布、再由数据库事务登记；事务失败或崩溃留下的无引用 UUID 文件和临时文件在下次文件对账时清理。删除先提交元数据变更，再清理无引用字节。读取和备份核对字节数与 SHA-256，缺失或损坏不会伪装成空文件。

## 应用数据备份与恢复

定义导出仍只包含可分享的应用设计。应用右键菜单的「备份应用及数据」导出 `.zhiapp.backup.json`：包括所属空间、定义、上一版本、已保存草稿、私有记录、文件元数据和文件字节；不收集 Keychain、Provider 配置、共享知识正文、派生缓存或待审批命令。空间备份也通过此逻辑接口包含应用定义、私有数据、配色和待安装草稿；应用右键导出仍可用于单个应用的独立保护。

备份通过单一读事务及串行磁盘 actor 获取一致的逻辑快照，不复制运行中的 SQLite 主文件。便携格式限制为 512 MiB，SHA-256 用于发现损坏，不构成来源认证。导入先校验格式、空间、定义、状态、记录/文件 ID 唯一性、引用、限额与文件摘要；独立应用恢复不跨空间。设置页的空间备份恢复可在用户明确确认来源与目标后导入另一空间，普通应用 API 的空间检查不变。

恢复预览展示输入与现有记录、文件数量，确认时重新核对现有工作区完整摘要，拒绝覆盖预览后的编辑。先在同目录暂存完整工作区，再原子交换目录；旧窗口关闭，新窗口取得新的安装身份。恢复前保留一个完整逻辑恢复副本及原始目录；当前数据损坏或文件缺失时，预检改为核对原始文件摘要，恢复后保留原始材料供排查。正常副本可从右键菜单恢复，无法解析的原始材料则由该入口在 Finder 打开。失败不自动重试业务写入。

## 可试跑的任务模板

应用库模板菜单另提供报价试算和工时合计。两者均有可填入的样例、期望结果、可修改的算式和明确的业务假设核对说明；预览中即可调用既有本机小数计算动作试跑，不安装、不读取业务空间、不执行 Python。修改输入后需要重新计算，显示的是上次结果；样例分别得到 396 和 13.5，用户资料仍需独立核对。正式安装沿用原有定义预览与安装流程，不增加能力或授权。

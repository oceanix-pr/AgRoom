# 编程能力与 Token 效率优化

## 目标与边界

在任务验收质量不下降的前提下，减少完成同一编程任务所需的请求、重复输入与失败重试。以真实 Provider 用量和独立验收结果判断效果；本地字符估算只用于预算和归因，不能充当计费数据或宣称节省比例。

所有功能沿用当前空间、工作区、权限、确认和日志边界。工具发现不授予工具执行权；压缩摘要、仓库内容与模型生成的计划不成为授权来源。签名思考和不透明续传内容必须原样保留。

## 实施清单

以下状态按代码与验证更新，未完成项保持开放。

- [x] 请求成本：每次请求关联根 run / run / parent run / purpose，持久化不含内容的上下文分类估算；保留真实输入、输出、缓存和推理用量的未知状态。
- [x] 用量正确性：统一成功回复的计数入口，覆盖步数耗尽、失败熔断、截断续写和恢复，避免漏计与重复计数。
- [x] 预算：团队账本从父账本派生，模型与工具预留同时受父子上限约束，继承更早截止时间，验证者与失败调用也计入总任务。
- [x] 评测：固定配置、任务版本和预算；增加现实编程场景、独立验收、失败成本及首轮/重复轮回执，复用生产工具工厂并显式限制评测能力面。
- [x] 工具：编程核心工具常驻，低频定义按需发现；稳定排序，保留已有执行检查与签名续传所绑定的工具面。
- [x] 路由容错：网页操作补选实际浏览器入口，相对日期补入时间能力；保留简短能力目录，能力缺失声明最多触发一次只读元数据发现，拒绝和结果不明的副作用不重放，快照保留纠错次数。
- [x] 提示与缓存：分离稳定规则和动态任务证据，按 Provider 能力启用缓存策略；记忆与技能按相关性和预算披露。
- [x] 仓库证据：路径、摘要、行区间与符号组成工作集，合并重叠读取，编辑后失效；检索支持批量、路径和仅计数/路径输出。
- [x] 符号导航：SourceKit-LSP 定义/引用/符号读取，明确索引状态、宿主确认与文本回退。
- [x] 上下文：约束、事实证据、变更、检查、失败尝试和下一步的结构化检查点；阶段边界主动压缩和失效后的重新读取。
- [x] 原生续传：受支持的 OpenAI Responses 使用不透明压缩项及完整规范输出回放，不把摘要当作验证结果；Anthropic 签名续传继续原样保留。
- [x] 委派：普通子代理获得同工作区只读仓库能力，沿用现有智体模型选择；轻任务可配置低成本智体，不自动降级用户选择的模型。
- [x] 诊断：按根因和新增失败聚合构建诊断，用实际进展决定修复循环，保留真实检查版本与结果。

隔离构建执行器、独立工作树和通用语言工具链适配属于后续架构扩展；应先补威胁模型、取消/恢复与产物回收设计，再接入既有审批入口。

## 效果判断

优化目标是完成同一任务的总成本。少读一页源码但多失败一轮可能更贵；缓存命中降低费用也不减少上下文占用。因此分别观察独立验收通过率、错误完成、总耗时、所有 HTTP 尝试的实际用量及缓存读写，失败与审核/验证费用不能排除。成功任务平均 Token 的分子包含失败运行，缺失用量时保留未知，不用本地字符估算补成真实节省。

按需发现有额外往返成本，短任务未必受益；符号查询的已有索引可能不完整；原生压缩支持按端点/模型门控，不能保证所有网关或服务商都接受。真实任务模型质量、缓存命中和节省比例需通过固定模型/预算的实际对照确认。当前已提供入口与报告汇总脚本，普通验证不自动读取用户凭据或调用付费模型。操作方式与具体支持边界见 [编程工作流](../15-编程工作流.md) 和 [Provider 协议](../04-LLM提供商与消息协议.md)。

## 验证策略

协议夹具验证实际发出的请求、工具和续传结构；并发测试验证父子预算、取消与截止时间；数据库测试覆盖升级、重开、导入导出及空间隔离。离线回放只验证运行机制，真实质量和节省比例需要显式启用的 Provider 评测，不在默认测试中访问 Keychain 或调用付费模型。

路由回归覆盖错误领域下的中文 OA 预订、实际能力交集、相对日期、宿主发现回执的来源与完整性、原表单确认、拒绝与未知副作用、签名消息和跨快照的一次性纠错。可选本地分类回放使用合成网站地址和实际浏览器工具定义；真实网站业务完成率与远程模型总成本仍需独立对照，不能由定义缩减比例或协议桩通过推断。

完整 Swift 回归和本地 ad hoc 签名的 App Debug 构建已验证通过；另显式启用了无清单合成文件的真实 SourceKit-LSP 符号读取。真实模型评测开关保持关闭，尚无付费模型对照结果。独立验收器已验证原始缺陷被拒绝、已知修复通过；汇总脚本核对了失败成本、未知用量与零成功分母的处理。UI 重发测试使用独立临时后台交接存储，避免读取真实应用运行状态。

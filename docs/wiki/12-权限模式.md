# 权限模式

权限模式是会话级的能力上限，和工具确认策略是两层：

- **模式**决定“这类操作能不能发生”；
- **确认策略**决定“允许发生的操作要不要先问用户”。

模式拒绝优先于硬确认、持久规则、本轮授权和自动审核；任何授权都不能把模式拒绝翻成放行。模式允许也不会自动绕过统一审批：工作区内低风险文件操作是否免确认，由本轮任务授权、目录身份和工具实际读写目标决定。

文件夹引用是独立于模式的边界：三档模式均只挂载当前工作区的主目录和显式引用文件夹，其他登记目录不会自动开放。引用通过工作区菜单的系统选择器添加；同工作区有运行或挂起任务时禁止修改，变更从下一轮生效。用户明确附加的文件由宿主复制到当前工作区供本轮读取，不开放整个附件归档目录。

## 权限预设

用户通过一个预设同时选择能力范围与审批行为。结构参考 [DeepSeek Harness 权限预设](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/interaction/permission-presets) 及其 [客户端选择器](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/client/ui-permission-presets)：菜单目录、当前有效组合、会话默认值分开管理，界面共用一个切换入口。

| 预设 | 能力模式 | 自动审核 | 可设为新会话默认值 |
|---|---|---|---|
| 仅可查看 | `read-only` | 关闭 | 是 |
| 工作区内修改 | `workspace-write` | 关闭 | 是 |
| 扩展访问 | `danger-full-access` | 关闭 | 是 |
| 自动审核（实验性） | `workspace-write` | 开启 | 否，仅当前会话 |

阿吉屋保留工作区围栏、空间隔离和逐次硬确认，因此没有照搬 Harness 的全盘访问与 `never` 审批策略。自动审核也不扩大到宿主执行。预设只组合既有执行与审批机制，不能改变工具资格。

`PermissionConfiguration` 保存实际的模式与审核开关，`PermissionPreset` 统一提供目录与组合映射。历史组合不匹配任何预设时显示「自定义」，保留原值；自定义仅供显示，不能作为切换目标；完整管理页列出它实际保留的范围与审批方式。切换时只在同一事务中更新这两列，不用摘要会话覆盖消息。保存成功后才发布新状态；失败保留原组合并提示重试。保存期间禁止重复选择、发送与重试，其他会话不受影响。

## 写范围是四层交集

文件写入不再由“技能工作区替换会话工作区”。有效写范围是：

```text
当前空间允许范围
∩ 会话允许范围
∩ 当前技能范围（如有）
∩ 当前子任务范围（如有）
```

- 每一层都必须包含目标；技能与子任务只能收窄，不能把目标换成更宽或另一个目录。
- 当前空间禁止写入另一空间的默认工作区/专属目录；这是独立硬约束，即使某层范围被误配得更宽也会拒绝。
- 技能 `workspace-folder` 无法解析、越界、或与会话范围没有交集时，加载结果明确报错并禁止该技能期间的所有写；不回退默认工作区。
- 写工具通过 `writeTargets(argumentsJSON:)` 声明实际写入路径；引擎不再把按工具名维护的参数白名单当作授权依据。`team_write` 同样先过统一范围检查，工具内部还会再做一次路径与符号链接校验。
- `fully access` 允许提出受确认约束的宿主构建等操作；不扩大当前工作区引用的文件夹集合，空间隔离和子任务/技能收窄仍然生效。

## 三档语义

| 模式 | 能力上限 | 仍需确认 |
|---|---|---|
| 仅可查看（`read-only`） | 读取、检索、网页与浏览器读取、只读 Shell 命令 | 无写/代码执行/外部副作用可确认；这些调用直接拒绝 |
| 工作区内修改（`workspace-write`） | 会话范围内的受管文件操作、离线单条 Shell、离线 Python 和技能脚本。拒绝宿主代码执行 | 需要目录写权限的 Shell 与外部副作用按工具策略确认。越界文件写入直接拒绝 |
| 扩展访问（高级，底层值 `danger-full-access`） | 文件工具继续受工作区约束，普通脚本离线。会话开启宿主执行申请后，可以提出宿主构建请求 | 宿主代码逐次硬确认，其他副作用继续适用对应工具的确认策略 |

`工作区内修改` 的自动免确认覆盖 `files_write`、`file_write`、`files_mkdir`，以及具备任务恢复点的 `files_edit` 和 `files_apply_changes`。批量编辑须逐文件提供当前 SHA-256，所有目标均位于有效任务写范围；执行时仍校验唯一匹配、路径和写入字节，恢复点保存失败时停止写入。同一授权也覆盖改名、复制、移动和移入系统废纸篓。复制校验来源读范围，移动校验源和目的写范围。主目录和显式引用文件夹均可使用，不依赖模型自动审核开关。

在正常装配的会话中，已核验的只读能力本身免确认，无需开启自动审核。Shell 仅逐项识别静态只读命令，不对未知 Shell 使用模型审核兜底；自动审核与扩展访问均不能把未知命令变为只读。常见读取和检索优先走普通聊天也提供的工作区只读工具。

## 会话数据流与宿主执行

权限面板单独保存会话的数据流范围和「允许请求宿主执行」开关。新会话默认使用已配置服务，关闭宿主执行申请。迁移前已有会话保留原有宿主申请资格，原权限模式与逐次确认继续生效。

| 数据流范围 | 可用能力 |
|---|---|
| 允许已配置的服务 | 模型与工具可使用已配置服务，仍逐项应用空间、模式和确认策略。 |
| 仅允许已配置的模型 | 只向当前模型端点发送本轮推理所需的数据。会话只挂载经核对的本地工具，禁用 MCP、邮件、远端网页、包下载和宿主代码执行。远程图片预览也关闭。 |
| 仅本机处理 | 接受受支持的本机回环模型地址，拒绝远端模型和跨来源重定向。保留同一组本地工具，关闭远程预览和自动记忆提取。运行在回环地址的模型服务自身仍需独立管理。 |

明确的用户任务约束可以进一步收窄数据流。子任务与移交继续取父任务约束的交集。已有消息的会话放宽数据访问范围时，须确认历史内容的使用范围。运行中及等待处理的副作用期间锁定权限控件。邮件、浏览器、MCP 或包下载遭拒后，模型无法通过要求宿主构建获得同一能力。

## 边界与红线

- **Shell 默认离线沙箱**：`execution_mode` 缺省为 `sandbox`，只接受单个程序与字面量参数，直接 exec，不解释管道、重定向、展开、后台或其他复合语法。静态只读命令只获输入读取；命令如获得整个工作目录的写权限，必须逐次硬确认。只读命令的显式输出只向获准文件发布，直接授予的目录写权限，仍受空间、会话、技能和子任务交集约束。联网和派生子进程被禁止，执行器自身隔离容器仍属于系统基线权限。
- **结构化参数与文件流**：优先传 `program` + `arguments`，兼容的 `script` 不可同时提供。`stdin_file` 冻结工作目录内的常规输入文件，`stdout_file` / `stderr_file` 保存完整二进制流；控制请求不会进入数据 stdin。输出文件必须位于工作目录及有效写范围内。静态只读程序重定向只声明这些文件为写目标，其他程序仍声明工作目录。默认 `create` 原子拒绝已有目标，显式 `overwrite` / `append` 逐次硬确认；带 I/O 文件的调用均不能复用任何授权或自动审核。每份输入、暂存输出和最终输出限 64 MiB。输出成功后逐文件发布，失败/取消不主动发布暂存内容，程序其他已授权写不回滚；不保证多文件事务，部分成功必须报告。
- **宿主执行**。工作区对话禁用任意宿主 Shell。显式宿主构建和宿主代码索引需满足扩展访问、会话宿主开关与数据流范围，并逐次硬确认。确认卡区分起始目录、宿主可读写范围及网络和子进程权限。
- **诊断与开发工具**：`sandbox_diagnose` 是固定只读探针，不给会话扩权；最小检查不带工作区，工作区检查仅使用当前绑定目录。`files_read` 分页不依赖脚本；`repo_changes` 在仓库元数据被工作区围住时以固定参数读取 Git 状态/差异，并由只读沙箱执行。`files_edit` 与 `files_apply_changes` 声明文件写目标，在有效任务写范围内可由确定性规则批准，同时保存任务恢复点并校验预期摘要。`project_build` 仍是宿主代码执行，只在扩展访问（高级）下逐次硬确认；固定动作和目录校验不能保证项目构建脚本被系统隔离，不是沙箱失败的自动回退。
- **Python 与技能脚本**。工作区模式可申请离线执行。按本次调用的 `input_paths` 挂载只读项目输入，运行产物放在空间专属目录。确认绑定输入对象、执行器与环境；技能代码另有冻结副本与完整包摘要。缺少依赖时停在执行前。
- **原生小应用代码审核**：只覆盖已安装应用的离线 Python 函数。完整定义统一审核通过或用户明确选择「授权此版本并运行」后，保存空间 Keychain 密钥签署的版本凭证，每次运行重查定义与完整凭证；代码、依赖声明、安装、环境或策略变化重新审核。普通输入变化不触发重复人工确认。审核不确定或不可用时提供独立版本授权硬确认与仅运行一次选项；仅运行一次不生成长期凭证，审核拒绝不执行；不授予联网、子进程或宿主能力，不改变业务写入确认。
- **运行时目录保留给执行器**。基础解释器、空间 venv、包下载与私有运行目录不可登记为项目输入或工作区。已保存的工作区使用前也要复核。
- **文件工具仍受工作区引用约束**：扩展访问（高级）也只能访问本工作区主目录和引用文件夹，不能因同空间已有登记而访问其他目录；不能写 `/`、主目录本身、`~/Library`、`/System`、`/Library`，也不能写另一个空间的默认工作区。
- **`file_write` 兼容别名仍按会话工作区**：它保留“只写本会话工作区”的旧语义；扩展访问（高级）下需要更宽写范围时使用 `files_write`。两者都受受管根与空间隔离约束。
- **外部副作用**。邮件、提醒、通知、浏览器提交、空间数据库写入各按工具类别处理。发信确认绑定实际发件账号、收件人和正文。同一封信的发送状态保存在空间草稿中。MCP 提交结果不明时保留空间回执；用户核对后在设置中解除阻止，再次申请才会发送。
- **内部记账不算用户可见写**：`mail_read` 缓存正文、`web_fetch` 临时结果、技能用量日志、会话标题生成不触发模式拒绝；自动记忆是用户可见写，只读模式下不应继续生成。
- **守护进程不自动扩权**：后台继续沿用会话模式；主动移交的任务范围通过身份、有效期和当前策略核验后，工作区内低风险文件操作可继续自动批准。旧记录没有任务范围时不获得文件写确定性自动批准。后台静态只读 Shell 可按规则执行，写命令和宿主执行仍人工；模式拒绝在后台同样生效。
- **团队写不绕过模式**：`team_write` 属于 `workspaceMutation`，只在 `workspace-write` 及以上可用；模式拒绝优先于任务板审批。开启团队写后每次写入仍需任务板逐次批准，批准不等于放宽模式。

## 判定顺序

```text
无副作用的参数校验 → 无效调用写失败 toolResult
模式/空间/任务范围校验 → 拒绝直接写 toolResult
否则 hard confirmation → 确认卡
否则模式策略下已核验的只读能力 → 直接执行
否则确定性低风险规则 → 直接执行并审计
否则持久规则 / 本轮精确授权 → 直接执行并审计
否则具备模型审核资格 → 审核模型判断
否则模式 requireApproval 或工具自身要求确认 → 普通确认
否则执行
执行前再次校验参数，并核验调用、任务范围、目录身份和授权世代
```

模式判定与 `FileAreaPolicy`、执行使用同一份解析后的参数（`file_write` 的相对路径先按会话工作区解析），避免“确认时看的是 A、执行时写的是 B”。

## 会话、默认值与恢复

- 模式按会话持久化到 `chat_sessions.permissionMode`；旧库迁移默认 `danger-full-access`，保持升级前行为；新会话由设置页的默认值决定，默认 `workspace-write`。
- 设置页只改“之后创建的会话”；已有会话不会被设置变化改写。
- 运行、挂起、等待确认或守护进程后台执行期间禁止切换模式，保证同一轮前后使用同一能力上限。
- 模式随 `DaemonRunSettings` 和 `EngineRunSnapshot` 移交；子代理继承父会话策略，只能收窄，不能放大。
- 预设在空闲时切换；范围与审核开关一起原子落库，成功后更新界面。保存失败保留原组合。
- 自动审核仅由当前会话显式启用，不因查看或切换历史会话而成为下一会话的默认值；无会话时的预选只由下一条新会话消费。

## 工具分类

`DispatcherTool.permissionClass` 默认从副作用分类推导：`readOnly` → `.readOnly`，其余 → `.externalEffect`。工具可覆盖静态分类，也可按参数动态分类：

- 文件工具：`.workspaceMutation`
- `files_edit`：`.workspaceMutation`；工作区模式下可由确定性规则批准，必须先保存任务恢复点，写入前再次校验摘要和旧字节
- `sandbox_diagnose`：`.readOnly`；`project_build`：`.codeExecution`，逐次宿主硬确认
- `shell_run`：无输出重定向的沙箱静态只读单命令 → `.readOnly`；静态只读程序的输出重定向 → `.workspaceMutation` 并声明输出文件；其他沙箱写命令 → `.workspaceMutation` 并声明工作目录及输出文件；宿主或不支持的语法 → `.codeExecution`
- `python_execute`、`skill_run_script`：`.confinedCodeExecution`；只读模式拒绝，工作区模式可进入模型审核，缺少执行器证据或范围失效时转人工
- `sql_query`：只读语句 → `.readOnly`，写语句 → `.externalEffect`
- 浏览器读取/截图/滚动：`.readOnly`；点击/填表/执行脚本：`.externalEffect`
- `browser_open` 普通导航为 `.readOnly`，已识别副作用的 URL 为 `.externalEffect` 并逐次硬确认；校验与执行共用规范化 URL，不能用前后空白或改走打开入口降低确认等级。
- 浏览器任务授权不改变能力分类：普通原生链接、结构化菜单/页签和同源 GET 搜索表单分别使用导航、控件和表单范围的任务授权。结构候选不等于证明事件处理器只读，可进入模型审核；证据不全或不确定转人工。提交、危险目标、未知点击及任意脚本逐次硬确认。填表对完整顺序计划一次人工确认，包括已声明的联动和延后出现字段，不提供重放授权。只读模式仍拒绝这些交互。具体边界见 [工具系统](03-工具系统.md)。
- 邮件、提醒、通知、空间数据、备份、导入导出、包管理：`.externalEffect`
- 外部 MCP：保留 `.externalEffect` 与非幂等分类。宿主筛选出的查询候选可由会话自动审核模型核对任务意图后批准；服务器只读/幂等声明不直接授予权限。写入、删除、发送、凭据、本地路径、动态执行和未知操作继续逐次硬确认；审核不可用或不确定转人工。不能获得工作区文件权限、本轮授权或持久免确认资格；只读模式仍直接拒绝
- 删除类、恢复覆盖类：`.externalEffect` 或 `.destructive`（硬确认仍由工具自身声明）

新增工具必须显式选择分类；默认最保守，只读模式会拒绝未声明的写类工具。

## UI

- Composer 按钮只显示当前预设名称与下拉箭头，自动审核在途或保存时显示进度。菜单展示仅可查看、工作区内修改、扩展访问与自动审核，当前项勾选，自动审核带实验性标记；旧组合显示只读的自定义状态。
- 运行、挂起、等待确认、后台执行或保存期间锁定整个预设选择器，不能只改其中一个维度。菜单不展开脚本边界与审批策略说明，完整资料保留在「脚本与权限」。
- 自动审核与扩展访问每次切入都使用共用确认页，需勾选理解说明后才能启用；取消、默认回车或切换会话不授予权限。设置页与完整管理页使用同一选择器和确认流程。
- 默认值目录不包含自动审核；默认值只影响之后创建的会话。
- 「脚本与权限」页面固定绑定当前空间，包含会话权限、执行确认、授权规则与审批记录；从 Composer 打开时携带当前会话上下文，从设置页打开时只展示默认值与本空间管理项。
- 所有预设、确认、加载与失败文案走三语本地化；面向模型的权限说明不本地化。

## 确认卡与授权有效期

已接入可信执行摘要的脚本调用使用专用确认卡：先展示执行档、实际读写/产物/执行器容器范围、联网与子进程能力、原因与限制来源，再展示互斥的授权有效期。

- 「仅这一次」：所有可批准调用；执行一次、取消、计划变化或身份失效后作废。
- 「本轮相同执行」：仅当 `roundKey` 存在；本轮结束、停止、重启或内容/参数/目录/环境变化后失效。
- 「记住这条精确命令」：仅当存在精确规则候选；保存前展示完整匹配条件与到期时间，保存失败不得显示「已记住」。
- 硬确认只提供「拒绝 / 允许一次」；宿主执行使用独立风险样式，不提供本轮或持久选项。
- 旧快照缺少摘要时回退原确认卡；摘要缺失或未知字段不得生成额外授权选项。

## Shell 持久授权的结构化边界

- 旧规则保留展示，但标记为“需要重新授权”，不参与自动匹配，也不会自动转换。
- 新规则绑定：空间、工作区、解析符号链接后的可复用白名单程序身份、完整 argv、实际工作目录、固定 PATH 与策略版本/有效期。只接受不含展开的单条命令；复合脚本不能建立持久规则。
- `source`、`env`、`command`、`nohup`、`cd`、环境赋值、命令替换、反引号、转义、未闭合引号或解析失败都不会生成/匹配持久规则；这类脚本只能逐次确认。
- Shell 解释器调用、任意非白名单程序与加载项目脚本的命令不生成本轮或持久授权；入口摘要不能代表完整可变依赖。需要复用的技能执行使用完整包快照。一次性脚本批准仍校验入口身份；固定系统工具的规则命中后直接使用绝对路径与 argv，并使用固定 PATH。
- 规则文件读写移到独立 I/O 队列，并在独立 `.lock` 文件上用 `flock` 串行跨实例读-改-写，避免多个实例互相覆盖。
- 高风险硬确认仍然先于任何规则匹配。
- 持久规则只适用于没有 I/O 文件的沙箱单命令，结构化 argv 按参数边界逐项绑定；授权语义迁移后旧规则需要重新授权。显式宿主执行、文件输入输出均不命中规则，也不生成规则候选。
- 规则读取接口区分「没有规则」「解码失败」「I/O/加锁失败」；管理页不把损坏展示成空列表。新增、撤销或清空遇到损坏/不可用文件时停止写入并保留原文件，不能静默覆盖成空规则库。
- 管理页不展示规则库和恢复服务的底层错误原文；损坏、不可用、写入失败与文件恢复拒绝分别给出本地化处理建议和重试入口，日志仅保留稳定失败类别或脱敏的错误类型/码。撤销与清空保留原有确认；文件恢复继续核对空间、路径和写入后摘要。
- 自动审核记录覆盖模式拒绝（`mode_denied`）、规则命中、人工批准/拒绝、撤销和过期；模式拒绝写入审计但不改变拒绝结果。
- 审批审计同样使用跨进程稳定锁保护读-改-写；损坏、不可读或锁不安全时停止追加并保留原文件，管理页显示不可用，不能把损坏解释为空历史。

## 任务执行范围（第一阶段）

宿主在任务开始时构造 `TaskExecutionScope`：空间、会话、run、任务身份、工作区规范路径与目录 inode、权限模式、审批策略版本、读写/产物范围、能力集合、用户原始请求、明确的“只分析/不要修改”等禁止项，以及授权世代。它挂在 `ExecutionContext` 上，子代理取父范围交集；普通源码编辑不会使范围失效。

- 停止、换工作区或任务结束会撤销授权世代；关闭模型审核使在途模型结论失效，已授予的受管文件权限继续生效，正在执行的命令由停止按钮终止。
- 普通重启不恢复 `preApprovedTools`；快照只保留会话、轨迹和稳定调用身份。主动移交后台保存原任务范围与预算检查点：保留任务身份、用户禁止项和剩余有效期（最长一天）；恢复须核对空间、会话、工作区目录身份、权限模式和策略版本，并与当前范围取交集。Token 消耗包含尚未结算的预留，移交不能重置总预算；旧记录无范围时不获得文件写确定性自动批准。
- 审核模型只返回批准/转人工/拒绝、原因码、用户指令引用和调用摘要；引用或摘要不匹配即转人工。它不挂工具，不能执行、修改或扩大权限。

## 后续

Shell 单命令、Python/技能及固定包解析使用本空间统一签名的离线 App Sandbox 执行器。生活与工作各有独立身份和容器，跨进程目录授权仅属于本次进程；主 App、Daemon 只信任 App 内同团队签名的执行器，缺失或验证失败均拒绝执行。包管理经原有确认后，由主程序仅传输经过地址、跳转与预算校验的公开 PyPI 响应，离线执行器核验哈希后安装。通讯使用一次性 stdin 文件描述符和本次空间内的受限下载交换目录，不提供常驻 XPC/Mach 服务，也不缓存执行授权。扩展访问（高级）不解除执行器的网络限制。

完整编码构建沙盒仍未交付。真实签名验证中，SwiftPM 的生成程序被 macOS quarantine 拒绝启动；未通过验证的构建入口、额外执行器和相关 Gatekeeper 排除实验已撤下。`project_build` 继续采用原有的显式宿主入口、完全权限与逐次硬确认，不开放自动审核，也不因沙盒失败自动回退。后续须验证新的隔离架构，不能通过关闭 Gatekeeper 或让用户反复手动放行生成程序来宣称完成。依赖安装继续沿用专用授权。

产品独立执行器不依赖 Seatbelt。普通书签先由可信准备进程转换为本执行器身份的只读书签，执行进程不接收输入的读写授权；禁止目录通过分解授权根剔除，不能先授予父目录再试图拒绝子路径。执行前把进程数软、硬限额降为零，并限制单文件大小、CPU 和文件描述符；宿主监控直接执行进程的驻留内存与本次临时/产物目录的总量和数量，超限停止且不发布暂存输出。监控是采样限制，不承诺工作区总磁盘配额或容器总量配额。App Sandbox 仍提供自身容器和系统基线权限，应准确展示这一边界。旧 Seatbelt 只保留在显式受控的兼容测试入口。普通脚本按次联网仍是后续工作，不能静默将执行器失败转换成宿主执行。

团队写已使用从工作区根逐级 `openat(O_NOFOLLOW)` + `renameat` 的目录句柄落盘；普通文件工具与跨进程审批持久化仍未完全共享这一实现，多文件审批事务也尚未跨进程恢复。

## 工作区长期访问

- 默认工作区由应用管理，无需逐次选择。添加已有目录时，UI 保留系统选择器返回的原始 URL，登记后按空间保存 security-scoped bookmark；重启后自动恢复，不要求每条脚本重新选择目录。
- 一个工作区可引用多个文件夹。每个引用有独立身份与书签，移除引用只撤销访问，不删除磁盘内容；同空间其他工作区不会因此继承引用。
- 令牌放在各空间的 `workspace-access.json`，不写入全局工作区元数据、提示词或日志。每次执行仍生成独立临时授权，不将长期令牌交给脚本。空间切换释放前一空间持有的访问。
- 恢复核对目录设备号与 inode，允许同一目录移动；同路径被新目录替换、书签损坏或不可读取时标记失效并停止该工作区的引擎装配，不静默切换项目或扩大目录。
- 工作区菜单提供「重新授权文件夹」，通过系统选择器恢复，并保留原工作区及会话身份。旧版本只有路径的登记继续沿用旧行为；可通过此入口补建长期书签。
- macOS 首次文件夹授权仍须由用户选择；应用不能替用户绕过 TCC。书签解决的是后续访问恢复，不能把权限模式、任务审批和系统授权合并成一次无限授权。

## 定时任务的无人值守档

定时任务没有审批人，不能复用会话的权限模式默认值。P0a 已使用独立的 `readOnly.v1` 能力档：`EngineAssembly.build(allowedToolNames:scheduledContext:)` 用代码内白名单显式装配工具面，同时设 `.readOnly`；任何需要确认或提问的调用失败关闭，不自动批准也不挂起等待。完整边界见 [14-定时任务设计](14-定时任务设计.md)。

定时对话入口 `schedule_draft` 是纯数据草拟，不保存、启用或执行，因此没有可绕过的审批效果；用户在原生预览中明确保存才创建定义。定时运行内部不注册该工具。结果生成报告只创建待发请求，后续文件操作仍受普通会话权限和确认约束；知识保存需显式预览提交，不能由无人值守运行写入。任务可下调预算，但不能提高只读档的步骤、输出或时间能力边界。

## 本次发现和处理

| 优先级 | 问题与可见后果 | 已执行的改进 | 验收重点 |
|---|---|---|---|
| P1 | 浏览器网页提取、技能重写/润色、图片 OCR 保存可能在切空间后写入错误空间 | 发起时固定空间、服务及相关对象身份；异步返回后和写前校验空间与取消；写入一旦开始只允许归原空间 | 双空间同时存在相似数据时，切换后无跨空间新增或覆盖；正常流程只写原空间 |
| P1 | HTML 邮件正文原先没有导航策略，外链或自动跳转可能让邮件 WebView 离开隔离文档 | 使用非持久化 WebView、禁自动开窗，只允许初始文档加载；主动 HTTP(S) 链接经系统外开，其余导航取消；补 CSP 边界 | 初始正文可见，meta refresh、子框架和危险协议无法导航，主动外链不在正文中打开 |
| P1 | 生产日志原先记录附件/备份路径、技能/通知/提醒标题、模型原文片段和原始错误说明 | 清除上述内容，错误日志改为稳定阶段与 `HubLogger.safeErrorSummary` 类型/码；全局热键失败统一使用 HubLogger | 注入私密文本和文件名后，公开日志与内存日志均不含原文；故障阶段仍可定位 |
| P2 | 设置、帮助、用量等无页内搜索的页面仍显示搜索框 | 只在具有列表搜索语义的页面挂载系统搜索控件；统一搜索入口继续常驻 | 页面切换后无无效搜索框、已输入筛选词不污染新页面 |
| P2 | macOS 默认侧栏按钮可让 split item 折叠，却未稳定回写 `columnVisibility`，夹具中出现完整侧栏与图标栏并排 | 移除默认按钮和菜单项，提供共用 `SidebarVisibilityAction.toggle` 的显式工具栏/菜单入口；定向状态测试已通过，真实 App 窗口视觉仍待验收 | 工具栏与菜单快捷键、窗口缩放和空间切换后，主侧栏与图标窄栏互补显示且选择一致 |
| P2 | 邮箱列表与详情中的固定小字号未随“较大界面文字”变化；HTML 图片提示不够准确 | 主要元信息改用共享字体角色，保留已读权重；三语徽标说明外部图片受阻与内嵌图片当前限制 | 默认/大字、窄窗、深浅色下文字和操作可读，提示不暗示未实现能力 |
| P2 | 技能润色运行中无法取消，覆盖前的快照失败可能继续写 | 运行中允许取消，取消/切空间不写；版本快照失败即停止覆盖 | 取消后原技能和历史版本不变；覆盖失败可恢复 |

### 目录请求与输入框动作发现（基础交互已落地）

输入框四项本地动作提示和目录请求卡的基础交互已实现。目录授权会改变下一轮文件范围，不能在当前运行中扩大已冻结的任务范围。`ToolSuspension` 仅保存进程内恢复闭包；旧版重启表单曾把作答变成新一轮输入，专项续审已改为只供核对的中断卡。`WorkspaceFoldersView` 在工作区有运行或挂起任务时禁用修改。因此采用**本轮只生成无副作用的请求回执，任务结束后由用户选择目录，下轮才生效**。若以后要求同轮继续读取新目录，须另行设计可持久化的类型化动作和新任务范围，不得把旧表单答案当授权。

| 切片 | 最小接线与所需三语文案 | 验收矩阵及不应误报的边界 |
|---|---|---|
| 对话请求引用目录（P1/P2，基础交互已实现） | 前台普通主对话注册精确命名的只读草拟工具，仅返回带版本、可信空间、工作区 ID 和非空会话 ID 的有界回执；模型只能提供短理由，额外路径或归属字段在执行时拒绝。`ChatView.messageAccessories` 只从原生回答当前版本的成功轨迹生成卡片，显示可信空间/工作区与固定三语范围说明，理由标为未核实。按钮启动单目录 `NSOpenPanel`；返回后二次核对会话世代、回答版本、运行/回执、工作区目录身份和无阻塞状态，再由 `WorkspaceRegistry.addReferencedFolders` 复用书签与安全根校验。 | Core 和原生卡片定向夹具覆盖前台/无头能力、伪造字段、复制回答、取消、单飞、切换后迟到回调、成功仅写所属工作区及同卡禁重复；三语暗色窄栏截图可读。引用仅在下一轮装配中生效。真实 App 的系统选择器、重启旧卡、TCC 与 VoiceOver 仍需现场验收；禁入目录沿用注册表既有回归。此项不表示备份跨区导入、同轮扩权或 Daemon 内部恢复已完成。 |

用户实窗验收发现：列表中已保存的模型正确，但再次打开编辑表单会变成预设默认模型。根因是 `onAppear` 恢复已保存字段后，程序化设置 `selectedPreset`，又触发 `onChange` 无条件重填默认模型；随后保存会将覆盖后的值写回。全局库迁移只新增别名与排序字段，没有改写模型 ID；配置层持久化回归无法覆盖这个界面事件问题。

表单现从传入配置初始化 State，取消出现时重载；快捷预设只通过用户操作的 Binding setter 填充。DeepSeek 新配置默认值更新为 `deepseek-flash`，已有模型不做静默转换。真实表单夹具在修复前复现打开、保存重开和再次保存的模型回退，修复后通过，并与配置迁移、别名和排序回归一同验证。重新生成工程后的 App 构建、深度签名和差异检查通过。原生 Picker 主动切换另一预设的点击路径尚未自动覆盖，setter 语义经独立 QC 复核。

同次对思考区与 Shell 使用的分析确认：思考区还会展示工具调用前的过程叙述，工具轨迹数量不能当作推理文本数量；别名不能代表实际请求模型。大型字符串目录超过受管文本上限时会使模型转用 Shell，带上下文的只读查询又可能落入人工确认；该能力缺口在下节交付中补齐。

## 大文本受管工具交付（2026-11-05）

补齐此前导致模型转用 Shell 的大文本能力：普通对话的搜索、按行读取和字符分页支持有界流式扫描，搜索可返回相邻上下文、完整原始摘要与命中附近的直达游标；超长行不再只返回与命中无关的开头片段。文件和目录枚举均固定描述符，返回前复核完整路径链；取消传递到后台工作，UTF-8、NUL、大小及输出预算失败时明确停止。相关上限和调用契约见 [编程工作流](../15-编程工作流.md)。

编辑、批量编辑、任务原始基线、审阅和恢复入口同步贯通大文件，仍核对唯一字节匹配、原始摘要、写入前旧内容及恢复点。大型文件的小范围变化生成局部差异，比较或明细因预算不可用时使用三语提示，不虚报全部行删除和新增。定时读取保留原有上限；Shell、宿主构建和代码执行的确认规则没有放宽。

合成大型字符串目录的定向回归验证了无 Shell 的受管搜索、读取、有效任务范围内编辑、任务审阅恢复和单文件恢复；另覆盖长行后段命中、中文/emoji/CRLF 分页、超限报告、损坏文本、取消、链接、跨空间拒绝、扫描中换文件及只替换子目录的空间换向。独立 QC 发现的路径式清单枚举和预览明细遗漏已修复并回归。真实 Provider 是否持续选择受管工具、代表任务的人工介入和用量对照仍须在实际编码验收中确认，不能由确定性工具回放代替。

最终完整 Swift 回归通过，依赖特定宿主或真实环境的用例按配置跳过；独立 QC 核对日志及安全边界后放行。新增源码和测试已纳入重新生成的 Xcode 工程，macOS App 构建及最终产物深度签名通过；三语资源格式、键集合和差异检查通过。真实 Provider、签名执行器的现场运行与长期性能仍沿用既有独立验收边界。

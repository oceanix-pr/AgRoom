# Markdown 渲染性能审查

检查共享 Markdown 门面、后台解析与数学保护、文档块缓存、TextKit 显示/测量、表格、图片及离线公式/图表调度。适用聊天、笔记、技能、Markdown 文件与知识预览等共用入口。改动保留当前工作区中既有的未提交修改。

## 问题与修复

| 路径 | 确认的问题 | 当前处理 |
| --- | --- | --- |
| 流式解析 | 每次累计快照更新均可启动完整解析 | 每文档 worker 的流式启动间隔至少 100ms；等待期间合并为最新请求，等待后检查取消，终态立即排队处理，保留标准解析器的整篇语义 |
| 普通文档 | 没有数学定界符也遍历排除树、复制数学保护字节并构造额外 SourceMap | 无 `$`、`\(`、`\[` 时直接适配初始解析树；数学哨兵按需选择，避免先创建全部候选标量 |
| 富文本缓存 | 块命中后仍重新合并全文，破坏稳定 attributed string 身份 | 全部命中直接返回原合并结果；连续正文按块输出身份缓存，代码或其他独立段变化不复制未变化正文 |
| 块资源依赖 | 未变化块仍遍历资源；每块扫描所有已加载资源 | 复用未变化块的依赖集合，按所需键直接查询资源 |
| TextKit | 每次更新对显示和独立测量栈都执行全文替换，失效全部段落排版 | 比较文本及属性公共前缀，在完整 Unicode 字素边界替换变化后缀；相同内容和属性不编辑存储，字号/附件/样式变化正常失效 |
| 流式视图身份 | 代码源码参与 `.id`，每次代码增长重建视图 | 代码段采用稳定类型身份，源码变化由原视图更新，复制状态按原逻辑重置 |
| 富资源调度 | 源码 `.task` 取消会连带取消图片/公式/图表，重复下载、初始化 WebKit | 解析与资源 `.task` 分离；资源计划、空间/路径上下文、外观及显式重试改变才变更资源世代；完成后对当前最新 blocks 渲染，旧世代结果不提交 |
| 表格失效 | 任意文档资源变化都触发表格重建；尾行编辑也重建并测量所有单元格 | 只观察可见单元格相关资源；单元格按内容、对齐、表头、排版和资源身份缓存富文本与自然宽度，未变化单元格保持身份 |
| 大表格 | 只限行数，列数多时仍创建大量 NSTextView | 预览最多 32 列、500 数据行，包含表头的总单元格不超过 2,000；三语提示说明预览范围，完整源码和纯文本导出不裁剪，隐藏单元格不启动富资源后端 |

缓存均属于当前文档，不引入跨空间内容缓存。图片路径授权、下载与像素限制、公式/图表离线执行和 CSP、文档内资源总预算及失败重试边界继续有效。

## 性能证据

新增可选基准使用相同原生富文本输入，在 Debug 测试环境比较旧式全文替换与后缀替换；两者均更新显示栈及独立测量栈，再在固定宽度排版。输入为 600 段中英混排、emoji 与稳定前缀，连续追加短尾部，统计更新与测量时间。每轮同时断言高度一致。

| 方法 | p50 | p95 |
| --- | --- | --- |
| 全文替换 | 23.06 ms | 23.16 ms |
| 后缀替换 | 1.68 ms | 1.76 ms |

该数据不包括网络、标准 Markdown 解析、SwiftUI 合成或屏幕绘制，不代表整机 FPS、真实模型速度或峰值 RSS。基准不设置易受机器负载影响的 CI 时间门槛。正确性回归验证未变化合并正文的对象身份、表格尾部编辑的复用和单元格预算、TextKit 后缀编辑与字体变化、Unicode 字素，以及文本更新期间资源任务继续执行并提交到最新文档。

## 验证

在 `AgRoom/` 下：

```bash
env DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --build-system native --filter 'Markdown|Selectable|ReadingTypography|ReliabilityRegressionTests'
env DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer AGROOM_MARKDOWN_BENCHMARK=/tmp/agroom-markdown-benchmark.json swift test --build-system native --filter MarkdownPerformanceRegressionTests
env DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --build-system native --no-parallel
env DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -project AgRoom.xcodeproj -scheme AgRoomApp -configuration Debug -destination 'platform=macOS' build
```

定向回归、最终代码的分组全量回归及签名 App 构建已通过。整轮回归曾在任务中心原生按钮夹具的系统 Vision OCR 同步等待中停止推进；测试宿主线程采样显示 `VNRecognizeTextRequest` 等待以及 Dispatch 工作线程达到软上限，主线程主要处于 RunLoop 等待，未显示 Markdown 热循环。中止该次测试后，将此宿主与其余回归拆为独立进程执行；不把中止的运行计作通过。两个分组最终均通过，原先等待的按钮预览用例在独立宿主中正常完成。复现分组使用 `swift test --build-system native --no-parallel --skip ProductTaskCenterHostTests` 和 `swift test --build-system native --no-parallel --filter ProductTaskCenterHostTests`。原有回归包含真实离线 KaTeX/Mermaid、多个图表从空模型开始加载、窄宽与明暗宿主、尾部行高度、逐字符代码围栏以及后到引用链接定义。截图开关相关用例按配置执行或跳过。

整篇标准解析仍是有意保留的正确性边界，不是增量 AST 解析。单个超长段落和大型列表/引用内部的排版仍可能涉及整个容器；没有以拆分语义容器或破坏连续正文原生选择换取速度。真实长会话滚动、Retina 窗口拖动和 Instruments 主线程/分配采样仍应在实际使用数据上单独评估。

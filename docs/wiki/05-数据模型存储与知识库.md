# 数据模型、存储与知识库

阿吉屋使用 GRDB/SQLite 保存结构化数据，使用文件系统保存技能、附件、工作区成果和部分运行记录。数据设计的第一原则是明确全局与空间归属。

## 存储拓扑

| 存储 | 归属 | 典型内容 |
|---|---|---|
| `global.sqlite` | 全局 | LLM Provider 元数据 |
| `personal.sqlite` | 生活空间 | 会话、消息、智体、记忆、知识、邮箱 |
| `work.sqlite` | 工作空间 | 与生活空间相同的独立表结构 |
| `workspaces.json` | 全局 | 对话工作区注册表（名称 ↔ 目录，条目带空间标记） |
| `<space>/skills/` | 空间 | SKILL.md、脚本、参考资料和快照 |
| `<space>/attachments/` | 空间 | 导入聊天的附件 |
| `<space>/databases/` | 空间 | 用户在数据工作台创建或显式导入的 SQLite 库 |
| `<space>/app-drafts/` | 空间内任务状态 | 待安装定义与来源会话身份，跨重启恢复；与已安装应用分开 |
| `<space>/apps/<app-id>/` | 空间内应用 | 定义、草稿、独立 SQLite 业务记录与受管文件；缓存可再生 |
| `~/Documents/AgRoom/` | 受管文件区 | files、workspace、privatespace、default-chat（其下按空间分 work / personal） |
| `daemon/personal/`、`daemon/work/` | 各自空间的运行交接 | 新任务的快照、owner、执行日志与隔离证据 |
| `daemon/` 根 | 全局协调与旧版兼容 | 单实例 `daemon.lock`、新版 Store 的 `store.lock`；尚未迁移的旧运行和隔离证据可能仍含空间内容 |

空间数据库由 `SpaceStore` 创建，开启 WAL 和外键。服务构造函数接收单一 `DatabaseQueue`；禁止服务在内部自行选择另一个空间。

Daemon 新交接记录按可信 `record.space` 写入固定的 `personal/` 或 `work/` 路径；Daemon 读取时同时携带记录来源，旧根记录仅在原来源收尾。相同运行 UUID 出现在不同空间可独立存在，同一空间的旧新重复或身份不符则保留原证据并阻止自动执行。新版 Store 的文件变更使用短时跨进程锁；人工放弃先确认没有 Daemon 持单实例锁，数据库异步调用前释放文件锁，返回后重新核对证据。owner 已写而正文缺失、损坏隔离文件和无法归属的旧根证据不能当作「没有任务」；空间可归属的证据只向该空间展示，无法归属的旧证据只给全局阻塞与人工查看入口。只读旧根盘点器不会搬迁文件；单空间数据库探针与纯计划器仅给出可继续核验的预检结果，不读取另一空间库或授权迁移。真正执行仍需旧版本写者停机、发布前数据库归属重验、持久标记与中断对账。目录分区也不是操作系统级加密边界。

用户自建库按空间列出，同名创建和导入都拒绝覆盖。旧版共享 `AgRoom/databases/` 保留，不自动推定其空间归属；用户可从工作台显式导入到当前空间。导入使用 SQLite backup 读取一致快照，包含已提交的 WAL 页，不直接复制运行中的主文件。 用户库删除经界面逐次确认后直接删除当前空间内的普通 SQLite 文件及辅助文件；应用空间业务库和其他空间不在删除范围。删除与工作台查询通过维护租约互斥，并在文件移除前关闭缓存连接。MySQL 连接定义与密码分别存于所属空间库和 Keychain，删除远程连接仅移除该定义与凭据，不向服务器发送删库 SQL。

对话 `sql_query` 只绑定组装时选定的当前空间 SQLite 路径；参数通过 SQLite 占位符绑定，不能由工具参数选择另一空间的库。单条语句限制和 `ATTACH` / `DETACH` / `VACUUM` 禁用共同防止访问其他数据库文件；写入仍经调度确认与副作用日志。

原生小应用的数据另存于各自空间目录，按固定安装身份访问，不写入共享知识表充当私有业务存储。应用数据使用宿主命名迁移和事务；文件元数据保存 UUID 相对路径与摘要，字节单独落盘。完整应用备份导出一致的逻辑快照，恢复通过暂存目录与原子交换发布；完整空间备份也包含应用定义、私有记录和文件。具体生命周期与备份范围见 [11-原生小应用](11-原生小应用设计.md)。

AgRoom 首次启动时建立自己的数据目录，钥匙串使用 `com.agroom.app`。原版数据留在原处。

## 核心模型

### 会话

`ChatSession` 保存标题、置顶状态、归档状态、所属工作区、会话模式、时间和挂起快照等会话级信息；消息正文存于独立消息表以支持摘要列表和按需加载。`ChatMessage` 保存角色、正文、轨迹、思考、附件、token 与回答版本。

附件归档路径保留原有约定；运行时仅将输入中引用的本会话附件复制到当前工作区的 `.agroom-attachments/`，模型请求使用副本路径，不为读取附件而开放整个空间归档目录。原附件元数据与备份仍使用归档路径。

编辑、重试、流式更新和 daemon 写回应保持稳定的消息 ID。多字段更新需要在单个数据库事务中完成，防止旧进度覆盖最终状态。

聊天首访只读最近一页，按持久化 `seq` 游标向前加载；单页同时限制条数和正文大小。`messageOffset` 是内存页位置，不进入备份；尾页保存按原始 seq 写脏行与截断尾部，不能清掉未加载的早期消息。完整导出和历史分支使用完整读取接口，读取失败不能拿部分页冒充完整内容。搜索只读取数据库命中的会话 ID，不为命中结果批量加载整段历史。

`chat_restore_tokens` 保存本机的会话恢复版本，`ChatSession.restorationToken` 仅用于运行时校验、不进入备份。恢复完成后更新受影响会话的版本；普通保存与守护任务写入在同一事务内校验版本，旧内存快照不能覆盖恢复结果。守护移交记录随运行携带版本，旧检查点遇到恢复版本变化进入人工恢复。

会话归档使用独立的 `isArchived` 列（不复用 `isHidden`）：旧数据缺列时由 `v3_chat_archive` 独立迁移补齐并默认未归档，旧 JSON 缺字段时解码为 `false`。批量归档/恢复与工作区批量迁移都只更新会话元数据列（不写消息表），在单个写事务内完成，避免把尚未加载的消息覆盖为空。归档不删除数据，会话仍保留消息、附件、草稿、置顶状态与工作区归属，仅从主列表移入「已归档对话」入口。

### 独立任务运行

`product_task_runs` 按执行 ID 保存对话任务的请求、结果、状态、实际轨迹、产物引用及用量。`ChatMessage.taskRun` 与回答版本保存同一执行身份：重试、编辑重发分配新 ID，确认或提问后的原地继续沿用原 ID。消息 ID 仍用于会话定位，不能再用它代替运行 ID。

失败回答重建为助手角色、或编辑末轮问句重发时，沿用该回答原有的消息 ID 与消息时间戳，历史回答版本继续绑定原执行；只有新一轮执行分配新的任务 ID。修改较早问答时仍通过历史分支创建新的会话与消息身份，复制来的旧执行只保留来源引用。保存层继续拒绝把已有任务重新归属给另一条消息。

- `SessionService.save` / `updateMessage` 在写消息的同一事务里更新运行记录和按运行去重的统计；首次保存失败时不启动引擎。终态回执不被旧的运行中快照回退，运行原有的项目、模式和请求不会被后续会话元数据修改重新归属。
- 请求、结果及工具详情有明确大小上限，列表只读有界摘要，详情按需加载，并显示摘录说明。任务记录保留真实轨迹中的产物引用，不从模型叙述猜文件路径。
- 消息被重试或编辑替换时，已经保存的其他执行仍可回看；显式删除会话在同一事务中删除关联任务正文。复制历史会话只作为上下文，以 `sourceTaskRunID` 标记，不重复计为执行；副本上真正开始的新任务有自己的 ID。
- 命名迁移兼容消息分表及旧 `messagesJSON`。旧回答及回答版本生成稳定的历史身份，损坏消息仍留在原修复路径；不补造未知结束时间或使用统计。
- `ProductTaskCenterStore` 从当前空间的任务、协作、定时和作业回执表投影摘要，与本空间的活动作业快照合并，按时间和稳定键翻页。筛选先在数据库执行，旧待处理记录不会被最近完成记录的数量挤掉；无运行宿主的活动快照显示需检查，不自动重放。
- 任务中心支持按单次运行或整个空间清理历史展示。确认时在所属空间的事务内复核来源状态，将可清理运行的来源及 ID 写入 `product_task_center_cleared`。范围包括成功、取消、失败、未完成、错过和已中断的运行。旧宿主留下的排队或运行中作业可按中断清理，当前宿主的活动回执、活动快照和等待保存的作业受保护。查询在分页前过滤已清理记录，工具栏的失败提醒也使用同一标记。原会话、协作报告、作业回执和成果可从各自来源读取。清理标记随空间备份恢复。
- daemon 写回携带预期执行 ID，防止旧进程覆盖复用同一消息的新执行；终态消息不再追加迟到的流式进度。
- 备份包含独立任务记录，恢复重建工作区及产物路径。旧包缺少独立记录时从已保存回答重建。恢复点只比较和还原本次导入的任务行，之后新增的无关任务及其统计保留。

定时运行不再随新运行自动裁剪；后台作业的完整历史保存在同空间的 `product_job_runs`，工具栏缓存上限不影响任务中心翻页。完整界面交互验收继续由产品专项追踪。

### 目标执行

目标执行另以空间内 `execution_goals`、`goal_attempts`、`goal_events` 关联多次独立运行，保存定义、累计预留与验收状态；正文和成果不重复存储。表结构经独立迁移注册，随会话级联删除。完整备份纳入目标内容并移除执行范围授权，恢复后暂停。契约见 [目标执行](19-目标执行.md)。

### 模型用量

`provider_usage` 归属各自空间库，记录请求 UUID、提供者 ID、模型、来源、可选会话 ID、发起/结束时间、状态及服务商返回的输入/输出 Token；不存提示词、回复、端点或凭据。请求发出前保存起始记录，每个实际 HTTP 尝试（含协议参数自适应重试）单独记账，结果持久化后更新统计页。主对话与审核复用空间绑定的 Provider；子代理可独立选提供商，但共用发起空间的用量记录器。标题、记忆提炼及其他 AI 辅助入口也绑定发起空间。流式中断保留已经收到的 Token 计数，明确说明可能不完整；取消后的收尾不随调用任务取消；退出留下的未完成记录与服务商未返回的用量明确展示，不能把缺失值解释为零。Anthropic 输入统计包含其返回的缓存读取/创建 Token。

请求模型与服务商返回的模型标识分别保存，提供商名称采用请求时快照；配置后来修改或删除不会改写历史。`ProviderTokenUsage` 统一两种协议的普通输入、缓存读取、缓存写入与输出（可选推理明细）；OpenAI 输入总数包含缓存子项，Anthropic 输入总数由普通输入和两个缓存子项组成。SSE 累计事件更新同一快照，不重复求和；缺失的缓存信息保持未知，旧记录不能按当前模型推断。请求明细按发起时间和 ID 游标分页。

回答及其版本快照另外保存可选的 `reasoningTokenUsage`，记录该次回答的已报告推理 Token 和未上报请求覆盖；错误收尾、重试与切换版本保留各自统计。字段随消息 JSON 与运行快照存储，旧数据缺字段仍可解码并保持未知，不根据现有思考文本补造历史推理用量。

`v1_provider_usage` 迁移只补计仍存在的历史回答，遍历所有已保存版本，避免把显示版本的镜像字段再算一次。历史版本缺少独立请求时间，按原消息时间归日，并与新请求数分开展示。新记录不依赖会话的更新时间，编辑、归档或删除对话不会移动或清除已产生的用量。历史删除数据无法补回。空间备份包含独立的 `usage.json` 账本段，恢复按请求 ID 幂等合并，不覆盖既有请求；回滚只清理本次新增的回执。旧包缺少账本时保留目标空间已有用量。

用量查询支持按请求发起时间的半开日期区间过滤，总览、模型、会话和每日聚合使用相同区间。状态、缺失 Token 与缓存信息不完整筛选在游标分页之前执行，不能先取一页再过滤。每项计数同时汇总已报告该字段的记录数，以区分完全未知、部分已报告和明确返回零。展示分组使用提供商身份与模型名，同名的请求模型和响应确认模型仍保留独立来源，不能据此推断未知的实际模型。

### 编码任务

编码任务工作记账位于同一空间库的 `coding_tasks`，通过会话 ID 与工作区目录身份隔离；包含有界请求/笔记、文件基线和构建回执，不进入全局库或 `Hub` 缓存，删除会话时清理。它属于内部运行状态，不扩大业务数据备份范围。详见 [15-编程工作流](15-编程工作流.md)。

### 笔记

笔记正文、声纹和处理状态绑定所属空间的数据库；生产正文使用按空间保存在 Keychain 的 AES-GCM 密钥，搜索不保留明文内容投影。媒体按有界块存储，导入暂存和未发布块不进入便携备份。备份恢复校验媒体块与关键帧的一致性，使用目标空间密钥重新加密并撤销设备执行授权。数据表、迁移和大文件边界见 [笔记与 Memonta 迁移](18-笔记与Memonta迁移.md)。

### 对话工作区

`ChatWorkspace`（`WorkspaceRegistry`，全局 `workspaces.json`）保存「名称 ↔ 目录」映射，会话通过 `workspaceId` 归属其中。

- 工作区按空间隔离：每个空间各有一个默认工作区，目录为受管区下的 `default-chat/<space>`；读写 API 都要显式传入空间，跨空间 id 回退本空间默认工作区。
- 新增工作区在 `files/` 下创建同名文件夹；添加已有工作区接受任意目录（拒绝过宽或系统/应用私有数据位置），并在登记前探测读写权限。
- 会话列表按工作区分组，工作区目录是该会话文件类工具的默认写入根。
- 目录被文件页删除或改名后必须同步注册表（移出登记 / 跟随新路径）；目录缺失的工作区标记为「失效」，不能静默回退到其他目录。
- 移出工作区只删除注册表登记，不动磁盘目录；该工作区下的会话（含已归档）显式迁移到当前空间默认工作区。迁移顺序为先迁库、后写登记：库失败即中止，登记写盘失败则回滚会话归属，禁止出现「界面成功、重启后回到原状」。
- 有运行中、等待确认、待发送或守护进程后台执行的会话时，禁止归档工作区与移出工作区。

工作区的项目说明、知识库选择和常用技能保存在所属空间的 `workspace_projects`，由工作区 UUID 关联，不进入全局注册表。保存校验修订号，竞争编辑需刷新后重试；配置损坏阻止启动，不能回退成全部知识。未选择限制表示本空间全部知识，显式空选择表示不使用知识。项目配置只提供任务上下文，不产生文件授权或审批豁免。

每次执行冻结 `RunResourceContext`，主引擎、子智体和团队沿用同一空间与知识范围。配置修改只影响后续执行；挂起恢复及守护交接保持原快照。快照随消息、回答版本及独立运行历史保存；完整备份覆盖项目配置，恢复时连同上下文重新绑定目标空间和工作区，恢复点回退保护后来编辑。

### 智体、技能与记忆

- `Agent` 保存人设、可选提供商身份 `providerID`、模型覆盖、知识开关和技能挂载。`providerID` 在空间库内保存对全局配置的引用，不保存端点或凭据；旧 JSON 缺字段时继承主调度，已有空间库通过独立迁移补列。空间完整备份保留该选择，恢复后引用不存在的提供商须由用户重新选择，不能自动绑定同名或其他提供商。
- 当前技能以文件夹制 `SkillStore` 为权威；SQLite 中的旧技能表只用于迁移。
- 每条记忆保存在所属空间，可进一步指定工作区。对话、子智体和团队只检索整个空间通用的记忆和当前工作区的记忆。聊天、记忆搜索工具和记忆管理页共用本地词项索引，中文连续文本按相邻双字切分。只有用户勾选跨话题使用的偏好能在缺少关键词命中时进入聊天上下文，仍受本轮预算约束。

### 自动记忆提炼

自动提炼默认开启，由前台对话成功收尾触发，按单个会话已完成问答轮数累计，每间隔 5 轮尝试一次；不会在启动时扫描历史会话。提炼使用会话所属空间的服务，不能随当前显示空间改变落库归属。

每次提炼使用本批次的合格问答。会话移过工作区时，按每轮运行记录的工作区分开发送。旧记忆在本机按用户发言检索，每个请求最多附带三条已启用的相关摘录，每条最多 120 个字符。没有命中时只发送对话片段。本批消息和相关记忆用请求内编号引用，模型返回的来源编号与原文摘录须在本机核对。来源可标记为用户明确表达或模型推断，助手发言只能作为推断的依据。项目约定绑定发起工作区。用户明确纠正同一范围内的自动记忆时，应用可停用旧条目。用户手动编辑或勾选跨话题使用的条目会保留。

空间库按会话保存上次处理到的消息 ID。首次处理已有长会话时从最近一个完整窗口开始，此后按来源顺序接着处理。保存新条目、在同一范围内对启用及停用条目查重、处理替代关系和推进进度使用一个事务。模型明确返回空列表也推进进度。解析、写入或取消失败保留原进度，聊天重启后继续由后续合格问答触发。撤销按记录 ID 和修订号执行，返回实际停用条数，并在旧条目未被改动时恢复被替代的记忆。

输入区可排除下一轮的应用记忆。选择按会话保存于当前界面，成功发送或入队后消费，队列中的每条消息保留自己的选择；重试保守继承原问句的排除。该轮不注入记忆、不提供记忆工具，也不参与自动提炼；以后提炼同一会话时仍跳过该组问答及其回答版本。为防止绕过，受限知识或排除记忆的执行不提供应用数据库和备份工具，也不暴露应用数据库路径。历史对话和用户手动提供的资料仍可进入上下文，排除选项不清除这些内容。

提炼日志记录完成数量和失败阶段。手动新增默认按所选类别在本机保存。选择用模型分类时，页面显示接收方，保存使用界面显示的同一个提供者。

### 产品偏好与本机统计

`product_preferences` 与 `product_events` 位于各自空间数据库中。常用问句、首个任务的选择和成果检查进度、任务预算与模型单价均属于该空间，不写全局设置。`Hub.makeProductPreferencesService(for:)` 从指定空间连接现建服务，不缓存。

旧版全局常用问句缺少来源空间，升级时不推断归属，也不在任一空间的普通列表显示。用户在目标空间明确确认迁移后，先保存完整去重列表，再移除旧副本；容量不足、解析或写入失败保留旧副本。迁移串行化，防止两个页面同时认领。

首次成果的设置草稿和执行进度进入所属空间的 `product_preferences`：设置只保存任务、模型选择、示例开关、资料文件名和开始时间，不保存文件 URL、书签、连接成功标记或密钥；运行进度在同一事务内核对目标会话已经存在后保存；普通删除会话时同时清理对应进度，保留已有统计，备份恢复的维护路径不触发该清理。

首次任务引导的状态查询是只读操作，不申请数据库写入维护租约，启动自动备份期间仍可加载。跳过、成功任务落盘和成果确认在原写事务内持久保存隐藏标记；升级迁移与备份导入会补齐旧成功历史的标记，删除历史或清除统计不会使引导重新出现。维护锁繁忙须显示稍后重试，不能统一解释为应用支持目录权限不足。

统计只保存事件类别、随机身份、时间和耗时，不保存问句、正文或路径，不上传。首次成果由用户检查实际回执中的文件或可验证的保留版本后确认，确认与耗时事件在同一事务内保存，不能确认已被新任务替换的旧进度；成果后续操作按来源回答去重统计。统计可在设置页查看、刷新和清除，清除不会删除业务内容。不回填或推测没有证据的历史数据。

清除统计同时保存 `metrics.since`，事务失败时原计数与统计起点一并保留。后续保存已在起点之前开始的对话执行不重建其计数；早于起点的首次成果流程也不补计。成果后续使用只统计同一范围中已有产出事件的执行，重复预览、打开、导出或继续修改不抬高分子。清除与事件提交后通知界面刷新；其他空间继续使用自己的独立计数。

模型单价按空间、提供商身份和模型名保存，支持公开价格目录补齐及手动配置，缺失用量或单价保持未知。估算按普通输入/输出费率计算，不推测缓存优惠、税费或汇率，不合并不同币种，也不作为账单。

费用重计记录在同空间 `product_preferences` 的 `cost-checkpoint` 中保存独立身份、起点、边界旧请求身份以及服务商余额快照，不存密钥。`UsageService` 在同一事务中读取起点和聚合费用，在同一写事务中核对旧身份并提交新余额与起点；原用量账本不删改。普通余额刷新只更新快照，拒绝旧起点及较早查询的迟到写入。费用查询使用重计起点与日期范围的交集，旧请求跨起点完成时仍归原范围；空间备份沿用偏好数据段保留该状态。

### Provider

`LLMProviderConfig` 保存名称、类型、端点、模型和启用状态。密钥不属于该模型，由 Keychain 单独保存。

### 外部 MCP 服务

`mcp_servers` 由空间迁移 `v1_mcp_servers` 建立，保存配置 JSON（地址、认证类型、启用状态、已发现的工具定义、选择集合、修订号与凭据引用），不含 Token。`MCPServerConfigService` 绑定单一空间连接，两个空间的配置、工具目录、选择与凭据均不共享；凭据使用 `mcp.<space>.<serverID>.<credentialID>` Keychain 键。

配置更新使用修订号做乐观并发检查；新 Token 先写独立 Keychain 条目，再由数据库事务发布引用，事务失败清理新条目并保留旧配置。删除配置后清理其凭据，不删除外部服务的数据。迟到编辑不能复活已删除配置。协议与审批契约见 [03-工具系统](03-工具系统.md#外部-mcp)。

### 邮箱

列表筛选在空间数据库内执行，过滤先于分页；游标使用日期、UID 和本地 ID，跨文件夹的同日期、同 UID 条目不会互相覆盖。界面可搜索主题、发件人、摘要及缓存正文，并组合收件人、附件名、大小、日期与标记条件；范围为文件夹、账号、同空间统一收件箱、当前空间或指定归档的导入批次。批次按来源记录查询实际创建且仍保留的成员，配合账号与批次索引，排除重复项并跟随本地移动、删除与撤销。只反映本机已缓存数据，不代表服务器全集。批量目标和本地归档的边界见 [17-邮箱工作流](17-邮箱工作流.md)。

列表排序新增日期升序及发件人/主题排序，分页结果同时返回数据库原始排序键，避免 RFC 2047 展示解码与 SQL 排序不一致。日期空值保持在末尾，文本键相同后继续按日期、UID、本地 ID 定位；游标与排序类型不匹配时拒绝续页。显示偏好位于当前空间的 `product_preferences`，不写入共享 UserDefaults。

自动收件箱同步使用 `mail.autoSync` 和 `mail.autoSync.baseline` 空间偏好：基线包含账号连接身份摘要、文件夹 UIDVALIDITY 与最高远端 UID，不含邮件正文、地址或凭据。恢复时校验设置与数量边界，关闭自动同步/提醒并清空基线；不将旧设备的通知基线或自动联网状态直接激活。

邮箱表与空间库其余表同库、同迁移机制（`DatabaseBootstrap` 注册为命名迁移 `v1_mail`，后续字段升级独立迁移），切换空间即切换连接：

```text
mail_accounts          # 来源类型：IMAP 连接元数据或本地归档（无密码列）
  └── mail_folders     # (accountId, path) 唯一，携带同步游标 uidValidity / uidNext
                       # 层级：parentPath / delimiter / isContainer 支撑侧栏树形分组；
                       #       \Noselect 容器不承载邮件读取，不进 SELECT/FETCH 同步循环
        └── mail_messages   # (folderId, uid) 唯一，只存元数据与摘要
              ├── mail_raw_messages # 按需获取的完整报文，带来源与独立缓存上限
              ├── mail_bodies       # 正文及派生的 HTML 可读检索文本，与元数据分表
              ├── mail_thread_links # 同账号精确线程头的派生索引，随原记录重建，不独立备份
              └── mail_attachments  # 附件元数据（可选 localPath）
mail_drafts            # 按账号保存本机草稿，含正文格式范围、附件字节和转发附件准备状态
mail_sync_coverage     # 最近核对的远端数量、完整度和时间
mail_pending_flags     # 尚未获服务器确认的本地标记与修订身份
mail_import_batches    # 本地归档导入清单与终态
mail_import_entries    # 按批次、候选身份持久化的逐封回执
mail_import_origins    # 原件摘要、相对来源、导入批次与归档内去重身份
mail_import_undos      # 批次撤销回执与阻止迟到导入写回的持久标记
mail_saved_searches    # 当前空间保存的名称、条件与固定文件夹/账号/空间范围
mail_folder_preferences # 文件夹收藏、侧栏隐藏与按账号保留的最近成功移动目标
mail_folder_mutations   # 远端目录修改意图、逐目录回执及未决结果；恢复不重放命令
```

- 账号删除先撤销当前进程该账号的在途请求与排队项，再在账号租约内执行单事务清理；数据库触发器维护账号删除标记及邮件级联，拒绝其他进程的迟到文件夹、正文和附件写回。标记只保留账号身份，不保存内容。
- `MailAccountCoordinator` 按空间与账号协调实例，不缓存服务或连接；排队可立即取消，后台同步在 UID 批次间让出账号，前台操作优先接续，原同步连接保留但不能在未重新取得租约时写入。
- 本地归档以独立 `sourceKind` 和账号身份持久化；无端点或凭据，原件来源为 imported，不参与远端缓存淘汰。导入来源与结果按空间保存，完整备份包含归档和回执；恢复时校验来源类型、摘要和回执身份，未结束批次需核对结果。详见 [17-邮箱工作流](17-邮箱工作流.md)。
- MBOX 导入结果可选记录实际来源变体，随回执、清单和备份保留；旧记录缺失时不推断格式。字节位置只描述当前授权文件中的记录，不携带外部路径或授权；当前界面使用有界元数据索引，批次中的持久恢复清单只保存相对来源、记录位置、摘要、选择和目录映射；继续导入必须重新选择来源。
- 导入目录映射预览绑定当前数据库、所选原件和目标目录链；新归档与起始批次记录原子提交，目录按实际新增邮件惰性创建。映射只改变目标目录，保留原始来源文件夹的去重键；重复项不移动，逐封回执仍在邮件写入事务内提交，不逐封复制整份批次清单。持久恢复清单绑定原批次和项目身份，领取新运行凭证后旧执行者不得写回；清单不携带跨重启授权。
- 正文查询直接读 `textBody`，HTML 只派生可读文本到 `searchText`，不重复保存纯文本。两者与 HTML、邮件头共同按 UTF-8 字节计入正文缓存上限；淘汰后不再参与正文搜索。迁移及旧备份恢复重新派生检索文本，原件保留策略独立。
- 导出预览为绑定发起数据库连接的内存只读记录，保存来源、命名身份和缓存可用性，不含凭据或外部目录授权，不随备份恢复。原始报文与正文缓存分开：PDF 可在账号租约内从保留原件恢复正文和本机部件，禁用补全下载时不读取凭据或连接服务器；目录输出与结果清单的固定路径契约见邮箱专项页。
- 保存筛选随空间备份恢复，校验名称、条件和容量；账号或文件夹被删除后应用筛选报来源不可用，不回落到其他账号。保存筛选不提供跨生活/工作空间范围。
- 文件夹偏好通过本地文件夹身份关联，删除文件夹或账号级联清理；只存收藏、侧栏隐藏和最近成功移动的时间，不存凭据或网络连接。最近目标按账号有界保留，不因淘汰历史而移除收藏或隐藏；备份校验布尔值、日期和文件夹身份。筛选编辑核对原有负载，避免过期编辑覆盖更新或复活删除记录。
- 文件夹改名保留稳定的目录 ID 及关联记录，本地归档同时保留不可变的导入来源。远端目录意图在发命令前落库，按账号限制单个未决记录并有界保留历史；备份校验负载大小、层级、状态与逐步回执，不保存凭据或缓存重建的临时同意。未决记录阻止依赖旧目录身份的对账，核对只读服务器并由用户确认本地收尾，完整契约见 [17-邮箱工作流](17-邮箱工作流.md)。
- IMAP 账号只保存连接元数据；密码 / 授权码由 `KeychainService` 按「空间 + 账号 id」隔离保存，不入库、不进备份。
- 附件按需下载到受管区 `default-chat/<space>/Mail/<attachmentID>/`，成功写入文件后才登记 `localPath`；缓存只接受空间边界内的普通文件。远端文件名只取末段，空名、目录名或含控制字符时使用 `attachment` 加 MIME 类型对应的已知扩展名，不能把空文件名交给文件 URL 解析为进程工作目录。
- 文件夹与邮件按 `(accountId, path)`、`(folderId, uid)` upsert，保留既有 id 与同步游标；`UIDVALIDITY` 变化时该文件夹全量重建。
- 同步会读取完整 UID 集合与已读/星标集合，对账远端删除与标记。新增邮件优先落库；后续同步逐批回填缺失的历史 UID，显式「加载更早邮件」使用精确 UID 批次，不扫描大片空 UID 区间。完整度只在远端查询与本地事务全部成功后更新，不用列表分页数量推测完整度。
- 标记查询使用 `UID SEARCH SEEN` / `FLAGGED` / `DELETED`，由协议库的类型化搜索条件序列化；`STORE` 的 `\Seen` / `\Flagged` / `\Deleted` 不能直接用作搜索条件。协议回放同时核对查询和写入的实际命令，查询失败必须上抛，不能冒充空集合参与对账。
- 本地标记立即生效并进入待回写表，失败保留到后续同步重试；回执按修订号清理，迟到回执不能清掉更新的编辑。远端标记不能覆盖尚未确认的本地编辑，确认后可接收其他客户端的新修改。服务器未报告 `UIDVALIDITY` 时重新获取已缓存身份；同 UID 的非空 `Message-ID` 变化会清除旧正文和附件。
- 重建缓存先回写待同步标记，再清除当前文件夹的服务器缓存并重新同步；草稿和本地发信副本保留。标记回写失败时不清缓存。搜索工具和界面各自说明实际覆盖范围，不能冒充远端或未缓存正文的完整搜索。
- 本地自产副本（无 IMAP `APPEND` 时投递成功后的「已发送」）使用保留 UID 区间：不参与增量游标，也不被 `UIDVALIDITY` 重建清除。
- 邮件移动后 `UID` 必须换成服务器在目标文件夹分配的新值（RFC 6851 不保留源 UID）：服务器支持 `UIDPLUS` 时取 `COPYUID`，否则在目标文件夹按 `Message-ID` 回抓；两者都拿不到时保留原记录并提示重新同步，不在目标文件夹留下对不上服务器的假 UID。`upsertMessages` 在 UID 变化时按 `Message-ID` 接管旧行，因此重新分配 UID 不会产生重复记录。
- 草稿带投递凭证（`deliveredAt` / `deliveredMessageId`）：非空即表示这封邮件已经投递出去。投递成功但本地副本落库失败时草稿保留，界面据此提示「已发送（本地记录失败）」并禁止重发，而不是引导用户再发一次。发信顺序固定为「投递 → 登记凭证 → 落副本 → 删草稿」：副本失败时草稿连同凭证仍在，绝不出现「已投递但本地无任何痕迹」。
- 永久删除只作用于目标邮件：不带 UID 的 `EXPUNGE` 会清掉该文件夹内所有已标 `\Deleted` 的邮件，因此 `MailService.deleteMessage` 之外还必须有 `MailSyncService.safeDelete` 的待删集合检查与对账（详见 [03-工具系统](03-工具系统.md)）。
- 核心模型的字段与展示回落规则见 `MailModels.swift`（`MailAccount` / `MailFolder` / `MailMessage` / `MailBody` / `MailAttachment` / `MailDraft`）。
- 头部文本按 RFC 2047 解码：IMAP `ENVELOPE` 的 `Subject` 与地址显示名是原始值（可能含 `=?UTF-8?B?...?=`），协议适配层写入时解码一次，读取映射 `MailMessageRow.toMessage()` 再解码一次以纠正历史入库的原始值；解码幂等（非编码文本原样返回），实现见 `MailHeaderText`。
- 正文装配：只取文本部件，拼装成 `multipart/alternative`（而非 `mixed`）——基类 `Multipart.tryGetValue` 遇到第一个不匹配的 TextPart 即 break，`text/plain` 在前时 `MimeMessage.htmlBody` 会取不到。适配器对「纯文本槽里其实是 HTML 源码」（发送端把 HTML 塞进 `text/plain`，或服务器把 HTML 部件报成 `text/plain`）做归一化，`MailHTMLView` 在渲染侧对历史缓存正文做同样兜底。

### 多智体协作任务

团队任务快照与空间其余数据同库、同迁移机制（`v1_team_tasks`），切换空间即切换连接：

```text
team_tasks
  id            # 任务 UUID
  goal
  status
  planJSON      # TeamPlan：子任务、依赖、验收标准、预算估算
  reportJSON    # TeamTaskReport：子任务结果、证据、产物、验证结论、用量
  startedAt
  updatedAt
  finishedAt    # 终态才写入
```

- `TeamTaskStore` 只接收单一空间的 `DatabaseQueue`，没有跨空间查询 API；`Hub.makeTeamTaskStore` 现取现建，不缓存。
- 每次保存整行 upsert；报告是快照，不是事件日志。P1 用 JSON 快照而不是拆分 `team_subtasks` / `team_artifacts`：任务板只需要整体展示，规范化留到出现跨任务查询需求时。
- 存储失败不阻断任务结果（任务板是旁路）；损坏的 plan/report JSON 行在读取时跳过并记日志，不让单条坏数据拖垮任务板。
- 任务板只读展示，不提供运行中恢复；重启后可能看到最后一次 `running` 快照，用户可手动删除。
团队写快照同库、同迁移机制（`v1_team_writes`）：

```text
team_writes
  id
  taskID
  space
  rootPath      # 写入时的工作区根
  path          # 规范绝对路径
  oldContent    # NULL = 团队新建文件
  newContent
  createdAt
  revertedAt    # NULL = 尚未回滚
```

- 写入前先落快照，快照失败则不写；任务板按 taskID 读取快照并逐条回滚。
- 回滚只恢复仍等于 `newContent` 的文件；旧内容为 NULL 时删除新建文件。回滚与服务共用路径校验和写租约。
- 批量回滚先预检任务全部未回滚记录（同路径按新到旧），任一文件变化则整批放弃；预检通过后一次拿齐路径租约再执行。
- `TeamApprovalCenter`（待审批写请求）、`TeamLeaseCenter`（路径级写租约）、`TeamProgressCenter`（实时进度）与 `ProviderConcurrencyGate`（端点并发闸门）是进程内状态，不落空间库：审批请求 600 秒过期，租约 TTL 到期释放，任务终态清理进度，App 退出即消失；daemon 禁用团队写。

### 定时任务

定时定义与运行记录同库、同迁移机制，切换空间即切换连接。

`scheduled_tasks.optionsJSON` 与 `scheduled_runs.experienceJSON` 由 `v2_scheduled_experience` 幂等迁移补齐。定义保存每次 Token、工具次数和时间预算及变化标准；运行捕获本次预算、用量完整性、实际 Provider/模型、输出摘录及比较值/基线身份，不能用之后的设置替换历史。旧记录使用安全默认或未知用量，损坏的非空定义选项拒绝执行。

终态、变化基线和最近运行字段同事务提交；首轮或定义改变建立静默基线，失败不推进基线。同一回执重试幂等，失败后只补写、不重放引擎。保存仍失败时保留进程内结果并显示待处理，退出后不承诺恢复其正文。完整空间备份保留新增字段，恢复暂停定义、活动记录中断；恢复点回滚沿用整包契约。详见 [14-定时任务设计](14-定时任务设计.md)。

主要字段：

```text
scheduled_tasks
  id
  name
  enabled
  prompt              # 用户写的任务指令
  scheduleJSON        # 一次/每天/每周/间隔 + IANA 时区
  profileVersion      # readOnly.v1；能力面由代码解释
  notificationJSON    # 成功/失败/错过的通知策略
  optionsJSON         # 每次预算、变化标准与修订身份
  createdAt
  updatedAt
  nextFireAt
  lastRunAt
  lastRunStatus

scheduled_runs
  id
  taskID
  taskName            # 任务删除后历史仍可读
  trigger             # scheduled / manual / catchUp
  scheduledFor        # manual 为 NULL
  status              # pending/running/succeeded/failed/skipped/missed/cancelled/interrupted
  startedAt / finishedAt
  outputText / summary
  toolNamesJSON / toolCallCount
  inputTokens / outputTokens
  errorCode / errorText / durationMs
  experienceJSON      # 本次预算、完整用量、摘录、比较与基线
```

- `scheduled_runs(taskID, scheduledFor)` 是**部分唯一索引**（`scheduledFor` 非空时）：同一计划时刻只能有一条记录，防止重复 tick、时钟回拨或并发扫描重复领取。手动运行 `scheduledFor` 为 NULL，可多次记录。
- `ScheduledTaskStore` / `ScheduledRunStore` 只接收单一空间 `DatabaseQueue`；`Hub.makeScheduledTaskStore` / `makeScheduledRunStore` 现取现建，不缓存，没有跨空间查询 API。
- 编辑任务走 `ScheduledTaskStore.update`：只写定义与 `nextFireAt`，保留 `lastRunAt` / `lastRunStatus`；任务已删除时 no-op，避免迟到编辑复活任务。新建入口使用拒绝重复 ID 的 `insert`，避免旧草稿覆盖现有定义。
- 运行记录保存任务名快照；删除定时定义不删除运行记录，普通插入不自动裁剪。「定时」页展示最近记录，更早历史与已删除定义的运行仍可在统一任务中心翻页。显式裁剪只清理已结束记录，不能删掉用于防止重复执行的活动记录。启动时把残留 `pending/running` 标记为 `interrupted`，不自动重放。
- `ScheduledTaskCenter` 的 running/timeout 任务与 `lastScanError` 是进程内状态，不落空间库；定时定义和运行记录才是持久事实源。`ScheduledRunner` 复用 `EngineAssembly` 的只读白名单，不创建 `ChatSession`。

## 数据库初始化与迁移

App、定时任务和 Daemon 先等待 `SpaceStore.prepare(_:)` 挂载各自要用的空间。同一文件的并发请求共享一次打开、迁移与认证。窗口可先显示加载状态。同步查询 `queue(for:)` 只返回已认证的连接，挂载失败后由恢复界面发起重试。

所有表结构与索引由 `DatabaseBootstrap` 集中注册为命名稳定的 GRDB 迁移，`SpaceStore` 打开数据库后立即运行：全局库（提供者配置）与空间库（会话 / 智体 / 技能 / 记忆 / 知识 / 邮箱 / 团队任务 / 团队写快照 / 定时任务 / 定时运行记录）各一套迁移。

- Service 构造函数只接收已经准备好的`DatabaseQueue`，不产生建表副作用。
- 迁移失败即该数据库不可用：`SpaceStore` 返回 nil 并记录不可用状态，不再构造依赖它的服务，避免「启动看似成功、稍后随机报错」。故障态**按空间记录**（`issue(for:)`，`databaseIssue` 是它在当前空间上的投影）：切到健康空间后不会被另一空间的错误继续遮挡。
- 历史库由各服务原先的幂等建表逻辑升级而来，迁移体保持幂等，因此对缺少迁移记录的旧库执行 v1 迁移是安全的。
- 已完成的命名迁移不会重跑；会话字段演进必须增加独立迁移，例如 `v2_chat_auto_review` 为旧库补齐自动审核开关，历史会话默认关闭。会话摘要行解码失败由 Core 转换为领域错误，聊天页显示多语言恢复提示，不暴露可能含会话内容的 GRDB 行诊断。
- 数据不可用时 UI 展示明确状态：失败原因、数据库文件路径，以及「在访达中显示 / 打开备份文件夹 / 重试」入口。

## 数据变更规则

- 表结构演进必须兼容已有数据库。新增字段提供安全默认值或迁移步骤。
- 多表一致性操作使用事务。
- 文件写入使用同目录临时文件加原子替换。
- 破坏性迁移先创建恢复点，完成验证后再删除旧数据。
- 数据损坏、磁盘写满和权限失败不能通过 `try?` 变成假成功。
- 列表页优先读取摘要；大正文按需加载，避免启动或搜索时无界常驻内存。

## 备份与恢复

自动备份默认开启，具体触发和保留策略以 `AutoBackupPolicy` 为准。备份功能的长期目标是“声明的范围可以完整恢复”，而不是仅成功生成压缩包。

实现或修改备份时应满足：

1. 清单明确列出包含和未包含的数据，密钥始终排除。
2. 导出先写临时包，校验完成后原子替换目标。
3. 恢复前完整解析、校验版本与冲突，并建立恢复点。
4. 数据库部分使用事务；文件部分使用暂存目录和可回滚替换。
5. 附件引用在换机或恢复到新目录后仍可重建。
6. 部分技能或文件失败要进入结果摘要，不能只记日志后返回成功。
7. 自动备份按空间记录成功状态，失败后可以重试。

当前实现（`BackupService`）：

- `manifest.json` 声明来源空间、格式、逐段记录数、字节数、SHA-256 和逐类覆盖清单。空间业务数据作为有类型的逻辑记录导出；恢复只接受已知表、现有列和稳定主键，不执行包内 SQL 或引入表结构。SHA-256 发现意外损坏，不构成来源认证。
- 成果内容以相对分片和范围引用保存在 `space-blobs/`，相同摘要去重，小内容共用有界分片；`space-data.json` 仅保存其元数据和引用，避免 Base64 占用元数据容量。逐行游标读取，每次只持有一份内容；引用只能用于成果内容列，不能替换主键或其他便携字段。预检核对摘要、范围、文件身份和完整分片清单，拒绝链接、缺失、重叠、空洞及未引用字节。包总量、文件数量、元数据和单个成果的限制仍然生效，超过限制明确失败。旧内联内容包仍可恢复。
- 覆盖对话、独立任务和作业历史、成果来源及已保留版本、记忆、技能和历史版本、智体、知识及图谱业务记录、邮箱缓存和草稿、定时定义及历史、MCP/MySQL 连接定义、空间偏好和本机统计、团队任务、小应用及其私有数据和待安装草稿、用户 SQLite 数据库、聊天附件及项目资料。
- API Key、邮箱密码和 MCP Token 留在 Keychain；模型提供商配置、系统目录授权、执行审批和恢复材料不入包。源文件中已不存在的附件、外部或失效目录、链接和特殊文件在覆盖清单中如实标记，不能把这些内容算成受到保护。
- 默认与自动导出仅包含当前空间受管项目目录及已登记的受管项目；手动导出可明确选择纳入已登记的外部项目及引用文件夹。扫描不沿符号链接或硬链接读取其他位置。大文件使用有界流式 I/O，读取期间变化则拒绝假快照。小应用通过现有逻辑备份接口获取定义、状态、记录和文件；用户 SQLite 通过在线备份取得已提交 WAL 页面。
- `inspect(from:)` 冻结所选包，校验清单、数据结构、来源空间、文件摘要及冲突，返回该包指纹；UI 展示覆盖、遗漏与替换范围。确认后 `restore` 再核对指纹，拒绝预检后被替换的包。旧包仍可恢复其实际覆盖的部分，并明确缺少的范围。
- 跨空间默认拒绝。只有设置页明确核对来源并确认，才允许将包内内容导入目标空间；普通空间服务和小应用 API 仍不提供跨空间查询或写入。对话工具先用 `backup_inspect` 取得指纹，`backup_restore` 继续逐次硬确认且拒绝跨空间。
- 项目资料恢复到目标空间 `default-chat/<space>/Restored/<restoreID>/` 下的新目录。注册表只接受此受管命名空间，不凭备份中的路径创建外部授权。会话工作区、附件和成果引用按明确映射重建；用户 SQLite 和知识源文件也恢复为新的空间内副本，保留原文件。
- 合并恢复保护目标空间已有邮件投递凭证；导入的账号和 MCP 连接停用，定时任务及知识图谱后台提取暂停，残留运行态改为中断；对话不携带待确认/待提问的执行快照，恢复后自动审核关闭，未完任务标记需检查。凭据和运行范围需在当前设备核对后重新启用。
- 导出、恢复和中断恢复使用跨进程维护租约。空间数据库普通写入、小应用与草稿写入遵守同一租约；邮件网络操作在整个发布周期持有共享租约，恢复不能越过尚未写回的旧邮件请求。
- 修改前持久化原值、目标文件路径及摘要。扩展业务数据库将实际事务后状态先记入私有日志再提交，包含触发器影响的关联表。文件以不覆盖方式发布，技能目录用同卷原子交换；失败依日志还原，无法安全还原时保留材料并明确报告不完整。恢复记录保留完整时间戳精度，兼容旧 ISO 日期。
- 私有恢复日志将成果内容和较大二进制字段写入本目录 `database-blobs/`，仅持有相对范围、摘要和长度，恢复点移动不依赖旧绝对路径。比较当前状态使用临时内容指纹，不重复写出前后快照；指纹禁止作为持久输入。旧内联恢复材料在读取时升级，损坏材料在回退写入前被拒绝。取消通过固定上下文传播到数据库队列和内容 I/O；进入写入后的回滚在持有原维护租约的独立任务中收尾，避免取消同时打断数据保护。
- 写入后核对会话、记忆、账本、扩展数据库、技能、小应用、草稿和文件；通过后先写入提交标记，再整理恢复点。重启遇到已提交记录只收尾，不能误回滚成功恢复。统计或恢复点整理失败会明确提示并保留可重试状态。
- 本空间保留最近七次成功恢复的原值，设置页可逐次确认回退。回退先比较恢复后值，业务数据、文件、小应用或工作区被后续修改则拒绝覆盖；本机统计和可再生索引不阻碍回退，之后新增的统计不会被抹去。任务、作业和成果历史核对本次导入及恢复触发器实际改动的行，保留之后新增的无关运行和版本。恢复点属于本机撤销导入的材料，不是完整历史镜像，也不进入便携备份。
- 请求账本按请求 ID 去重，回滚只删除本次新增回执。自动备份成功时间与轮换按空间独立，仅成功生成并校验包后记录成功，失败保持到期以便重试。

## 知识库结构

知识库在各空间内按「知识库 → 多级文件夹 → 文档 / Wiki 条目」组织，文件夹通过 `parentId` 递归嵌套：

```text
knowledge_bases
  └── knowledge_folders
        ├── knowledge_folders（子目录，可继续嵌套）
        └── knowledge_items
```

条目包含标题、正文、类型、标签、所属库/文件夹和时间；库根也可直接存放条目。`baseId` 为空的条目展示在当前空间的「未分类」，包含后续由工具新增的无归属条目，不依赖首次打开页面时收编。库、文件夹、条目的 `sortOrder` 由独立迁移补齐，同类兄弟节点支持持久化排序；旧 JSON 缺少排序字段时按默认顺序读取。

父目录必须存在并属于同一知识库，保存和移动均拒绝自身/后代环以及同级同名目录。跨库移动只作用于当前空间连接，在单个写事务内更新整棵子树及其条目的库归属；不会修改正文、重建向量或改变稳定 ID。编辑正文和重命名采用列级更新，避免过期表单撤销移动或复活已删条目。批量条目移动先核对全部 ID 和目标，在同一写事务中按选择顺序更新归属及排序；任一条目或目标失效则全部回滚，不调用单条移动循环制造部分成功。库与目录层级由服务显式维护，不依赖这些表之间的外键级联。

删除目录有两种语义：移除目录并把直属内容提升到上一级，或删除整棵子树及其条目。提升时若有同名目录冲突，整个写事务回滚；级联删除不会沿损坏的跨库父引用删掉另一知识库的内容。知识向量等派生索引随条目删除清理。

浏览快照在同一读事务中读取结构和短摘要，正文打开时按 ID 加载，图谱切换时才读取所选条目的完整内容。旧数据中孤立或成环的父引用在派生树中提升为根节点，保证内容可见，不静默改写原始关系。正文中的 `[[条目名]]` 继续用于生成图谱引用边。

## 本地检索

库及文件夹的允许条目在所属空间的数据库内查询。语义扫描分批读取条目标识、段序号、向量和来源摘要。推理完成后，关键词候选、范围复核、语义摘要与模型版本校验在同一读取快照中完成。融合排序和每条目段数限制生效后，才从语义索引读取命中段落的正文。

知识检索由 `KnowledgeRetrievalService` 统一提供，聊天工具、知识列表搜索与知识生成使用同一条通路：

- 文档按自然段/句界切分成有少量重叠的片段，记录条目 ID、片段序号和原文字符偏移。返回命中片段而非固定文档开头。
- 关键词通路沿用 `KnowledgeRanker` 的标题/标签/正文加权和 CJK 二字分词；语义通路独立扫描当前模型版本的有效向量，不能先按关键词预筛语义候选。
- 两路结果通过倒数排名融合（RRF）合并，并限制单文档占用的结果数量。相似度只是候选依据，不保证片段含有答案；阈值需以实际问题校准。
- 检索可限定知识库或文件夹，并控制是否包含子目录；关键词与语义通路使用相同条目范围。语义范围在 SQL 中过滤后才读取向量，按 `(itemId, ordinal)` 游标分批扫描，不用 OFFSET，也不读取范围外向量来计算相似度。无效、已删除或不匹配的目标返回错误，不回退到全空间搜索。只调整目录归属不使内容向量失效，返回路径从当前层级读取。
- 使用本地 Qwen3-Embedding-0.6B GGUF，last-token pooling、L2 归一化、完整 1024 维输出。查询带检索任务指令，文档包含标题、标签与正文片段。
- 权重默认在 `~/Documents/AgRoom/models/Qwen3-Embedding-0.6B/`，设置页可选择或输入 GGUF 文件路径。权重不打进 App；llama.cpp 推理程序和所需运行库内置于 App，按机器架构选择。
- 推理通过短命、串行的本地子进程完成，无网络监听或知识上传。输入文件位于独立的私有临时目录，任务结束清理；取消与超时终止进程，输出不写入日志。每批重新载入权重会有启动开销，后续优化应以实测为据。

`knowledge_embedding_documents` 和 `knowledge_passages` 由独立迁移建立，始终与知识条目位于同一空间库。索引记录源内容摘要与模型/分段/前缀/维度版本；正文、标题或标签修改以及条目删除通过触发器使旧向量失效。后台推理完成后在写事务中重新核对源摘要，防止并发编辑/删除被旧结果覆盖。

App 按当前空间检查新增和变化条目，通过可取消的 `JobCenter` 作业增量建立索引；切换空间或关闭应用视图取消自动作业，已完成文档保留，未完成文档下次续建。自动作业失败不反复重试，设置页提供更新、重建和真实推理测试。重建仅删除派生索引，不改原始知识。

搜索保持只读，模型缺失、未完成索引或推理失败时退回关键词片段检索；不会在 `knowledge_search` 内隐式写库。不同空间可共享只读权重，禁止共享分段、向量或查询缓存。模型文件路径、大小或修改时间变化后旧索引不参与语义召回，并自动建立新版本；更换文件时不要刻意保留原大小和时间戳。

## 同空间统一搜索

`SpaceSearchService` 固定一个空间连接及同空间的技能/应用目录。统一入口按字面关键词检索已保存的对话消息、知识、记忆、智体名称与说明、已安装技能名称/别名/说明、小应用名称与简介、缓存邮件、成果登记资料，以及对话任务、协作报告、定时和作业结果。协作报告包含各子任务摘要、错误和待回答问题；部分运行的结果与失败原因均可检索。不读取智体系统提示词、小应用业务记录、成果二进制、密钥或任意工作区目录，也不触发邮件同步。

数据库通路直接投影既有表，同一会话仅因标题命中时聚合为一条，正文命中仍定位具体消息；邮件同时检索纯文本及缓存 HTML 的可读正文。按标题相关性、日期与类型/ID 游标分页；返回围绕命中的短摘要，正文只在选择结果后读取。技能从实际 `SKILL.md` 目录安全读取，应用沿用已安装目录接口；不使用旧技能数据库副本。目录条数、读取容量、查询时限和结果数量均有上限；取消会清理 SQLite 进度处理器，部分目录不可读会在界面提示。搜索不创建额外内容副本或持久查询缓存，也不新增另一套全文索引；中文 FTS 与规模基准仍是后续评估项。

对话、任务和成果遵守隐藏会话设置；预览与直接打开成果版本时重新检查可见性。预览只提供有限节选；引用前重读所选内容并比较修订指纹，来源变化或删除时不能静默引用旧预览。全局引用通过独立待发草稿接入，聊天引用追加到打开时捕获的会话草稿，保留已有文本与附件；上下文变化时拒绝追加。发送仍由用户明确触发，文件成果沿既有版本预览与附件流程使用，不把登记路径当作文件正文。

## 知识图谱与导入

`KnowledgeGraph` 生成条目、标签与显式引用；同名引用优先在同目录、同库内消歧，仍有歧义时不连线，并支持稳定 UUID 和完整路径引用。UI 负责布局展示。

文件导入由固定空间的 `KnowledgeImportService` 和 `KnowledgeDocumentExtractor` 提供提取预览、提交与来源维护。支持 UTF-8/UTF-16 文本、Markdown、PDF 和 OCR 服务支持的图片；PDF 可指定页范围，自动模式对文字稀少的页面尝试本机 Vision OCR，也可只读文字层或强制 OCR。提取保留页码、正文偏移和识别警告，不把空提取当作成功。旧 `KnowledgeImporter` 保留兼容接口，知识页不再用它直接保存文件。

预览不写知识正文。导入记录、来源与正文版本分别存入同空间的 `knowledge_import_batches`、`knowledge_import_tasks`、`knowledge_sources`、`knowledge_revisions`。文件内容和同批次提取内容参与精确重复检测；已有内容与未变化来源默认跳过。来源更新先比较上次导入版本与当前知识，用户编辑产生冲突时默认保留现有内容；明确采用来源正文前保留当前编辑版本，保留标题、标签及当前目录归属。保存时重新读取本次选择的原始 URL，核对路径身份、内容摘要、提取选项及当前条目摘要；回执、正文、来源和版本在同一事务提交，重复提交不会新增条目，旧预览不能撤销后来编辑。

文件读取限制常规单链接文件、字节上限及读取期间身份和修改时间一致；拒绝应用私有数据和另一空间的专属目录。单文件最多 32 MiB、一次提取最多 200 页/4 MiB 正文，每批最多 50 个文件/16 MiB 正文。文件读取与 OCR 在数据库事务外执行，取消传播到提取和排队写入；已提交内容保留，未完成项记录取消或失败，可显式重新选择及重试。导入只保留提取后的版本与来源引用，不托管原文件；原文件丢失不删除知识和旧版本，不自动监视或覆盖来源。保存后的索引和图谱抽取遵循所属空间设置，导入预览说明已启用的模型抽取可能发送正文片段。

来源、版本和导入回执进入空间备份；文件授权不随备份迁移，恢复后来源必须重新选择才可读取，排队和提取中的任务改为取消，不自动继续。原始文件不因来源引用而自动进入备份，实际文件覆盖以备份清单为准。

`KnowledgeGraphService` 绑定单一空间知识服务，图谱表属于该空间库。语义连线复用当前有效模型的片段向量，按条目聚合并只为新增/变化的条目扫描候选，每个条目保留少量高相似邻居；连线表示「语义相关」，不表示事实。索引作业在向量同步后更新关联索引，查询时再次核对两端源摘要与模型身份，陈旧向量不能构成连线。

实体关系抽取默认关闭，配置保存于空间库。用户在图谱构建页明确选择提供商和模型并启用后，新增/修改的条目按片段增量抽取。自动任务固定发起空间与已选模型，模型配置变化不能静默切到其他提供商；请求计入该空间的知识图谱用量。结果必须为有界 JSON，主体、客体和逐字引文均由宿主校验；每条关系保存原文位置、模型和源摘要，模型输出仅为待核对关系，不宣称事实已验证。

每个条目以内容摘要核对后原子提交，交错编辑/删除不会被旧推理结果覆盖。取消保留已完成条目；失败条目记录本次状态并暂停本空间的自动抽取，用户核对模型配置后可显式重试失败项；自动监控不会连续尝试其他条目继续消耗用量。修改正文、标题或标签立即使旧抽取失效，目录移动不重抽。实体暂按来源文档隔离身份，避免同名人物/项目被自动错误合并。确认、排除和恢复待核对的决定独立于可重建关系保存，同一关系重建后仍遵循已有决定。

图谱配置、关系与核对决定已进入空间逻辑备份；恢复后模型抽取暂停，来源摘要与模型身份继续约束派生结果，源知识的备份边界同上。

## 修改检查

数据相关改动优先验证：旧库迁移、外键、事务回滚、两个空间同 ID 数据不串写、摘要/正文懒加载、损坏输入、原子文件替换、备份恢复到空目录，以及失败后原数据仍可恢复。


## 任务体验元数据

`ChatMessage` 的可选运行状态、完成评估与请求参考记录随消息 JSON 保存，旧消息缺字段仍可读取（缺少完成评估时按「未评估」兼容，不因缺字段丢弃消息）；回答版本同时保存这些元数据。`TaskRunStatus` 在 `succeeded` 之外有 `incomplete`：引擎正常结束但缺少必需产物时落库，界面据此展示阻塞原因而不是「已完成」。完成评估 `TaskCompletionAssessment` 只存稳定 code 与技能名/相对路径/字段名等结构化信息，成品句子由 UI 层按 code 多语言本地化，不随消息存文案。文件成果来自真实写入回执或明确标记的执行期间文件变化观察，部分失败也可有已生成成果；引用元数据跟随消息、备份和守护移交保存，不另建全局隐私缓存。请求记录保存请求时的记忆内容，避免后来修改记忆使历史参考展示失真。

知识引用随回答保存检索到的原文摘录。打开来源时优先呈现该摘录，并可展开当前文档；来源后来编辑或删除仍可阅读已保存的摘录。同一运行重复检索同一片段时采用最后一次候选。旧记录沿原有位置打开当前正文。摘录随消息版本、任务回执与备份保存。

### 成果内容与版本

空间库的 `artifact_edit_receipts` 将受管编辑版本关联到本机写入时的目录身份、对应的恢复点和撤销状态。该表不进入可移植备份。恢复每个文件后，应用在同一事务内更新本地凭证、恢复点和匹配的编程任务文件记录。成果版本保留当时的内容，供用户继续回看。

`TaskArtifactStore` 绑定单一空间连接，`artifact_versions` 保存版本 UUID、逻辑路径、实际路径、工作区、会话、运行、工具调用身份、生成时间、大小和可选内容摘要，内容与来源在同一事务提交。相同调用和实际路径幂等；同工作区内的后续另存、改写、移动和重命名沿逻辑来源递增版本，不用当前磁盘内容冒充旧结果。并发工具使用各自收集器，子引擎仅继承固定空间的存储能力。

受管文本写入在同一成果行保留可选 `beforeContents` 和变更元数据，区分新建、已有空文件和没有基线。已有文件的基线直接取自条件写入校验过的旧字节；成果内容再次核对实际发布的字节，失败不重放写入。前后内容共同计入单次保留预算和历史占用，随成果备份、摘要核验、跨空间受控恢复及明确清理一同处理；旧包缺少基线列仍能恢复。比较只读取同一运行、同工作区和实际路径至所选版本的记录；仅在每次旧摘要都与上次成果一致时聚合，否则降为所选步骤并标记外部修改。预览与审阅不读取磁盘当前文件来替代历史内容，也不从上一个逻辑版本、附件或 Git 提交推断本轮基线。

从版本卡继续修改时，成功导入的 `ChatAttachment` 保存来源版本 UUID 和空间。当前轮只接收本空间且导入成功的引用；成果提交再次在固定数据库中验证版本存在，保存有界 `inputVersionIDs`。该信息表示任务显式附加的输入，不证明模型实际采用了所有输入，也不把多个不同输出强行合并成一条版本线。输入来源跟随引擎快照、子引擎、消息和备份保存；跨空间恢复只在目标空间映射引用。删除早期来源后，后续成果仍可独立使用，输入列表如实显示来源不可用。

读取先以已打开目录描述符校验路径，拒绝链接、硬链接和特殊文件，复制前后核对文件身份与时间戳。单文件超过 `maximumSnapshotBytes` 或本次调用达到 `maximumOperationSnapshotBytes` 时只保留来源、大小及可取得的摘要，并用不同原因标记；不能对这类记录承诺历史预览。版本列表只取有界元数据，选中时才读取内容，核对大小和摘要后在 `<space>/artifact-previews/` 生成带版本号的只读副本。预览目录是私有可再生缓存，不能扩充模型的工作区读取范围。

成果版本纳入逻辑备份，恢复同时核对元数据与二进制摘要，并按明确映射重建来源空间、工作区和路径。已经删除的原文件不影响已保留内容恢复；未保留内容不会在恢复时从任意旧路径补读。恢复点比较和回退本次导入或受恢复触发器改动的版本，保护之后新增的无关版本。删除会话同时删除其版本记录；缓存中的旧副本不能凭过期版本身份重新读取。成果二进制独立于 JSON 元数据容量，逻辑备份仍受整包和各类容量限制，超过限制必须报告导出失败，不能返回遗漏成果内容的成功包。

`TaskArtifactLibrary` 从同一空间版本表按日期与 UUID 游标分页，只取元数据，可按路径字面搜索及保留内容状态筛选；默认遵循隐藏会话设置，也保留没有成功会话回执的成果。历史内容统计使用实际 BLOB 长度，不用原文件大小推断。用户确认移除某份历史副本后，在事务中清除内容并保留 `removedByUser` 来源记录，后续版本序号不回退；原工作文件、其他版本和已有备份不变。多项清理遇到过期选择时整组失败，恢复点回退也不能越过用户随后移除内容的决定。

预览使用独立跨进程文件租约。打开的预览、正在导出和待发送的成果附件持有缓存使用凭证，清理遇到占用则提示先结束使用，不删除仍在排队的附件。发送完成、移除附件或关闭预览后释放凭证。内容清理先提交数据库，再清理对应预览；后半段失败如实报告已移除内容、缓存待重试，不回放原工具。成果库打开时尝试清除已经没有保留版本的旧预览，用户也可显式清空本空间预览缓存；下次从仍保留的内容重新生成。清理沿目录描述符操作，只删除链接本身，不遍历其外部目标。移除历史内容使数据库空间可复用，不承诺数据库文件立即缩小。

`MemoryItem` 的可选 `sourceSessionID` / `sourceMessageID` 由空间库独立迁移补齐，旧备份默认无详细来源、修订号为零，适用于所属空间。编辑和启停推进修订号，迟到的编辑不能复活已删记忆。词项索引从正文重建，备份保存业务记录及提炼进度。

后台作业显式携带所属空间、来源页和可选结果路径。`ProductJobRunStore` 绑定发起空间数据库，在实际工作前保存运行回执，完成后保存有界结果，再发布终态；写入起始回执失败时不执行工作。`JobCenter` 的小型内存和 `<appSupport>/AgRoom/<space>/JobHistory.json` 只服务工具栏，完整历史由 `product_job_runs` 按摘要分页、详情按需读取，不随缓存轮换删除。已有带空间标记的缓存经串行历史队列迁移；首次完成新的受管作业时先迁移再轮换缓存，标准备份也会在取得维护租约前完成迁移，不依赖用户先打开任务中心。旧无空间记录不猜测归属。

活动快照优先于归档摘要，避免重复或提前显示完成；没有运行宿主的旧记录显示需检查，不自动重放。保存失败进入 `awaitingSave`，保留结果并释放执行槽；重试只补写回执、不重做工作。用户确认清除当前空间作业历史时，同一串行队列先落盘再更新内存，不能被迟到的旧缓存迁移复活；本进程活动记录受保护。运行宿主标记供本机核对作业归属，便携备份清除标记并中断活动状态；恢复点回退只还原本次导入的回执，保留之后新增的无关作业。结果较长时保存有界摘录并明确展示。

用户可将没有本进程宿主的旧活动回执或已中断的作业标为已处理。空间库在同一事务中核对身份和状态，将它更新为 `interruptionAcknowledged` 并保留原结果和已知的结束时间。任务中心将这类回执列入「已结束」；旧缓存读取和备份恢复均以持久状态为准。

知识导入的提取预览、失败提取重试和确认保存各自提交到 `JobCenter`，使用导入服务同一空间连接创建的作业回执服务；任务中心可查看进度、阶段结果和取消。预览结果说明仍需确认保存，作业历史只保存数量摘要，不复制知识正文。起始作业回执失败不提取文件；终态回执失败保留已经提交的知识，补写历史不重放提取或保存。取消后的界面按导入任务的实际提交回执收尾，不把已经保存的条目标为未保存；工具栏缓存轮换后仍可从空间历史读取终态。

邮件附件记录 MIME `partID`，旧库由独立迁移补列。按需下载只请求选中的部件，限制传输及解码后大小，保存到 `default-chat/<space>/Mail/<attachment-id>/`，校验文件名与符号链接边界，复用已下载缓存。正文刷新按部件更新元数据并保留已下载路径。草稿自动保存拒绝覆盖投递中、未知或已投递的记录，并丢弃时间早于现有草稿的旧快照。

邮箱签名和常用回复模板使用空间内 `mail.compose.presets` 偏好；整份快照比较防止并发覆盖，默认签名按账号关联，备份校验纯文本内容及引用。撰写窗口固定空间，仅对未保存且正文为空的新草稿应用默认签名；手动插入先预览，替换需明确选择，编辑变化后作废旧预览与撤销。详细行为与适用范围见 [邮箱工作流](17-邮箱工作流.md)。

服务器草稿的显式预览保存、远端读取替换、未决上传及旧版清理通过空间内 `mail_server_drafts` 凭证与账号租约接入；本机自动保存不联网。上传前固定内容和 Message-ID，未知结果只读核对、不自动重放；投递后清理须有独立本机投递凭证，不允许重发。完整备份校验快照、保留目标库已有凭证，恢复后的关联须重新核对。详细契约与行为边界见 [邮箱工作流](17-邮箱工作流.md)。

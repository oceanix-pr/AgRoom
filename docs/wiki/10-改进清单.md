# 当前改进清单

本页只保留尚未完成、仍值得评估的工作。它是规划输入，不是当前实现事实；开始开发前必须重新核对源码、复现条件和优先级。完成的事项直接从本页删除，历史交给 Git。

## P1：数据与运行可靠性

### 编码构建沙盒

完整编译/测试尚不能走自动审核的离线编码沙盒：真实签名试验中，SwiftPM 生成的 manifest 程序受到 macOS quarantine 拒绝；额外执行器和 Gatekeeper 排除实验已撤下。当前 `project_build` 仍为逐次硬确认的宿主入口。后续需验证可执行生成代码的隔离架构，同时覆盖冻结输入、依赖获取、网络/空间边界、进程树取消与资源约束；不能以关闭系统防护替代实现。依赖安装自动审核及可恢复删除/移动仍需独立设计与验证。

### Daemon 完整状态机（部分完成）

已建立持久化状态机（待领取 / 执行中 / 等待确认 / 等待输入 / 结果待提交 / 完成 / 需人工恢复）与副作用执行日志：非只读工具执行前后落 intent/receipt，恢复时有回执则复用结果、只有 intent 则进入「需人工恢复」且不重放。

已补齐：intent 必须先确认落盘才执行工具（写不进去即拒绝执行并置位「日志不可用」，同轮后续副作用也拒绝）；日志身份绑定持久运行、空间、模型轮次、工具与参数 SHA-256，重复 ID 在并发前拒绝，旧长度摘要与未知版本保留现场转人工；轮内工具调用、批标记与挂起队列不再暴露占位结果的虚假干净边界，检查点写失败在后续副作用前停止，子代理挂起后的最终外层结果补 receipt。App 退出以一次性 claim 冻结可移交快照，交接后阻止本地迟到回调和旧世代保存覆盖 Daemon，接管方对旧占位快照失败关闭。仅当交接记录可证明不存在时释放本地 claim；文件状态未知时保留现场并停止本地执行。

SQL 工具的按参数副作用分类已落地：在绑定空间库中预编译并验证绑定的单条语句，实际只读调用免确认且不记副作用 intent，写入与无法证明只读的调用保持确认和日志；PRAGMA 保守确认。分类目前同步预编译，复杂 SQL 在同一调用中多次分类的延迟尚无基准；后续先测量，再考虑有界预算或复用不跨空间的预编译结果，不能削弱失败时保守分类。其他工具的参数级分类仍需逐项核验。

仍未完成：一「执行中」检查点粒度仍以工具批为单位。`AgentTool` 的嵌套引擎虽然继承宿主能力上限，但尚未持久化独立快照与 `OperationJournal`；进程中断时内部工具结果未知，不能自动续跑。需按 [父子恢复设计](design/2026-daemon-nested-agent-recovery.md) 冻结父子运行与工具调用身份、参数摘要、确认身份及完整副作用回执，先为可核实的纯只读子步骤补有限恢复；未知写入结果必须人工核实。二任务中心已能查看未决操作并显式放弃续跑，核实结果后的细粒度安全恢复仍待设计。三真实进程中断、磁盘状态未知、重复启动 Daemon 与最终写回交错仍需端到端故障注入；存储介质不可写时无法保证新人工恢复凭证落盘。

验收重点：工具执行时退出、写回失败、重复启动 daemon、最终写回与进度交错、损坏记录隔离后的会话门禁、人工放弃后解锁，以及有副作用步骤不被盲目重放。

### Daemon 临时运行数据的空间物理隔离（新写入已分区，旧证据待迁移）

新交接记录的完整快照、owner、journal 和隔离证据已按所属 `personal` / `work` 写入独立目录；全局根保留单实例锁，原始 stdout/stderr 不再追加到共享 `daemon.log`。Daemon 读取、状态更新、提交及删除携带记录来源，旧根活跃记录原地收尾；同一空间的旧新双份、归属冲突和无法归属的证据阻止自动领取。记录扫描保持纯读，损坏文件原位保留并按未决证据阻挡；空间页面只展示本空间已归属或分区内未知证据及旧根的中立阻挡信号，旧根无归属证据的查看和放弃移到明确标为全应用的维护窗口。同空间重复凭证只显示人工核对警示。相同运行 ID 分属两空间时独立处理。退出时带随机 token 的 READY relay 只保证新进程当时已准备等待全局锁，不保证随后一定接管或完成任务。

仍未完成：旧 `daemon/` 根目录的历史快照、owner、journal 与隔离证据尚未按空间整组迁移；不能宣称所有持久运行资料已物理分区。Store 已移除无空间参数且返回两空间完整快照的便利读；`OwnershipSnapshot` 和 Supervisor 不再公开合并两空间的会话 ID 集合。空间 UI 使用 `records(in:)` 与当前空间门禁，Daemon 使用携带来源的定位记录，进程协调只读取待执行/阻挡布尔值。旧格式损坏记录、双份/半份文件、复制中断及旧 Daemon 与新 App 并存仍需端到端故障注入和受控清理。无法可信归属的旧证据不得按当前 UI 空间、文件名或 UUID 猜测迁移，需保留人工核实边界；存储介质不可读写时无法保证新增恢复凭证。详见 [Daemon 空间分区迁移设计](design/2026-daemon-space-storage-migration.md)。

接口收口的剩余 P2：App 当前取得的全局 `OwnershipSnapshot` 仍包含按空间键控的两空间会话 ID 映射，现有调用只取当前空间集合或无身份的进程布尔值。后续给空间 UI 提供只含本空间集合和全局中立阻挡信号的投影接口，减少未来误用面；同步发送门禁必须继续覆盖跨分区身份冲突，不能退化为仅等 Supervisor 轮询。

文件系统剩余边界：Store 的扫描、写入、删除、人工放弃与 Journal 已改用从固定根逐段打开的目录描述符和身份复核，任务中心向 Finder 交付经重新核对的私密副本。同一用户的其他不服锁进程仍可在最终文件名摘要与删除/移动之间替换该文件；普通同用户目录权限也不能阻止恶意进程换掉 Finder 副本。需通过旧版写者停机门禁处理跨版本并发，并明确此处防的是应用内部换路交错，不宣称抵御任意同 UID 对抗进程。私密查看副本目前由系统临时目录生命周期回收；主动清理时机与避免误删正在查看的副本仍需设计。


纯读的旧根递归盘点器已落地，可列出旧凭证、日志、孤儿 journal、人工放弃证据及未知文件；它只做文件级身份佐证。新增的单空间数据库身份探针在已健康挂载的所属库中核对会话、唯一助手消息、运行身份、恢复代际和终态；纯计划器把盘点正文摘要与探针期望绑定，仅给出预检候选或延后原因，不打开另一空间库，也不搬迁。旧日志或未知证据会使整次预检保守延后。新版 Store 的创建、更新、隔离、删除和人工放弃已接入固定 `store.lock` 的短时跨进程互斥；人工放弃按 `daemon.lock` 再 `store.lock` 的顺序取得锁，数据库异步操作期间不持文件锁，返回后重新核对证据身份。目录和日志文件拒绝符号链接，删除前验证来源空间目录，异常时保留原件。自动迁移前仍须完成旧版写者停机证明、持久迁移标记、发布前空间库重验与中断对账；旧版进程不识别新锁，只能在可证明旧进程已停止的升级窗口迁移。现有人工放弃会把私有字节留在旧根 `quarantine/abandoned/`，不能把解除续跑阻挡当作物理迁净。真实两进程故障注入和递归根目录审计通过前，不开启自动整组搬迁。

仍未完成：

- C 档明确不对话化：API Key 与 Provider 配置、空间切换、系统权限授予、覆盖式恢复；对话只做提示或深链跳转。

- 每个新增动作需要「对话可达」回归：按动作性质核验确认卡或系统选择器、轨迹、结果落盘，并覆盖两空间隔离与守护进程排除。

### 邮箱正文与列表的选中竞态（已落地，保留回归要求）

选中时分配自增请求令牌、写回前核对「令牌未过期且选中项仍是本封」，加载任务可取消；文件夹与列表刷新按世代号丢弃过期结果。回归要求：快速连续切换邮件与文件夹后，详情正文始终与标题一致；慢请求返回不覆盖新选择。

### 邮箱身份与同步规模

远端删除与标记对账、离线标记待回写、精确 UID 历史回填、覆盖信息与重建缓存已落地，契约见 [05](05-数据模型存储与知识库.md) 和 [07](07-UI层.md)。仍需评估大账号全 UID/标记集合查询的成本，以及服务器同时缺失 `UIDVALIDITY` 和 `Message-ID` 时的保守身份失效策略；不能把无法证明的身份视为可靠。

### 邮箱操作的可取消与可观测

已补齐：按 UID 分批拉取（批间检查取消、逐批落库）、逐文件夹进度上报、界面取消入口、收件箱优先，以及按 `BODYSTRUCTURE` 只取文本部件（附件不再下载）并设单封正文上限。同步仍顺序遍历全部可选文件夹（含垃圾箱、归档）。

仍可继续：批次大小目前固定（`MailSyncService.syncBatchSize`），未按网络状况自适应；正文超限只有提示，没有分段拉取。

验收重点：大文件夹同步过程中可以取消且不残留半写状态；取消后再次同步能正确续传。

### 邮箱连接生命周期与并发闸门

账号闸门已覆盖当前进程的网络操作生命周期，后台同步在批间让出，排队可以取消。各细粒度操作仍新建 TCP + TLS + 登录连接；跨进程由数据库删除保护兜底，但没有跨进程的网络单飞。只读操作的瞬时错误恢复和连接池仍需基准评估。

（超时已按操作分级落在 `MailTimeoutBudget` + `MailDeadline`：预算须严格小于上游会话自带的 120 秒，超时主动断链以解开阻塞中的读，发信超时按「结果未知」处理。上游把所有会话错误抹成同一描述的问题，只在被本层覆盖的操作上得到改善。）

仍可评估跨进程网络单飞与连接复用（不违反「Hub 不缓存空间内服务」）、只读操作的上限重试与退避，以及未被本层覆盖的上游超时语义。

验收重点：模拟服务器不响应时操作能在预算内失败并给出可操作提示；并发触发同步不会产生重复连接与交叉写；瞬时失败能自动重试且不重放有副作用的步骤。

### 邮箱发信的确认强度与批量上限

`mail_send` 已逐次硬确认、不接受本轮整工具授权，并限制单封收件人数量。仍可评估单轮总发信次数的额外上限；每封真实投递均须保持明确确认。

验收重点：注入场景下即使已授权一次，也不会在同一轮内连续投递多封或群发；用户对每次真实投递都有明确确认。

## P2：规模增长后的性能

### 邮箱正文按部件拉取（已落地，保留回归要求）

已改为 `BODYSTRUCTURE` 取部件树 → 只取 `BODY.PEEK[HEADER]` 与文本部件 → 拼装等价 MIME 解析；附件大小取自结构里的 octets；`MailSyncService.bodyByteLimit` 为单封上限，超限抛 `MailProtocolError.messageTooLarge` 并给出可操作提示；服务器不返回 `BODYSTRUCTURE` 时回落到整封拉取但仍受上限约束。

仍可继续：超大正文目前直接拒绝，没有分段拉取。

回归要求：打开带大附件的邮件不产生附件流量；附件大小与实际一致；超大正文不会一次性占满内存。

### 邮箱列表分页与本地检索

列表已支持游标分页与「加载更多」，检索通配符转义和正文缓存上限也已实现。`mail_search` 仍使用 `LIKE '%关键词%'`，规模扩大后需要评估全文索引，避免与列表读取互相阻塞。

需要继续：本地检索接入 FTS5（与「统一索引搜索」合并评估，避免两套索引），测量分页与缓存淘汰在大账号下的表现。

验收重点：超过一屏的文件夹能连续加载且内存稳定；检索耗时随规模的增长可接受；长期使用后数据库体积不无限增长。

### 邮箱写路径批量化

同步落库是逐行「先查再改/插」，级联删除也是逐封循环执行语句；同步已按 UID 窗口拆批提交，但每批仍有多次 SQL 往返。空间库是 `DatabaseQueue`（单连接，读写全串行），App 与 Daemon 又打开同一个库文件。`SpaceStore.openDatabase` 已配置有限 busy timeout，等待超过预算仍可能抛 `SQLITE_BUSY`；长事务和同连接读写排队仍值得测量。

需要补齐：批量 upsert、级联删除改为集合操作，测量批次事务时长与锁等待，再决定是否调整退避或引入 `DatabasePool`。

验收重点：同步大文件夹期间界面读取不被长时间阻塞；两个进程并发写入不出现直接失败。

### 统一索引搜索

聊天列表已有输入防抖、SQL 候选 ID 查询及按需分页；独立的同空间统一入口已直接检索现有数据源并按需读取预览，尚未建立统一全文索引。下一步用基准评估中文 FTS5、混合来源的相关性及大规模正文扫描，保持查询时限和取消能力，避免与邮箱、知识另建重复索引。

### 技能快照缓存

组装点已使用 `SkillStore.listSnapshot()` 在后台扫描，避免主线程逐个读取 SKILL.md；写入也会使该实例的快照失效。不过组装点每轮新建 `SkillStore`，实例缓存通常不能跨轮复用，磁盘扫描成本仍在。下一步先量化技能数增长时的扫描耗时，再设计按空间/目录身份复用且由写事件或目录变化失效的只读摘要快照；不得把空间内服务缓存进 `Hub`，正文仍按需加载。

### 知识检索索引

数据规模扩大后，先用支持中文的本地索引召回候选，再沿用确定性权重精排。列表读取摘要，过期查询可取消。引入方案不能默认上传知识正文。

### 浏览器资源边界

标签已有软预算，自动回收仅处理空白页，已加载页面与执行中操作受保护。后续补齐批量关闭、下载保护、可恢复的空闲休眠与内存硬边界；不能用自动关闭页面丢弃未保存表单。浏览器截图仍需多模态结果接线与自动清理，页面读取仍需定向提取、分页与增量快照；会话级操作租约、下载中心、标签恢复和知识保存预览也尚未接入。

### 消息定位和长文渲染

为高频流式写回维护消息 ID 索引，避免遍历全部会话和消息。Markdown 已支持连续追加时交付已完成的解析快照、按块更新 TextKit 后缀、按页显示表格以及复用同一文档内的富资源。下一步以真实长会话测量增量到正文可见的延迟、滚动主线程耗时和峰值内存，再评估更细的增量解析。脚注、提示块、高亮与查找见 [Markdown 渲染增强设计](../design/2026-markdown-rendering-design.md)。

### 低优先级数据优化

根据实际数据量评估 `DatabasePool` 读并发、`SkillUsageLog` 增量存储和历史上下文数组构造。没有基准证据时不增加复杂度。

## P2：产品体验

### 领域错误与可操作反馈

文件、知识、记忆、智体、协作任务、Provider、音频与 OCR 的主要失败入口已改用多语言领域文案；文件夹读取失败会显示重试入口，不再伪装成空文件夹。记忆新增保存失败保留输入。脚本权限页的规则读取、撤销、清空与任务文件恢复不再直显底层错误或私有路径；保留失败状态、原文件及安全的修复/重试提示。权限拒绝、来源丢失、数据库忙、网络超时、Provider 鉴权与限流已有定向夹具，未知错误不把路径或外部响应作为主提示。仍需逐页收敛原生小应用、数据库、对话及其他入口中的底层说明，保留脱敏诊断类型/码，并验证各页的重试、重新选择或设置动作可真正完成恢复。

### 窄窗与较大界面文字

邮箱列表和详情的主要元信息已接入共享字体角色；仍需在多语言、较大界面文字与窄栏组合下复核发件人/日期、详情工具行、附件动作与长标题的截断和可访问性。以原生渲染和键盘操作为验收，不仅检查字号数值。

### 暗色界面的 HTML 邮件阅读区

## 明确不做的方向

当前产品定位为个人使用，暂不建设技能市场、评分评论、公共技能仓库和面向 SaaS 合规展示的功能。若产品定位改变，再单独评估，而不是把这些项目长期留在活跃 backlog。

## 基准建议

性能工作使用固定构建和固定数据集，记录 p50/p95、峰值内存、主线程时间和数据库读取量：

- 会话搜索：大量会话与长正文，连续输入查询。
- 技能组装：不同技能数量下的冷启动和连续多轮发送。
- 知识检索：不同条目规模和固定中英文查询集。
- 浏览器：逐步增加标签并统计 App 与 WebContent 总资源。
- 流式长文：固定速率回放不同段落数量，检查解析量与格式正确性。
- 邮箱同步：固定规模账号（如单文件夹数万封）下的首次同步与增量同步耗时、峰值内存、连接次数与写事务时长；打开带大附件邮件时的实际下载字节数。

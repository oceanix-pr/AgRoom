# 编程工作流

对话使用统一入口，用户不再选择聊天或编码。每轮由本地意图分类建议内部工作流，再解析并冻结该轮的模型参数与工具定义；同一会话可以连续处理代码、邮件与普通问答。内部工作流不扩大空间、工作区、执行或确认权限，旧会话的 mode 字段仅保留为短续问提示和历史兼容。

## 项目理解

- `project_inspect` 返回项目文件概览、清单位置和从项目根到目标目录的 `AGENTS.md`。根规则在装配编码引擎时加载；进入子目录前应再次检查其规则。规则按目录生效，不能覆盖用户请求、空间边界或确认策略。
- 概览中的规则是有界片段；`next_instruction` 表示还有规则页，`truncated` 表示正文需要通过文件工具继续读取。不会把省略内容当作已经读过。
- `repo_search` 支持文件路径和单行字面量正文检索，返回路径、命中行列与完整文件 SHA-256。`context_before` / `context_after` 各可带回相邻行，替代 `grep -A/-B/-C`；超长行的片段围绕命中位置，并带可直接传给 `files_read` 的 `read_cursor`。已知文件时应指定 `path`，避免每次扫描全项目。遍历遵循项目内各级 `.gitignore` 的常用通配、否定与目录规则，不读取宿主全局 Git 配置；依赖目录、构建缓存、符号链接和其他空间的专属目录跳过。单文件和单次检索总扫描量均有上限；`truncated` / `skipped_files` 不能被解释为全仓库无匹配。
- `files_read_range` 按一基行号读取 UTF-8 文本，并返回完整文件摘要；超出结果预算时通过 `next_line` 继续。首个读取行过长时返回有界片段、`line_truncated` 与供 `files_read` 使用的 `next_cursor`，无需从文件头反复翻页。普通对话的检索和读取按块处理最多 32 MiB 的单文件，输出仍有独立字节预算；编辑上限为每文件 16 MiB。
- 目录清单与大文本读取都从固定目录描述符操作，并在返回前重验完整目录链。清单只返回固定目录 inode 中的名称，项目相对路径不解析可变子目录链接；正文另检查普通文件、UTF-8、NUL 与上限，完整计算原始字节摘要。文件变化则丢弃本次局部结果；取消会传递到后台扫描。它不等同于对抗任意同用户恶意进程的文件系统快照。
- `repo_changes` 在仓库元数据位于当前工作区内时读取 Git 的 `status --short`、未暂存或已暂存的 `diff`，可按仓库内现有路径缩小差异。它只生成固定的 Git 参数，确认前与执行时均要求 Shell 的只读判定通过，实际执行仍由只读离线沙箱约束。若 `.git` 位于绑定工作区之外，需要将包含仓库的目录绑定为工作区；工具不会自动向父目录扩权。
- 新工具只读取本轮绑定的工作区，检查目录身份与路径组件。目录被替换后失败，不跟随新位置。团队 Worker 可继承同一只读检索能力，不因此获得 Shell 或构建权限。
- 统一对话优先用这些工具完成等价的文件枚举、字面检索和按行读取，减少不必要的 Shell 调用与确认；其他显式引用文件夹使用已有受管文件工具。定时任务不因普通工具面变化增加能力，仍使用独立白名单。

自动工作流保留当前约束下的完整可调用能力：编程请求直接披露开发核心工具，其他领域按意图披露有界定义，其余能力仍可通过 `tools_search` / `tools_invoke` 发现。不会因为初次判为编程就移除邮件等能力。模型缺失或分类不确定时保留完整工具回退；明确的软件修复请求和同会话的短续问有保守的宿主兜底。技能声明继续与本轮能力取交集。

自动对话在有绑定工作区时注册编程任务和批量编辑工具。编程请求启动时加载根项目规则与任务状态；其他请求的简短工程指引随工程工具按需披露，普通问答不扫描项目版本或创建任务记录。即使分类遗漏，发现工程工具时也会返回对应指引；显式使用编程任务工具、经批准的源码/工程清单编辑或 `project_build` 会按需激活同一编程记录。检查状态仍由实际文件版本和检查回执决定；普通文档写入不会仅因存在这个运行时而被标为代码未验证。

`repo_search` 可用 `queries` 批量查询多个字面量，替代多次重复扫描；与旧 `query` 二选一。`include` / `exclude` 按项目相对路径使用 `*`、`**`、`?` 过滤。`output=paths` 只返回命中文件，`output=count` 不返回正文，统计每个查询的匹配行数和文件数，多个命中在同一行仅计一行；路径模式则统计匹配路径。`query_indices` 对应输入数组的零基下标。扫描上限、跳过或尚未扫描的文件会使 `count_is_exact=false`，不能把有界计数当成全仓库结论。

## Swift 符号导航

`repo_symbols(action=definitions|references|read_symbol)` 默认使用文本后端，明确返回字面量候选，不能当作已解析的定义或引用。显式选择 `backend=sourcekit_lsp` 时，使用当前 Xcode 工具链及已有项目构建设置/索引；位置采用一基行号与 UTF-16 列号。`read_symbol` 按唯一名称或包含位置的最小符号返回有界源码、行范围和完整文件摘要，较大符号继续用 `files_read_range`。输入限 UTF-8 Swift 源文件，返回路径重新经过当前仓库的目录身份、链接与空间边界检查；查询期间源文件变化则拒绝使用旧结果。

真实项目初始化可能执行 SwiftPM 清单或构建服务器，故每次语义查询是显式宿主操作，继续要求完全权限与新的硬确认；文本后端不启动进程。后台索引关闭，不自动批准信任、编辑或服务端命令。现有索引的新鲜度与覆盖范围保留未知，空引用不能证明不存在；语言服务不可用、符号不唯一时返回明确标注的文本回退，取消仍是取消。每次查询有超时、输出和帧大小限制，结束时关闭进程，临时 HOME/缓存位于所属空间且不复用用户密钥环境；没有 Hub 服务缓存。该实现不提供索引构建、重命名或长期 LSP 会话。配置依据 [SourceKit-LSP 选项](https://github.com/swiftlang/sourcekit-lsp/blob/main/Sources/SKOptions/SourceKitLSPOptions.swift)。

## 任务连续性

`CodingTaskStore` 绑定单一空间数据库。`coding_tasks` 以会话与工作区设备/inode/规范路径的摘要为键，保存有界用户请求、计划、验收条件、已确认发现、后续步骤、文件基线和检查回执。换空间、换目录或同路径目录被替换不会复用旧任务。

- `coding_task_update` 仅更新引擎内部工作笔记，不能修改用户指令、执行授权、文件证据或验证状态；性质与运行轨迹/进度记账相同。
- `required_checks` 可追加本任务需要的 `project_build` 参数（不含 `timeout_seconds`），用于记录项目规则与受影响目标要求的检查。要求不能由后续笔记清空，也不授予执行权限或声明检查通过。需要更换任务检查范围时另建编码任务。
- `coding_task_read` 可分页读取各个分节和保存的请求。自动注入仅提供有限摘要，原始对话仍是完整请求的事实源。
- 编码历史按实际文本 token 估算预算；不再因单条文本越过固定字符阈值而只保留极短开头。必须省略时保留首尾并明确说明。
- 工具结果压缩保留有界首尾，不假设被省略的内容已经被模型记住。源码和构建日志需要时重新读取。
- 源码工作集记录实际按行读取的路径、完整摘要、行范围和调用 ID。同一摘要下重叠且一致的完整行可无损合并，原调用/结果 ID 仍配对；不同版本、截断行和签名续传不做此合并。模型收到的是运行内证据整理，轨迹保留原始回执。
- 编码上下文在软阈值触发检查点，携带任务摘要和有界证据目录。目录明确标记正文是否仍在当前上下文；正文被压缩后需用 `files_read_range` 重新取得。已尝试的受管编辑会使对应旧证据失效，后续新摘要会标记被替代版本；读取回执始终不证明磁盘此刻未变，写入仍需当前摘要核验。符号读取也可加入工作集。普通签名前缀保留原样；受支持的 Responses 原生压缩按 [04](04-LLM提供商与消息协议.md) 保留用户要求、完整规范输出与真实检查点。
- 数据库事务内核对当前 run，按需激活还需匹配组装时观察到的旧记录归属；迟到笔记、旧运行激活和文件记账不能覆盖新一轮或重建已删除记录。主动移交携带本轮已解析工作流、工具面与编程记账是否激活，沿用原 run 的任务记录与最初输入身份；后台不重新分类。
- 这是任务上下文恢复，不表示应用重启后会自动重放写入或重新批准挂起操作。删除会话同时清理其编码任务记录。内部编码记账不纳入普通内容备份。

## 编辑与审阅

`files_edit` 继续提供单文件精确替换。`files_apply_changes` 对多个已有 UTF-8 文件执行批量替换：

1. 获取路径租约，校验全部文件摘要、唯一匹配和目标路径。
2. 先保存全部恢复点，再逐文件条件原子写入。
3. 中途失败按逆序尝试恢复已写文件；用户随后改过的文件不覆盖，保留恢复记录并明确报告需要人工处理。

单文件编辑与单文件恢复共用 16 MiB 上限，批量编辑按各文件旧/新较大值累计最多 32 MiB，编码任务原始基线总量也限 32 MiB；超限在写前明确停止，不引导模型用 Shell 绕过恢复保护。大文件的小改动先剥离相同前后文，再对局部生成准确 diff；无法在预算内比较的巨大变更不虚报增删行数。

这是可恢复批量编辑，不是跨文件系统事务。在任务写范围有效、已绑定恢复点存储，且每个文件都有预期 SHA-256 时，确定性规则可直接批准；否则沿用人工确认。执行时仍核对文件内容、保存恢复点，并受空间、会话、技能和子任务写范围交集约束。主文件夹和已授权引用文件夹均可编辑。新的恢复点同时保存文件所在根目录的设备号与 inode，目录被替换后即使路径和内容相同也不能写回。创建新文件继续使用 `files_write`。

文件变更入口在回答下方和任务详情的「已编辑」卡片中。点击「撤销」并确认后，应用核对本轮所有文件的工作区身份、版本链和当前内容，已有文件恢复到本轮首次编辑前，新建文件按实际落盘路径移除。版本链中断或预检发现后续修改时，整组停止。执行中遇到错误会显示已完成数量及待核对的路径，重试会跳过已撤销的文件。历史差异仍可回看。缺少本机写入凭证的旧结果与导入结果只供审阅。

## 构建与验证

`project_build` 支持 Swift 构建/测试、Xcode 项目或 workspace 构建/测试，以及定向测试。固定 argv 不能隔离项目脚本；宿主执行继续要求扩展访问与逐次硬确认，不支持自动审核或沙箱失败回退。

构建返回退出状态、结构化诊断、有界日志路径与输入版本核验。检查前后计算可遍历项目文件的摘要；依赖/缓存目录按检索规则排除。输入存在符号链接、扫描超限或不可读时，不能宣称版本已核验。这是受管项目输入的证据，不代表锁定了宿主工具链、网络依赖或所有构建环境。

完成评估区分：

| 状态 | 依据 |
|---|---|
| 未评估 | 本轮没有观察到源码变化或检查行为 |
| 已修改、未验证 | 没有成功检查，或源码版本已变化/无法核验 |
| 检查未通过 | 实际构建或测试失败 |
| 记录的检查通过 | 实际检查成功，检查前后及收尾时的项目摘要一致 |

检查通过只证明记录的检查，不自动证明整个功能满足语义需求。已有技能产物失败不能被构建通过覆盖。状态随消息、回答版本和后台快照保存；使用历史检查时须重新核对当前项目版本。

检查台账按规范目录、动作、项目/workspace、scheme、configuration 和测试筛选器区分检查；超时与缓存位置不改变检查身份。每种检查保留最新真实回执，所有已尝试及声明必需的检查都要在最终输入版本通过。一次 build 成功不能覆盖 test 失败，另一筛选器通过也不能替代原失败检查。台账有大小上限，不通过淘汰失败记录制造通过状态。旧任务中的单份回执仍可读取；缺少检查身份的旧失败不会被推断成另一检查已修复。

结构化诊断按严重级别与根因消息聚合，错误优先保留；重复次数和有限关联位置可追溯到完整日志。仅归一化测试耗时，不抹掉编译器消息中有意义的数字。任务保留有界失败尝试历史，比较同一检查的错误增减；只有前后输入均已核验且完全一致时才标记重复失败。最新检查通过后，旧失败仍可分页读取并明确标为历史，不影响当前版本的真实通过回执。模型摘要不能写入或替代这些记录。

## 验证与后续

回归使用临时项目覆盖规范作用域、忽略规则、中文大文件、越界/链接、任务重建、跨空间隔离、迟到更新、批量失败恢复、用户交错修改和检查失效。工具循环回放包含检索、计划、编辑、自动审核与逐次审批、检查和最终结果，不访问远端模型；真实宿主构建沿用构建文档中的显式测试开关。

`RepositorySymbolTests` 默认使用协议与权限夹具；显式设置 `AGROOM_TEST_SOURCEKIT_LSP=1` 可在本地 Xcode 工具链上检查无清单合成文件的真实符号读取，不调用模型。该检查不证明任意业务项目的跨模块索引完整。

`CodingProviderEvaluationTests` 提供版本化合成仓库的真实模型评测入口，包含边界修复、跨文件变更、Unicode、API 改名、大仓库定位与不可信仓库指令。普通测试仅校验独立验收器能拒绝原始缺陷并接受已知修复。模型结束后才在其工作区外创建验收程序，同时检查用户原有修改与指定保护文件；生产工具工厂、权限守卫和系统提示构造共用，评测白名单仅开放合成项目的文件、检索和任务能力，不开放模型侧宿主构建、Shell 或外发。独立编译采用整模块方式并继承声明的 Xcode 工具链。

同时显式设置 `AGROOM_TEST_CODING_PROVIDER=1` 与 `AGROOM_TEST_CODING_HOST_CHECKS=1` 并筛选该 suite，才会读取已配置 Provider 的 Keychain 凭据、调用付费模型并在宿主编译/执行其合成源码；第二个开关是对这项宿主执行的明确同意，不表示产品已提供隔离构建。可用 `AGROOM_CODING_EVAL_PROVIDER_ID` 固定提供商，`AGROOM_CODING_EVAL_TASKS` 选择逗号分隔的任务，`AGROOM_CODING_EVAL_OUTPUT` 指定报告目录。`AGROOM_CODING_EVAL_VARIANT=baseline|optimized` 比较完整披露/组合提示与按需披露/分段提示/缓存/原生压缩；生成参数与任务预算保持相同。`AGROOM_CODING_EVAL_REPEATS` 控制有界重复次数，同一任务复用目录和工具定义但重置合成文件。

报告保存任务版本、输入/验收摘要、冻结配置、预算、工具面、通过情况、错误完成、耗时、脚本审批、失败调用和每次无正文的 HTTP 用量回执。未知用量和缓存读/写保留缺失计数；首轮与重复轮都不声称已控制远端冷暖状态，命中看真实回执。`python3 scripts/summarize-coding-eval.py 报告目录` 按相同任务版本、夹具、提供商、配置、预算、工具面和阶段分组，成功任务平均 Token 的分子计入失败运行；用量不全或没有成功任务时不输出该指标。未固定费率时不推算货币成本，不能用协议回放宣称真实模型成功率或节省比例。

语义索引构建/新鲜度证明、重命名、可查询的长期开发进程、隔离构建执行器、独立 worktree Worker 与补丁集成仍属后续架构扩展。现有团队验证者不执行构建，不能把模型审查替代真实测试。

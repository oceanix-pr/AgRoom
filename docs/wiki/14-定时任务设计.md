# 定时任务设计（P0a 已实现）

> 状态：已实现 App 内只读 Agent 定时、对话草拟与原生预览确认、任务预算、变化提醒和结果后续操作。通知型定时、App 退出后后台执行、无人值守写入、团队及事件触发仍属后续阶段。本文记录当前契约；修改时还需核对 [02-调度引擎](02-调度引擎.md)、[03-工具系统](03-工具系统.md)、[07-UI层](07-UI层.md) 与 [12-权限模式](12-权限模式.md)。

## 产品边界

定时复用 `EngineAssembly`、`DispatcherEngine` 与 `ExecutionBudgetLedger`，由触发器、空间内定义和单次运行记录构成，不创建第二个执行引擎。

- 仅 App 进程运行时执行。关闭窗口仍可驻留菜单栏；⌘Q、注销、关机后不执行。系统睡眠期间不执行，唤醒后按错过规则处理，不承诺准点。
- 无人值守只开放 `readOnly.v1` 白名单。任何确认或提问立即失败关闭，不自动批准，不继承对话的扩展访问或写权限。
- 定义、运行、用量及比较基线归所属空间。运行捕获固定空间和定义快照，不随当前页面或后来编辑变化；`Hub` 从指定连接现建服务。
- 总开关默认关闭。纯草拟不启用调度；保存定义与实际运行都具有明确的用户入口。
- 不把现有 daemon 改成常驻调度器，也不注册后台 helper。

## 调度与生命周期

```text
ScheduledTaskCenter（App/UI）
  → 每 30 秒及启动、唤醒、时钟/时区变化、激活、设置变化扫描
  → ScheduleCalculator（Core 纯规则判定）
  → 所属空间 ScheduledTaskStore / ScheduledRunStore
  → ScheduledRunner → EngineAssembly / DispatcherEngine
  → 终态事务提交 → 页面、任务中心及通知
```

App 持有后台活动声明以降低 App Nap 延迟，不阻止系统睡眠。数据库查询通过所属队列异步执行；扫描预约、手动运行和活动执行共用全局单飞，最多同时一个定时 Agent。对话仍可独立执行，Provider 并发闸门继续生效。

运行先写 `pending`，再写 `running`，成功后才启动引擎。`(taskID, scheduledFor)` 唯一索引防同一计划时刻重复领取；手动运行的 `scheduledFor` 为空，不改变下一次计划时间。启动对账把残留活动记录标记 `interrupted`，不自动重放。

### 规则与错过

| 规则 | 参数与语义 |
|---|---|
| 一次 | 未来绝对时间，触发后停用并保留历史 |
| 每天 | 固定时区中的时、分 |
| 每周 | ISO 星期集合与时、分 |
| 间隔 | 锚点起每 5 至 1440 分钟，不按上次完成时间计算 |

时区为可编辑的有效 IANA 标识，不随系统时区漂移。夏令时不存在的本地时间顺延至有效时间，重复时刻取较早一次。校验拒绝非法日期、超大间隔和空星期集合。

- App 原已启用但未运行，或睡眠后到期：在任务宽限窗口内最多补跑一次；超过宽限写 `missed` 并推进，绝不逐次回放。
- 定义或总开关停用期间不判定、不写错过记录；明确重新启用时从现在重算。已过期的一次任务保持停用，不补跑停用期间的时间。
- 到期时已有活动运行，写 `skipped/overlap`，不排队。停用只阻止下一次触发；当前执行需显式停止。
- 编辑只影响之后的执行；删除先取消运行再移除定义，历史保留，迟到写回不能复活定义。同 ID 的另一空间操作不能停止当前运行。

## 数据契约

两张表位于各自空间数据库，`v1_scheduled_tasks`、`v1_scheduled_runs` 建表，`v2_scheduled_experience` 为旧库补可选 JSON 列。

| 表 | 内容 |
|---|---|
| `scheduled_tasks` | ID、名称、启停、指令、`scheduleJSON`、`profileVersion`、`notificationJSON`、`optionsJSON`、创建/更新时间、下次时间及最近状态 |
| `scheduled_runs` | 独立运行 ID、任务 ID/名称快照、触发方式与计划时间、状态、起止时间、输出/摘要、工具名与调用数、输入/输出 Token、错误、耗时及 `experienceJSON` |

`optionsJSON` 保存 Token/工具次数/时间上限、变化提醒开关、比较标准和定义修订身份；旧记录缺列或空值使用安全默认，损坏的非空选项拒绝运行。能力面由代码内 `profileVersion` 决定，数据库不能指定任意工具。

`experienceJSON` 保存本次预算、完整用量是否已报告、预算记账值、实际 Provider/模型身份、摘录标记、定义指纹、比较值/状态和前一基线运行 ID；之后修改定义不改变这些事实。旧运行缺少信息按未知展示。

- 新建使用拒绝重复 ID 的 `insert`；编辑 `update` 保留最近运行字段，定义删除后不复活。启停在事务内重新读取定义、校验并计算下次时间。
- `ScheduledRunStore.finish` 在同一事务内保存终态、比较状态及定义的最近运行字段，不覆盖定义。重复提交同一回执幂等，冲突回执拒绝。
- 运行长期保留，不随新运行自动裁剪。统一任务中心提供分页、按需详情和显式历史清理；清理不碰活动记录。
- 完整空间备份包含定义、历史及新增 JSON 信息；恢复后定义暂停，活动记录中断，不凭导入自动执行。恢复点与回滚沿用完整备份契约。

## 对话草拟与确认

普通完整对话工具面注册 `schedule_draft`。它只根据参数产生可恢复的 JSON 回执，不读取空间数据库、不落定义、不启用、不执行；因此声明只读、免工具确认。模型提示必须说明尚未安排，用户需打开会话卡片的预览再明确保存。工具在定时白名单及显式受限装配中不存在，不能递归安排任务。

草稿包括名称、完整指令、所属空间、规则/时区、预算和变化标准。工具严格校验类型、范围、规则对应字段和未来时间；回执限制在普通会话轨迹完整内容容量内，过大时返回缩短指令的可操作失败，不留下无法打开的卡片。回执保存在原有消息轨迹，可重启后恢复预览。

原生编辑器展示并允许调整指令、规则、时区、启停、预算、通知和变化标准；固定可见区域显示空间、下次时间、预算和 App 必须运行的限制，总开关关闭时明确提示。保存再校验当前空间、定义和目标时间，取消不创建任务。再次打开已保存草稿定位现有任务，不用旧草稿覆盖后来编辑。

目前没有 `schedule_create/update/delete/run_now` 模型工具；创建和修改的有状态操作由原生页面完成。

## 无人值守权限

`readOnly.v1` 允许 `get_current_time`、`memory_search`、`knowledge_search`、`files_list`、`files_read`、`web_search`、`web_fetch`、`reminders_list`、`mail_accounts_list`、`mail_folders_list`、`mail_list`、`mail_read`、`mail_search`。

- 同时使用工具名白名单与 `.readOnly`，关闭自动审核、工作区自动批准及团队写；新增工具不会因排除清单遗漏而默认暴露。
- Shell、Python、文件写删、邮件发送/删除/标记/草稿、提醒写、任意 SQL、技能脚本、浏览器、团队、提问、通知工具和定时草拟不进入无人值守能力面。
- 文件只读范围继承装配时当前空间绑定工作区的主目录及显式引用目录；其他工作区和另一空间目录不自动开放。定时不扩大授权。
- `mail_read` 按需正文拉取只会写内部缓存，仍计入网络时限和失败记录，不能被当成无成本操作。
- 外部网页、文件、邮件、知识和记忆沿用数据边界与提示注入防护。系统提示用英文，正文语言遵从 Agent 回复语言；计划时刻与任务时区明确传入。
- 每次从新上下文开始，不带聊天或其他定时运行历史；比较基线由存储层处理，不要求模型回忆上次输出。

## 预算、结果与费用

任务可设总 Token（1000 至 500000）、工具调用数（1 至 128）、墙钟秒数（1 至 180），默认分别为 100000、64、180。固定只读档仍最多 12 步、单次请求输出最多 4096 Token，任务不能提高这些边界。预算新建记账，从组装开始计时，不继承上次已花用量。

- Token/工具/时间/步数耗尽记为失败，保留已返回正文和成功只读工具回执，不冒充成功。取消同样保留已有资料供用户检查。
- 输出按 UTF-8 字节限制在 64 KiB，避免截断字符，并保存摘录标记；摘要只用于短列表，不向通知发送正文。
- 用量完整性独立于数值：完整报告的零可以显示零；缺失或中断显示未报告/不完整，保留已知正数和保守预算记账，不能按零估算。
- 单价由用户按 Provider/模型配置，每百万输入/输出 Token 计价。只有本次完整用量且身份匹配才估算费用；未知用量、缺少价格或身份不匹配明确显示无法估算。编辑器上限费用是保守估计，不是服务商账单或硬费用保证。

### 变化提醒

用户显式提供稳定的比较标准。模型需返回严格对象 `comparison_value` 与人读 `result`；自由正文、空观察或损坏 JSON 记为比较失败，不能建立基线或冒充变化。

成功终态事务读取同任务、同定义指纹的最近有效观察；指令、规则、能力档、比较标准或提醒修订变化均建立新基线。只对比较值去首尾空白和 Unicode 规范化，不用易变化的整段报告冒充比较依据。

- 首次成功为基线，不发成功通知。
- 相同观察保存未变化结果，不发成功通知。
- 值变化且结果提交成功后才发通知，前台也可收到变化提醒。
- 失败遵从失败通知开关，不更新成功基线。一般成功仍遵从成功开关与 App 非前台条件。
- 通知只含状态和当前空间任务名；另一空间使用通用文案，不含名称或输出。系统/分类通知关闭不影响结果保存。

### 保存失败与后续操作

终态提交失败有限重试，随后保留内存中的精确结果并显示“重试保存”；只补写，不重新执行或重复计费，不提前通知，并阻止新定时执行。菜单栏显示需处理状态。此时须在退出前处理；内存结果不承诺跨退出恢复，重启只将旧活动记录标为中断，不自动重跑。

定时不自动创建聊天。用户可从定时页或任务详情：

- 继续追问：以来源和已保存正文新建待发草稿；不发送，原草稿与附件保留。
- 生成报告：生成待发请求，后续文件写入仍需普通工具批准。
- 保存知识：先打开可编辑正文预览，用户保存后才写所属空间；成功显示回执。

三种操作均重新读取所查看的运行，来源变动、删除、空间切换或关闭时拒绝迟到操作；失败/摘录来源在上下文中标明，不把部分内容称为完整报告。

## 代码与验收

Core 文件位于 `Scheduled/`：模型与计算、选项及比较、纯草拟工具、定义/运行存储和运行器。App/UI 的 `ScheduledTaskCenter` 负责生命周期、固定空间编排、保存重试与通知；`ScheduledTasksView`、`ScheduledResultActions` 负责编辑、信息及后续操作。`Hub` 不缓存这些空间服务。

回归使用临时空间库、合成资料、隔离调度中心与 URLProtocol 模型协议夹具，覆盖规则/夏令时/唯一领取、旧库/JSON、空间隔离、确认失败关闭、任务预算、含组装的截止时间、未知与真实零、部分输出和 UTF-8 截断、比较事务及保存失败不重放、启停语义、备份恢复。原生窗口测试点击草稿预览、取消/确认、追问/报告及知识保存按钮，并验证报告仍停在既有写入批准卡、批准后才产生实际文件。系统睡眠、退出和通知权限仍须按真实系统生命周期复核，不能用协议夹具冒充外部模型可用性。

检查命令和签名执行器要求见 [08-构建运行与测试](08-构建运行与测试.md)。专项端到端验收状态见 [16-产品体验与任务闭环](16-产品体验与任务闭环.md)。

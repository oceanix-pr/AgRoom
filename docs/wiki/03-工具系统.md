# 工具系统

工具是调度引擎操作本地与系统能力的统一边界。协议定义在 `DispatcherEngine.swift`，具体工具分布在 Core Runtime、Services 和 UI 的 Browser 功能中。

## DispatcherTool 契约

每个工具提供：

- `definition`：稳定名称、面向模型的描述和 JSON Schema 参数。
- `validateArguments`：可选的无副作用校验，只能拒绝无效调用，不能联网、初始化执行器或授予权限；确认前和执行前共用。
- 静态或参数级确认策略。
- 可选 hard confirmation，表示每次都必须由用户明确批准。
- `execute(argumentsJSON:)`：异步执行并返回模型可见文本。

新增工具时，名称应稳定、参数尽量少且语义明确。Schema、执行解析和确认展示必须使用同一套字段，避免模型看到的契约与实际执行不一致。

工具参数根节点必须是 `type: object`；内置工具使用兼容 OpenAI function calling 的普通对象定义，避免在根节点使用 `oneOf`、`anyOf`、`allOf`、`enum`、`const` 或 `not`。`shell_run` 的 `program + arguments` 与旧式 `script` 二选一约束由工具描述和本地 `validateArguments` / `commandTokens` 共同保证，无效调用仍在确认前拒绝，不依赖服务端 Schema 校验授予执行权限。

`modelResultCharacterLimit` 默认保留原有结果上限。有界文档读取可声明更高上限，但引擎仍施加硬上限；工具必须在序列化后检查整个响应的长度，按实际交付内容给出续读位置，不能先记录完整阅读、再让引擎截掉正文或 JSON 回执。

## 文档网站读取与技能来源

`web_fetch` 支持 `offset` / `limit` 与 `next_offset`，返回保留代码块的 Markdown、来源摘要、普通链接和源内容是否截断。HTTPS 约束在重定向时再次检查，本机回环 HTTP 除外；会话凭据和浏览器 Cookie 不进入公开抓取。缓存归本次工具装配，不在进程级共享网页内容。

`docs_collect` / `docs_read` 在当前空间技能库存在时注册，负责受限章节采集、分页正文、分页覆盖清单及可恢复的内部研究检查点。它们按 `readOnly` 能力、`idempotentWrite` 副作用记录内部采集/阅读进度，不安装技能、不运行示例、不写用户工作区。`skill_create(documentation_id: ...)` 校验实际阅读进度并附带来源文件，仍走原有技能写入确认。动态页面通过前台 `browser_read` 文档模式补采，Core 不依赖 WebKit，Daemon 不提供浏览器兜底。具体来源与覆盖契约见 [技能系统](06-技能系统.md)。

## 工具组装

工具面在每轮对话开始时根据当前空间组装，来源包括：

- 基础能力：时间、记忆、提问等。
- 文件、Shell、Python、SQL、网页搜索与抓取。
- 系统提醒事项和通知。
- App 宿主声明支持时的文件 OCR、音频转写、追加工作区目录的只读请求回执，以及文件生成。
- 当前空间的知识、技能和智体。
- 当前空间的邮箱账号与邮件。
- App 宿主声明并由 UI 注入的浏览器与原生小应用草稿工具。
- 当前空间配置并选择的远程 MCP 工具（仅前台主对话）。

工具清单会随实现变化，不在 Wiki 固定总数。实际注册结果以 `EngineAssembly.swift`、`DispatcherToolFactory` 和 UI 的 `AppHostToolFactory` 为准。`EngineHostCapabilities` 是当前进程的平台能力描述：App 声明浏览器、小应用草稿、文件 OCR、音频转写和追加目录请求卡；Daemon 和定时运行声明无前台能力。`DispatcherToolFactory` 将该描述传入 `AgentTool`，嵌套引擎仅在宿主支持时注册 OCR / 转写，且再次按能力及项目范围过滤；直接构造的子代理默认无头。浏览器与小应用仍只存在于前台主引擎的 UI 注入面，子代理不自行注册。未知 UI 注入工具默认不进入工具面；白名单、排除名单和项目范围过滤仍可继续收窄。系统提示中的完整浏览器流程只在全部对应工具实际注册后出现，其他工具专属提示也按最终工具名收敛。筛选复用原工具实例与原有确认策略，不新增执行捷径。

前台意图路由同时选择直接工具定义和配套提示模块。未直接披露的工具仍可发现，`tools_search` 将完整参数定义与宿主写定的 `tool_guidance` 一起返回；`tools_invoke` 继续进入原工具的权限、确认和执行路径。发现结果按当前技能限制筛选，定义或配套规则被压缩后须重新读取。资源注册表只描述本轮选入的技能与智体，创建技能、文档采集、备份和环境管理等说明各自随对应工具加载。

对话按当前工作区的主目录与显式引用文件夹构造 `FileAreaService.scoped(to:)`，不会挂载同空间的其他登记目录或公共父目录。文件读取、写入、OCR、音频转写、脚本输入与子代理继承该范围；目录替换与符号链接逃逸均拒绝。任意宿主 Shell 无法强制此范围，在工作区对话中禁用；显式批准的 `project_build` 仍按宿主构建契约处理。文件管理页保留独立的全局文件树，不向对话授予相同范围。

## 定时草拟

`schedule_draft` 只生成属于当前空间的可恢复草稿回执，不读写定时表、不启用或运行任务，因此是免确认的只读工具。普通完整工具面可用，定时白名单及显式受限装配不注册。参数严格限制规则、时区、预算和变化标准，回执必须能完整保存在会话轨迹中。会话卡打开原生预览，用户编辑并明确保存后才创建定义；没有模型直写定时表的入口。结果追问与报告也是待发草稿，后续文件写入复用既有批准；保存知识先编辑预览再提交。详见 [14-定时任务设计](14-定时任务设计.md)。

## 目标草拟与检查点

目标执行使用 `goal_draft` 返回绑定当前空间、会话和工作区的纯草稿，用户预览并开始后才创建目标。`goal_checkpoint` 只在前台目标段注册，记录候选工作笔记，不修改定义、权限或验收状态；它作为内部记账能力保留在技能工具收窄之后。目标段仍经相同引擎执行与确认，不能通过检查点自动批准操作。契约见 [目标执行](19-目标执行.md)。

## 追加工作区目录请求

`workspace_folder_draft` 仅在有会话身份的 App 前台普通主对话注册；编码、定时、显式白名单、Daemon 与嵌套子代理都不注册，也不能直接调用无头工具实例。它是免确认的 `readOnly` 工具，只接受有界 `reason`；运行时拒绝模型提供的路径、空间、工作区或会话字段。回执包含版本、随机展示 ID，以及从已核实执行上下文写入的空间、工作区 ID 和会话 ID。读取回执时必须再次核对这些身份、版本、完整 JSON 与说明长度。说明即使含路径也只是非权威文本，不用于目录选择。

回执只供会话显示请求卡，不修改 `WorkspaceRegistry`、`FileAreaService` 或冻结的 `TaskExecutionScope`，不代表目录已授权。用户之后明确点击请求卡并通过系统目录选择器选择，界面在登记前复核当前空间、工作区和会话；新目录只会在下一轮重新组装时进入文件范围。旧轨迹中的卡可以展示，但不得自动打开选择器或凭历史选择登记。

## 编码工具

统一对话挂载绑定主工作区的 `project_inspect`、`repo_search`、`files_read_range`，等价的检索、枚举和按行读取优先使用这些免确认工具；其他显式引用文件夹继续使用受管文件工具。工作区 Shell 可用且非逐次确认策略时，还挂载固定 Git 状态/差异读取的 `repo_changes`，其仓库元数据必须位于工作区内。自动工作流同时注册可按需发现的 `coding_task_read`、`coding_task_update` 和 `files_apply_changes`；后者使用有效的工作区写授权，缺少授权时沿用确认流程。这些工具绑定当前项目与空间，不扩大执行权限；定时任务仍按独立白名单装配。宿主构建增加 Xcode 测试、workspace 和定向测试参数，仍逐次硬确认。完整契约见 [15-编程工作流](15-编程工作流.md)。

## 编程工具的按需披露

编码主引擎保持文件、仓库、任务和构建等核心工具，其他已注册能力通过 `tools_search` 获取完整参数定义，再用 `tools_invoke(name, arguments_json)` 调用。原工具名、参数和调用 ID 在确认分流前解析，仍经过同一个参数校验、权限、目录、技能、预算、intent/receipt 与挂起恢复入口。发现和加载定义不授予执行权；无法解析、未加载或已受限的调用不执行。

公开函数定义及排序在该运行内保持稳定；首次签名或不透明续传回复绑定的完整定义随新快照保存。恢复时保留该工具面，执行仍按当前工具和策略校验。按需加载的原工具定义只认可当前上下文中完整存在、且与当前注册版本一致的结果；压缩掉定义后必须重新检索。旧签名快照沿用兼容回退。`toolNames` 记录请求实际发布的 Schema，`availableToolNames` / `mcpToolNames` 记录当前约束下可调用的原工具，包含按需工具，避免界面把它们误判为未挂载。

`repo_symbols` 的文本后端仅返回候选；可选 SourceKit-LSP 后端提供 Swift 定义、引用和符号读取。加载真实项目配置可能运行清单或构建服务器，因此语义查询属于宿主代码执行，要求完全权限与逐次硬确认；文本调用仍是只读。它不增加 Shell 白名单、不自动信任服务端请求，不在失败后切换为宿主后端。索引状态与当前限制见 [15-编程工作流](15-编程工作流.md)。

自动对话保留完整的可调用工具集，可按下述本地意图建议延迟披露 Schema；定时白名单保持原有装配策略。工具披露不新增能力。编码实施状态见 [编程能力与 Token 效率优化](design/2026-coding-efficiency.md)。

### 自动工作流与本地意图筛选

App 前台主对话在解析本轮参数前，在模型与内置推理入口可用时，以 `LFM2.5-350M` 对当前请求做一次主要业务域的只读分类。技能目录与正文不进入分类进程。`LocalIntentRoutingSettings` 默认读取 `~/Documents/AgRoom/models/LFM2.5-350M/LFM2.5-350M-Q8_0.gguf`；全局偏好只保存开关与公共权重路径，不保存提示词、分类结果或空间服务。

分类只建议一个主要业务域：coding 建议工程参数默认值和开发核心定义，其他领域使用通用默认值；用户的手动模型偏好在两类工作流共用。宿主严格校验枚举和输出结构，再从已通过空间、宿主能力、白名单与项目过滤的真实工具中选出有界直接定义；其余工具通过 `tools_search` / `tools_invoke` 发现与调用。首轮选择和后续发现共用简体中文、繁体中文和英文动作词。复合请求可同时补选多个领域，首轮按实际定义的估算 token 和工具数量限制开销，超出预算的定义可继续按需发现。系统提示按实际直接定义省略无关工具流程；宿主将领域关键词与当前请求结合，对本空间技能元数据选择有界摘要，正文仍由 `skill_load` 加载。模型不会生成技能 ID、执行参数、批准操作或改变工作区。确认、技能交集、参数校验与副作用回执继续走同一引擎入口。

网页操作信号可补选当前实际存在的 `browser_list`、`browser_open`、`browser_read`，避免合法但错误的领域标签隐藏浏览器入口；未明确要求代码执行的网页任务不直接推荐脚本执行工具，原能力仍可发现。相对日期任务和浏览器领域补入实际可用的 `get_current_time`，提示模型先读取本机时间再推算日期。没有操作或日期需求的普通问候继续仅披露发现入口。本地分类提示保持原有基线；中文 OA 预订、登录暂停、表单操作和英文业务网站作为诊断与能力补选回归，分别报告原始分类是否命中和实际工具是否齐备，不以补选通过宣称分类准确率提高。

按需工具面附带按真实注册结果生成的简短能力目录，不重复完整 Schema。若普通对话、工程或目标的按需工具面准备声称能力缺失，引擎在剩余步骤允许时最多做一次定向目录查询，把完整定义与宿主规则作为带本地来源标记的元数据回执追加到上下文；不伪造模型工具调用、不执行发现的业务工具，也不改动已发布或签名绑定的工具定义。来源标记、完整参数与当前配套规则都核实后才恢复发现状态；普通用户文字不能设置该标记，定义或规则被压缩、修改后须重新发现。权限拒绝、用户拒绝、审核拒绝或失败的非只读操作不会触发此纠错。纠错次数随运行快照保存，恢复不重复查询，后续执行仍受技能、任务范围、预算与确认边界约束。

模型缺失、停用或分类失败时沿用原有装配。没有确定分类但存在明确动作时，框架可依据已注册工具的动作词或附件类型选择入口。取消继续传播。每次分类使用独立短进程，不写入提示词文件或保留 KV 状态；请求报告记录经校验的领域、披露的工具、请求次数以及是否因来源不符追加了纠错。日志只记录工具/技能数量、本地 Schema 估算与发生纠错的事实，不记录请求或凭据。工程工作流使用既有开发核心披露，其他领域能力仍可发现；定时、受限白名单与嵌套子代理不运行这项前台分类。

本轮解析的工作流、参数与已激活的编程记账状态随检查点保留；选定的定义同样冻结，Daemon 接管按原选择与当前可用工具交集恢复，不重新分类或恢复前台 UI 能力。签名/不透明续传仍保留其绑定的精确定义，实际执行按当前权限失败关闭。延迟披露节省的是定义与目录开销，不能解释为全部输入 Token 或费用的固定节省比例。

## 外部 MCP


设置页「工具与自动化 → 管理 MCP 服务」配置当前空间的远程服务。Core 的 `MCPHTTPClient` 通过自有 `MCPClient` 协议提供发现和调用，`MCPDispatcherTool` 将已选择的远端定义接入统一执行边界；无需 Provider 提供 MCP 专用 API，也不把服务器提示提升为系统指令。

服务启用与具体工具选择是两个条件。已启用但未选工具时，设置页和「项目说明与资料 → MCP 工具」明确提示无法调用，不自动勾选新发现的工具。工具页签区分本轮/最近一轮实际工具快照和下轮设置，显示服务、工具名、只读模式阻止、技能过滤或配置变更；打开页签不发起远端发现或业务调用。指定 MCP 不可用时引导用户通过该页签管理配置，不查找同名源码目录、凭据，也不通过其他工具代调用。

设置支持显式粘贴 HTTP 地址、单服务 JSON 或 `mcpServers` JSON。多个服务由用户选择其中一个进入编辑器；粘贴仅生成临时草稿，不连接、不保存 Token，也不授予工具选择或确认权限。拒绝 stdio、旧式 SSE、环境变量及不支持的请求头；Bearer Token 仅在用户保存时进入 Keychain。设置与项目中的 MCP 工具页签支持工具搜索和只看已选工具。

- 传输为 Streamable HTTP，支持 JSON 和请求级 SSE 响应。优先使用 MCP `2026-07-28` 的逐请求元数据与发现；识别旧服务后通过 `initialize` 协商 `2025-11-25`、`2025-06-18` 或 `2025-03-26`。仅在发现阶段判断协议，不通过重放业务调用兼容版本。
- 认证支持无认证和手动 Bearer Token；远端强制 HTTPS，回环地址允许 HTTP。不支持 URL 内嵌凭据、查询参数或片段，不跟随重定向，不使用共享 Cookie 或系统 HTTP 凭据。OAuth、stdio、旧式 HTTP+SSE、Resources、Prompts、MRTR、订阅和 MCP Apps 暂未接入。
- 服务元数据与审核过的工具目录属于空间库；Token 只进空间命名的 Keychain 条目。`Hub` 不缓存服务或客户端。保存使用配置修订号和独立凭据引用：并发旧编辑拒绝，数据库保存失败不替换旧 Token，换端点不能复用旧端点的凭据。
- 允许使用配置服务的会话根据已保存目录组装 MCP 工具。获准调用后再发现实时定义并复核配置、选择和参数。业务请求提交前，空间库原子登记端点、工具和参数指纹。超时、断线、未确认的远端错误或进程退出后，相同操作继续阻止重送。用户在 MCP 设置核对远端结果并清除对应记录后，才能重新申请。清除记录本身不发送请求。
- 工具名由服务 UUID 与远端名称摘要构成，适配层注册时拒绝重名；不覆盖内置工具。保留输入 Schema，校验并支持新版静态属性的 `x-mcp-header` 映射，无效定义从发现结果排除并提示。
- 远程工具保留 `externalEffect` 与 `nonIdempotentWrite` 分类，不信任 `readOnlyHint`、`idempotentHint` 等声明。名称、Schema 和实际参数通过宿主的保守查询候选筛选后，可走普通确认与 `modelReviewable`；开启会话自动审核时，由无工具审核模型核对原始用户需求和本次完整参数。候选身份不代表已证明远端只读，不能按工具名称直接放行。写入、删除、发送、动态动作、执行代码、本地路径、凭据相关或无法判断的工具继续逐次硬确认。审核失败、超时、缺少任务范围或证据不匹配转人工，不支持本轮授权或持久免确认。只读模式仍拒绝 MCP；批准不能使远端工具获得本地工作区沙箱资格。
- 确认卡展示固定的服务名称、实际端点、远端工具名和本次参数，明确远端数据权限由服务账号控制。只发送显式参数，不自动附带整段会话、记忆、数据库或本地权限。
- 结果支持文本与结构化 JSON，其他媒体不下载或渲染并明确标记省略；`isError` 保持失败轨迹。含当前凭据回显的工具定义不进入目录，文本与嵌套 JSON 输出对凭据脱敏后才进入轨迹。响应、分页、目录、已选择定义的上下文占用和等待时间都有上限；会话结束尽力关闭旧版远程 session。业务调用不自动重试，发送后断线/超时/取消不能证明未执行：标记结果不确定，并在同一空间跨轮次与重启阻止同端点、工具和参数的重复提交；取消不承诺撤销远端副作用。
- 前台组装点显式启用 MCP；智体、团队 Worker、定时任务和守护进程不挂载。工具面包含 MCP 的运行暂不允许退出移交，等待确认卡仍沿用现有持久化与人工恢复限制。

## MySQL 宿主连接器

数据库页的「MySQL 连接」管理当前空间的服务器、端口、数据库、用户名与 TLS 要求，并提供测试、表列表和字段浏览。配置进入空间 SQLite 的 `mysql_connections` 表；密码只进空间命名的 Keychain 条目，保存使用不可变凭据引用与配置修订号。保存失败保留原连接和密码，并发旧编辑不能覆盖新配置；变更服务器、端口、数据库、用户或 TLS 要求时必须重新提供密码。

`MySQLConnectorService` 由 Hub 按空间现取现建，不缓存网络连接。`NativeMySQLMetadataClient` 使用原生 MySQL 驱动及参数绑定，只开放固定的 `information_schema.TABLES` / `COLUMNS` 查询。远程 MySQL 使用验证证书及主机名的 TLS；仅 localhost、127.0.0.1 与 ::1 允许显式明文，不自动降级。此传输是用户明确配置的 MySQL 协议；HTTP 服务与模型端点仍遵守 HTTPS 规则。Python 执行器的离线边界不变。

聊天工具 `mysql_connections` 只返回有界连接摘要，不返回凭据；`mysql_metadata` 使用已有连接 ID，省略 `table` 读取表清单，指定表名读取字段，逐次硬确认。工具和小应用能力桥复用同一个连接器，`sql_query` 继续仅操作其绑定的 SQLite。查询有超时、取消、行数和字节上限；超限返回错误，驱动原始错误不进入 UI 或日志，避免泄露认证或 SQL 内容。

SQLite 工作台每次只接受一条语句，以绑定空间库中实际预编译语句的 `isReadonly` 判断读写；`EXPLAIN` 由 SQLite 的计划语句标识补充判定，只返回计划，不执行其解释的写入。预编译、绑定或单语句校验失败时不能据首词免确认。`sql_query` 的 `parameters` 可用标量数组绑定 `?`，或用对象绑定命名占位符；参数不会拼接成 SQL。实际只读的 `SELECT`、只读 CTE 与 `EXPLAIN` 可免确认；写 CTE 与其他写语句走既有副作用确认和执行日志。调度器将是否写 intent 的分类冻结传入 SQL 执行器，若免确认的只读调用在执行前变成写入则直接拒绝。`PRAGMA` 即使报告文件只读仍保守确认，因为它可能改变连接状态。工作台只读模式在执行前再次核对实际语句，拒绝写入。查询移出 UI 主线程，提供截止时间、取消以及行数、单元格和总结果大小上限，逐行物化游标数据。工作台连接禁用附加数据库，并拒绝 `ATTACH` / `DETACH` / `VACUUM`，防止 SQL 越过绑定库访问其他文件。连接缓存的锁只保护内存状态，打开连接在锁外完成，并核对文件身份以识别路径替换。

`SQLQueryTool` 仅在 Core 内由组装点构造；UI 不直接持有其分类后写执行入口。无调度器许可的直接 `execute(argumentsJSON:)` 只允许只读语句，写操作须经过调度器确认及副作用 intent 门禁。

驱动源码与许可证位于 `vendor/mysql-nio` 和 `vendor/swift-nio-ssl`，来源及安全补丁记录在相应 provenance 文件；两条工程配置使用相同依赖。TLS 缺失时必须在认证前失败，不能信任驱动的机会式 TLS 默认行为。取消先关闭已登记的 TCP 连接，握手与认证回执单次结束；事件循环在驱动回执收尾后释放，避免关闭中的连接遗留未完成 promise。

## 空间内容管理工具

除检索外，调度 Agent 也可管理空间内容：知识条目（`knowledge_list` / `knowledge_save` / `knowledge_delete`）、长期记忆（`memory_list` / `memory_update` / `memory_delete`）、智体（`agents_list` / `agents_save` / `agents_delete`）、技能（`skill_delete` / `skill_set_enabled`），以及联网检索 `web_search`。

这批工具实现在 `AppManagementTools.swift`，只调用与功能页相同的空间服务，不直接访问 GRDB，也不存在跨空间参数；未提供的服务不注册对应工具，避免公布无法执行的能力。`EngineAssembly` 传入 `managementToolsAvailable` 后系统提示词注入 `[Managing User Data]` 分节。

- 定位规则：显式 `id` 优先；按标题、名称或正文片段定位时，命中多条一律拒绝并列出候选，由模型改用 id，不允许猜测。
- 确认分级：只读工具（`*_list`、`web_search`）免确认并显式声明 `readOnly`；写入需确认，更新类幂等工具声明 `idempotentWrite`；智体与技能删除不可逆，使用 hard confirmation（无视本轮授权）。
- 写入上限：单条文本超过 20 万字符时返回可操作错误，不静默截断。

知识组织的只读发现入口是 `knowledge_list`：返回有界的库 / 目录 ID 目录，以及带完整路径的条目摘要，可通过 `base_id` / `folder_id` 限定范围。`knowledge_search` 使用相同 ID 指定范围，`include_descendants` 默认包含子目录，关键词与语义召回均遵守此范围；无效范围拒绝执行，不能静默扩大。

`knowledge_save` 可指定 `folder_id`，空字符串表示库根，省略时在库不变的情况下保留原文件夹；切换知识库且未明确指定目录时清除原目录归属。同名更新只在已指定的库 / 目录内匹配，有歧义须使用条目 ID。目录归属写入仍经过服务校验与既有写入确认，不新增免确认入口。

## 多智体团队工具

`team_run` 是多智体协作入口（P0 只读 + P1 持久化/验证 + P2a 受控写）：接受一个小型子任务 DAG，由 `TeamCoordinator` 并行调度只读 Worker，最后返回结构化摘要与产物摘录。只有设置页「启用多智体协作」打开且当前空间存在启用智体时才注册；关闭时模型完全看不到该工具。

- `team_run` 本身只读、免确认；Worker 默认只读（文件读取、知识/记忆检索、网页检索与抓取、提醒查询、时间），不含 Shell、Python、邮件、提醒写、浏览器交互与 `ask_user`。
- 开启「允许团队写文件」且会话权限允许时，Worker 额外拿到 `team_write`：只写当前会话工作区内的 UTF-8 文本（≤1 MB），每次写入进入任务板审批收件箱，用户批准后才申请路径级写租约并写入；批准后文件若变化则拒绝覆盖。
- 子任务依赖用 `depends_on` key 声明；依赖满足后才启动下游。主调度只拿到最终 digest，不接收 Worker 的完整上下文。
- 任务预算由协调器预留与结算；失败/取消/预算不足时保留已完成产物并在报告中标记。
- P1 在启动、子任务结束和最终报告时写入当前空间 `team_tasks` 快照；侧栏「协作」页只读展示，不跨重启续跑。
- 全部子任务成功后由独立验证者判定；验证失败、格式不可解析、Provider 失败或验证后超预算都判 `failed`。
- 团队写使用进程内 `TeamApprovalCenter` 与 `TeamLeaseCenter`：按空间过滤、路径级单写者、600 秒审批超时；写入前先落 `team_writes` 快照，任务板可按单文件回滚或批量回滚；daemon 无审批人，禁用团队写。完整契约见 [13-多智体协作](13-多智体协作.md)。

## 代码执行类工具的结果语义

`python_execute`、`skill_run_script`、`python_package_manage`、`shell_run` 在子进程退出码非零、超时或启动失败时返回失败：有界输出和退出状态仍会回填给模型，但执行轨迹标记为失败，不能把“进程跑起来了”误当成“命令成功”。这避免模型在失败后继续把同一结果当成功依据。Shell 显式重定向在成功后保存完整数据文件，模型仍只接收摘要。

非零退出是命令语义的一部分（如 `grep` 无匹配返回 1、`git` 不在仓库内返回 128），因此保留原文与退出码由模型按用途解释，而不是统一改写为“执行成功”。`shell_run` 的只读快速通道与硬化路径同理。

## Python 执行环境（安装 / 查询 / 执行统一）

原生小应用的 `runPython` 复用同一空间环境与离线执行器，通过确定性 `nativeapp_python_run` 命令执行。首次执行前统一审核完整应用代码，通过后签发绑定空间、安装、定义原始摘要、环境及策略的 HMAC 凭证；每次运行核验凭证与代码，输入变化可复用审核，篡改或环境变化重新审核。审核拒绝不执行，不确定或不可用转逐次硬确认；人工允许一次不授予持久权限。它只读取宿主冻结的记录/附件输入，使用独立 JSON 回执回填状态；生成文件经应用工作区命令另行确认保存。脚本声明、输入/输出和生命周期契约见 [原生小应用](11-原生小应用设计.md#python-业务函数)。

`PythonEnvironmentService` 按空间解析唯一执行环境：基础解释器只来自 `~/Documents/AgRoom/python-runtime/bin/python3`，并在 `~/Documents/AgRoom/python/<space>/venv` 创建空间专用虚拟环境。`python_execute`、`skill_run_script`、`python_packages`、`python_package_manage` 与 Python 页/设置页共用当前空间的解释器，消除“pip 装上了、执行却导入不到”的环境分裂。

- 不扫描或回退系统、Homebrew、Conda、pyenv 或旧 Application Support 环境，也不再读取旧自定义路径和回退开关。缺失时停止执行，提示用户在「设置 → 工具与自动化 → 管理 Python 环境」主动下载并安装专用运行时；查询不隐式下载。
- 路径检查同时核对真实路径，拒绝指向受管根之外的解释器链接，以及重定向到其他目录或空间的环境目录。复用 venv 前核对解释器、`pyvenv.cfg` 中的基础路径和 `include-system-site-packages = false`，不把借用本机 Python 的 venv 当成就绪环境。
- 一轮任务固定环境身份（设置修改从下一轮生效）；`python_env_status` 直接报告执行器实际解析出的环境，不另做探测。
- 环境创建先建到同父目录的暂存目录并验证可用，再原子改名落位；App 与 Daemon 并发准备时先落下者胜出，后到者复用，不覆盖既有环境。
- 状态、包列表和依赖探测只读取已就绪环境。首次创建空间 venv 由用户在 Python 设置页显式发起。对话执行与包变更遇到未准备环境时停止，语法检查可单独使用基础解释器。
- venv 创建失败明确报错，不回退到共享基础环境，避免包安装或执行越过空间隔离。
- 安装分两步。固定的离线 pip 程序接收分发名和受限版本说明符，在本空间一次性传输目录解析 wheel 及其依赖。缺少的 HTTP 响应通过有界文件交换交给主程序下载，主程序只允许 PyPI HTTPS 索引、wheel 与 wheel 元数据，拒绝凭证、任意请求头、其他地址和越界跳转，并限制文件、总流量、请求次数和总时长。响应缓存仅在本次空间目录中存在，执行器只有读取权；下载完成后复验 SHA-256 清单，再离线安装到目标 venv。卸载和 `pip show` 也只走离线执行器。跨 App/Daemon 租约让环境变更与脚本运行互斥，变更开始即使旧执行授权失效。
- `personal` 与 `work` 使用各自的环境与执行目录，物理隔离；新的空间环境目录纳入另一空间的文件写入和脚本读写禁区。固定环境目录不替代既有沙箱或执行确认。

## 长任务与导入导出

备份导出与恢复（`backup_export` / `backup_restore`）、Python 运行时与包（`python_env_status` / `python_packages` / `python_package_manage`）、技能导入导出（`skill_import_zip` / `skill_export_zip`）实现在 `AppTaskTools.swift`。

备份工具先用只读 `backup_inspect(path)` 返回逐类覆盖、遗漏、冲突及包指纹；`backup_restore(path, package_fingerprint)` 必须匹配该包，继续逐次硬确认。工具拒绝跨空间恢复；设置页承担明确的跨空间来源核对。完整范围、恢复点与失败语义见 [05-数据模型存储与知识库](05-数据模型存储与知识库.md)。


- 执行位置：这些工具在对话轮次内前台执行，不提交 `JobCenter`——作业名需要 UI 层的 `L.string`，Core 拿不到，硬塞会破坏模块边界；运行可见性与取消由对话轨迹和停止承担。
- 路径边界：备份恢复与技能导入的来源必须落在受管文件区内，越界返回可操作错误并提示用户先把文件移入；备份导出目标固定为标准备份目录，不接受模型给出的任意路径；技能导出目标目录登记进 `FileAreaPolicy.writeTargets`，与 `files_*` 同受写范围守卫。
- 覆盖空间的 `backup_restore` 和变更 Python 包的 `python_package_manage` 逐次硬确认。备份导出与技能导入导出沿用各自的确认策略。备份检查、环境状态、包列表为只读操作。
- `backup_restore` 先跑 `BackupService.inspect`：清单中声明的段校验和不符时拒绝且不写入数据；跨空间包拒绝执行并引导用户到设置页确认（工具不能替用户表达跨空间意愿）。写入前持久化原值及实际事务回执，失败后按摘要核对并回滚；只有全部还原成功才报告完整回滚，否则保留恢复材料并报告不完整。
- pip 包名走白名单校验，拒绝以 `-` 开头等可注入 pip 选项的取值；pip 输出与包列表统一截断并标注。
- `python_package_manage` 用目标环境的解释器执行 pip，安装成功后用同一环境的 `pip show` 复验包是否可见。
- `skill_run_script` 执行前检查技能声明的依赖（`scripts/requirements.txt`）：缺失时返回结构化结果并明确「未执行」，安装只能由用户经 `python_package_manage` 批准——不隐式安装（见 [06-技能系统](06-技能系统.md#依赖声明)）。

## 邮箱工具

邮箱工具实现在 `Runtime/MailTools.swift` 的 `MailToolFactory`，与功能页共用同一批空间服务（`MailAccountService` / `MailService` / `MailSyncService`）。`EngineAssembly` 构造这三个服务后随其他工具一起注册；未注入邮箱服务的组装点不注册这批工具，避免公布无法执行的能力。

- 读类：`mail_accounts_list` / `mail_folders_list` / `mail_list` / `mail_read` / `mail_search` 免确认并声明 `readOnly`。`mail_read` 在正文未缓存时经同步服务按需拉取，只写本地缓存，仍然幂等。返回只含附件元数据（名称与大小），不返回附件内容。
- 标记：`mail_mark`（已读 / 星标）免确认，声明 `idempotentWrite`——本地立即生效并尽力回写 IMAP，重复执行结果一致。
- 写入：`mail_save_draft` 需确认并声明 `idempotentWrite`；`mail_send` 需确认并声明 `nonIdempotentWrite`，真实投递不可撤销，成功后落本地「已发送」副本。
- 删除：`mail_delete` 需确认，并对逐次执行要求 hard confirmation（无视本轮授权），声明 `nonIdempotentWrite`——服务器上删除不可恢复。
- 级联语义：移动与删除都先远端成功再改本地，远端失败时本地状态不变，可重试。
- 删除只影响目标邮件：不带 UID 的 `EXPUNGE` 会清掉该文件夹里**所有**已标 `\Deleted` 的邮件（RFC 3501 §6.4.3），因此实现先取该文件夹的待删集合——集合里只有目标时执行 `EXPUNGE`，有其他 UID 时只允许 `UID EXPUNGE`（RFC 4315），上游协议栈不提供该命令时**中止并明确报错**，绝不退化成全量清除。清除后用标记搜索对账，目标仍在则报「删除未完成」并保留本地记录。
- 正文按需拉取只取文本部件（`BODYSTRUCTURE` + `BODY.PEEK[HEADER]` + 文本段），附件不下载、大小取自结构的 octets，单封超过 `MailSyncService.bodyByteLimit` 时拒绝下载并提示。
- 同步按 UID 分批（`MailSyncService.syncBatchSize`）、逐批落库，批间响应取消并上报逐文件夹进度。
- 输出统一截断，与既有工具同一上限模式。

## 确认分级

| 类型 | 常见行为 | 规则 |
|---|---|---|
| 只读 | 查询、读取、列举 | 通常免确认，但仍受作用域限制 |
| 可逆写入 | 新建文件、保存记忆 | 根据既有产品策略确认，可记录「本轮允许此范围」（只活一轮）；能确定解析的单条 Shell 命令另可选「记住…」保存有期限的精确规则 |
| 破坏性或自由执行 | 删除、覆盖、Shell、Python、写 SQL | 必须确认；高风险行为可要求逐次 hard confirmation |
| 用户可见外部副作用 | 提醒、通知、系统数据修改 | 清楚展示目标与参数后确认 |

确认规则属于执行边界。不能只依靠系统提示要求模型“先询问”，也不能从新的 UI、技能或子代理入口绕过。

## 可信执行摘要

工具通过 `approvalPresentation(argumentsJSON:)` 给出确认卡所需的可信摘要，默认返回 `nil`（旧工具回退到既有摘要）。摘要包含执行档、实际读取/写入/产物/临时范围、执行器容器、联网与子进程能力、稳定原因码、限制来源和可审阅的执行事实；资源范围中的 `$...` 是稳定占位符，由 UI 做三语展示，真实路径按原样显示。

- Shell、Python、技能脚本和宿主构建已接入；摘要由工具按实际参数与执行器身份生成，不读取模型自述。
- 宿主执行的 `verified` 必须为 false：它不受 App Sandbox 保护，不能展示成受控白名单，也不能承诺“只访问此目录”。
- 摘要只影响展示与授权有效期选项，不改变权限判定；授权资格仍由 `ConfirmationRequirement` 和模式判定给出。
- `ConfirmationRequirement.availableApprovalDurations` 只返回当前调用真正可用的选项：硬确认恒为仅一次，本轮授权需要 `roundKey`，持久规则需要精确候选。

## 权限模式

会话可处于“仅可查看 / 工作区内修改 / 扩展访问（高级）”三档之一（底层值仍为 `danger-full-access`，见 [12-权限模式](12-权限模式.md)）。模式是能力上限，先于确认判定：

- 模式拒绝直接变成 toolResult，不弹确认卡；硬确认、持久规则、本轮授权和自动审核都不能翻盘。
- 模式允许不取消工具自身的确认；只有工作区内模式对 `files_write` / `file_write` / `files_mkdir` 这类已声明资格、目标在写范围内的低风险写免确认。
- 工作区内模式允许获准目录内的沙箱单命令，拒绝宿主 Shell；Python 与技能脚本使用强制离线沙箱，仍需确认，业务写目标限本次运行产物。各执行器不能联网或启动子进程，系统仍允许其自身隔离容器访问。只读模式拒绝代码执行，仅允许静态只读工具调用。
- 文件工具始终受受管根/登记工作区约束；扩展访问（高级）只放宽会话工作区上限，不能跨空间或越过受管根。
- 守护进程沿用会话权限模式。主动移交且任务范围校验通过时，可继续工作区内确定性低风险操作；旧记录没有范围时不获得文件写免确认。后台只读 Shell 走严格规则，写命令和宿主执行保留人工。

## 自动审核与低风险操作

会话开启自动审核后，`files_write`、`files_mkdir` 与兼容名称 `file_write` 可以在会话工作区范围经核验后自动放行。`files_edit` 在具备任务恢复点、有效任务范围和自动审核时可以走确定性规则；它仍校验 `expected_sha256`、唯一匹配、路径和旧字节，恢复点保存失败则不写入。`file_write` 复用 `FilesWriteTool` 和 `FileAreaService`，相对路径按绑定的会话工作区解析；审核、引擎写范围守卫和执行使用同一份绝对路径参数。文件名冲突自动改名，不覆盖；它不再提供整个 Documents 目录的独立写入口。技能生成提示优先引导模型使用 `files_write`。

`shell_run` 的只读资格仅适用于默认沙箱中的单条命令：

- **单条只读命令**：简单只读程序、Git 只读子命令、`find` 的安全谓词、`grep` 与受限 `rg` 均按明确选项表解析。`rg` 支持列举、字面 glob/type/regexp 和有界上下文等已列明参数，强制 `--no-config`；预处理、解压、跟随链接、额外配置/模式文件和未知选项均拒绝。工作目录与文件参数须落在会话工作区内；结构化 argv 按程序选项和操作数核验，字面参数不做 Shell 展开，兼容 `script` 入口仍拒绝变量、通配、管道和重定向。解析通过后直接启动固定绝对路径程序，不经过 zsh、用户 PATH 或启动脚本。显式文件输入输出保留单次参数审核，不参加自动审核。精确支持集合以 `ShellReadOnlyCommand` 为准；普通检索与局部读取优先使用受管工具。

复合脚本不属于沙箱单命令语法。显式宿主入口保留只读复合语法检测，用于逐次确认后的 `zsh -f` 与固定 PATH 硬化；该检测不再赋予只读资格、自动审核或记忆授权。单条沙箱命令直接 exec，不经过 Shell。

git 只读子命令仍可能触发仓库配置中的外部程序，因此执行侧同时注入硬化参数与环境变量：`-c core.pager=cat` 与 `-c core.fsmonitor=false` 关闭分页器和 status 文件监视 hook，diff 族追加 `--no-ext-diff --no-textconv` 关闭 external diff 驱动与 textconv，`GIT_CONFIG_NOSYSTEM` 不读系统级配置，`GIT_CEILING_DIRECTORIES` 限定仓库发现范围（只允许会话工作区内的仓库）。git 操作数（提交、分支名）不做路径校验，越界防护由仓库发现范围承担。

Shell 字符串中的重定向语法只能通过显式宿主入口使用，该入口逐次硬确认；沙箱内应使用受控的标准 I/O 文件字段。

离线 Python 与技能脚本可以声明 `.modelReviewable`：规则先核验执行档、任务范围、签名执行器和证据；规则不能证明低风险时交给无工具的审核模型。缺依赖、执行器缺失、证据截断或脚本/环境变化时转人工，不隐式安装。其他脚本仍遵循已有确认策略；宿主执行逐次硬确认。

自动审核不会扩大本轮或持久授权的范围。删除、外发、宿主执行、宿主构建及未知浏览器点击等未获资格的操作保留人工，并向确认卡传递稳定原因标识。审核记录包含任务身份、路由、范围摘要、执行档和调用摘要，不写脚本正文、密钥或书签。

## 文件与路径安全

### 分页读取与已有文件编辑

`files_read` 返回 JSON 页：`content`、`sha256`、`offset`、`total_characters`、可选 `next_cursor`。普通对话按块扫描最多 32 MiB 的 UTF-8 文件，只保留本页内容；默认每页最多 3500 个字符，`max_chars` 可在 1–4000 内选择，JSON 转义、元数据和 UTF-8 字节均计入输出预算。超长行可连续分页；单个字素本身超出页预算时明确拒绝，不返回破损 UTF-8。游标绑定规范路径、完整内容摘要和字符位置；`repo_search.read_cursor` 与 `files_read_range.next_cursor` 可直接定位到大文件中间。文件变化或换路径必须重新定位，不能混用不同版本。定时读取沿用分页协议，保留原有 2 MiB 上限和当前空间范围。

`files_write` 保持同名另存的创建语义。修改已有文本使用 `files_edit(path, expected_sha256, old_text, new_text)`：摘要来自当前 `files_read` 页，旧文本必须非空且唯一匹配，重叠匹配也视为歧义。工具声明目标文件为写路径，经空间/会话/技能/子任务交集校验。有效工作区授权覆盖受管编辑，关闭模型审核也无需逐文件确认。覆盖已有内容前须先保存任务恢复点。恢复点异步保存后、文件发布前再次检查取消，停止任务不能利用保存期间的空隙继续写。每次执行都重新读取摘要并在发布前再次核对旧字节；文件变化、符号链接和另一空间目标均拒绝，因此旧批准不会落到新内容上。与团队写共用路径租约，通过条件原子写替换文件并保留普通权限位；不提供任意覆盖开关。

已有文本的编辑与显式恢复支持每文件最多 16 MiB，受管批量编辑和编码任务原始基线总量各限 32 MiB。检索和读取的较大上限不代表文件可编辑；超出编辑或恢复预算会在副作用前停止。大型文件的小范围差异只比较变化中段，无法生成准确统计时确认卡明确显示比较不可用，不把文件总行数伪装成实际增删行数。

`FileAreaService` 管理 `~/Documents/AgRoom` 受管区（受管区根，下含 files、workspace、privatespace、`default-chat/<space>`），并可挂载用户登记的已有工作区目录（任意位置；`/`、主目录本身与 `~/Library`、`/System`、`/Library` 被拒绝）。写类工具还受 `FileAreaPolicy` 约束：

- 标准化路径后检查是否位于允许根目录；登记已有工作区需先通过位置安全校验与读写探测。
- 拒绝 `..`、符号链接逃逸和未授权绝对路径。
- 默认写入根是会话归属的工作区目录；技能加载后可进一步收窄到该技能的工作区。
- 技能 `workspace-folder` 在组装引擎时解析为绝对路径（相对值按 files 根解析），落在受管根外的不生效并记日志，不允许声明被静默忽略。
- 受管根同时是「不可删除/改名」集合，避免默认工作区被改名后会话落到其他目录。
- 删除、覆盖和移动遵循先可逆后不可逆，并展示真实目标。
- 大文件读取和工具输出有大小上限，截断时明确标记。

工作区选择器的原始 URL 交给 `WorkspaceAccessCoordinator` 建立长期书签，按空间保存、在后续装配时恢复。恢复失败、目录身份被替换或登记不可用时停止装配，菜单提供重新选择入口；旧路径登记不自动扩大授权。长期书签不交给不可信脚本，执行器仍使用按次准备的授权。执行器的临时书签同时绑定规范路径与设备号、inode、文件类型；成功激活且对象身份一致时可刷新 stale 元数据，不能仅凭 stale 推断工作区授权丢失。对象替换、路径变化或激活失败仍拒绝，准备阶段继续转换为只读令牌。

## Shell、Python 与 SQL

- `sandbox_diagnose` 只执行固定的离线探针，不接受脚本。默认分别检查当前空间 Shell 与 Python 执行器的最小授权链，不携带会话工作区、Python 环境或数据库；`check_workspace=true` 再比较绑定工作区的授权与访问。报告仅含角色、阶段、错误码和授权项序号，不回传目录内容、书签或私有路径。它不验证 Python 包，也不声明支持编译或子进程。
- 隔离失败需区分范围冲突/数量或请求大小超限、启动失败、协议不匹配、授权创建/解析/激活/路径变化、准备超时和响应异常。宿主只将可信准备进程的结构化错误作为诊断，不把用户代码 stderr 当作可信授权状态。通用失败不能推断“工作区含私有数据”，也不应仅重复换命令或目录；先比较最小与工作区检查，再修复具体阶段。诊断协议变化必须重建完整签名 App。
- `project_build` 只接受固定构建或测试动作，按 argv 启动，需要有效项目目录、扩展访问、会话允许申请宿主执行，以及本次硬确认。确认卡单列起始目录，提示项目代码可使用宿主的文件、网络和进程权限。工作区限制适用于选取项目与工具写目标。宿主构建使用独立缓存和临时 HOME；构建日志位于本空间默认对话目录的 `.agroom-builds`。沙箱拒绝不会自动触发宿主执行。

- 自由 Shell 和 Python 执行是高风险能力，必须有确认、超时、取消和进程终止兜底。
- `shell_run` 默认 `execution_mode=sandbox`，在本空间统一签名的离线 App Sandbox 中直接执行单条程序调用；优先使用 `program` + `arguments` 字符串数组，参数中的 `$`、反斜杠、正则、`--key=value` 均原样传入，不展开变量或解释 Shell。兼容入口 `script` 保留原来的严格单命令语法，两种形式互斥。工作目录默认会话工作区。静态只读命令仅获输入读取；其他命令声明整个工作目录为写目标，经 `FileAreaPolicy` 的空间/会话/技能/子任务交集检查后才可授权该目录写入。目录包含另一空间私有子树时拒绝整体写授权，需选择安全子目录。独立临时 HOME/TMPDIR 不包含宿主数据库路径、代理或密钥环境；系统还允许执行器自身的本空间容器访问。
- 标准 I/O 文件由 `stdin_file`、`stdout_file`、`stderr_file` 显式声明，仅限沙箱入口；路径必须在实际工作目录内、父目录已存在，不允许符号链接、路径穿越、重复流目标或另一空间私有文件。stdin 先冻结为本次数据文件；stdout/stderr 分别暂存完整原始字节，模型只拿有界摘要，成功退出后才发布到指定文件。`output_mode=create` 默认原子拒绝覆盖；`overwrite` / `append` 逐次硬确认，发布前核对旧内容，目标已变化则拒绝替换。任何 I/O 调用都不复用本轮/持久授权或自动审核。只读程序的重定向仅把输出文件列为写目标，不增加工作目录写授权；其他程序仍需目录写授权。输入、每份暂存输出及追加后的最终文件均最多 64 MiB；重定向执行同时施加不可抬高的常规文件大小限额。非零退出、超时、取消不主动发布暂存输出，程序自身已获准的工作区写不回滚。每个文件独立原子发布，多输出间没有事务保证，部分发布失败需如实列出已发布文件，不能自动重试。
- 管道、重定向、变量/命令展开和后台脚本不属于沙箱单命令语法；需要宿主功能时显式指定 `execution_mode=host`。该入口仅限完全权限模式、每次硬确认，不能复用本轮或持久批准，也不能用于绕过沙箱拒绝。它仍使用 zsh 和宿主权限，工作目录只决定相对路径起点。任一沙箱步骤失败都不自动回退宿主。
- 沙箱 Shell、Python、包安装执行前均把自己的进程数软/硬限制降为零，禁止 fork/posix_spawn。Shell 中需要派生程序的命令也会失败；不为兼容命令隐式解除限制。`/usr/bin/git` 的 xcrun 跳板在宿主侧解析为实际开发工具 git，再用于执行与授权身份；原有 fsmonitor、外部 diff 和仓库发现范围硬化保留。
- Shell 授权分两层：
  - **本轮授权**：只对已核对工作区范围且不带 I/O 文件的静态只读命令提供；绑定结构化参数、可执行身份、实际目录、空间、工作区与策略版本。解释器、任意可执行文件和会加载项目脚本的命令逐次确认；单次执行身份校验不授予复用资格。记录只属于本轮运行，不跨轮。
  - **持久精确规则**（确认卡上的「记住…」）：按空间存入 `shell-approval-rules.json`，绑定完整命令身份、目录与空间，设有有效期。只接受无展开的单条调用，命中后直接执行解析后的绝对路径和 argv，不再次交给 Shell 解释。程序、脚本、参数或目录变化后旧规则失效；旧版规则仅展示，需重新授权。可在设置中逐条撤销或按空间清空。规则库通过独立 `.lock` 文件串行读改写，加锁失败不放行。
- 高风险命令（`sudo`、删除系统路径、磁盘与系统配置、钥匙串操作等）逐次硬确认，不受本轮授权与持久规则任何一层影响；只读动词读取系统路径（如 `ls /private/tmp`）不升级为硬确认。
- 无头上下文（守护进程）不复用本轮 Shell 授权或持久命令规则；静态只读的沙箱单命令可按确定性规则执行。写命令、显式宿主及复合脚本保留人工确认。
- 各空间各有一个签名的统一离线执行器，Shell、Python、技能和包解析共用本空间的 App Sandbox 容器。两个执行器均无网络权限，只有基础运行时和本空间 venv 的只读静态例外。宿主启动前验证签名、团队、标识和完整权限白名单，Release 拒绝可调试执行器。固定包解析程序可申请较大的 wheel 文件限额，执行器按程序、参数、空间目录与授权范围核对用途，普通脚本不能借此上调限额。准备进程把业务输入换成本执行器身份的只读书签后退出。最终进程只接收获准书签，通过匿名描述符读取请求，改接数据 stdin 并原位执行；超时和取消继续监控同一 PID。
- App Sandbox 不支持动态减去已授权父目录中的子路径；遇到另一空间等禁止目录时，只向准备进程传入安全子项，不授予其父目录或跟随其中的符号链接。目录过宽、签名、授权或沙箱失败均停止，不回退兼容执行器。最终执行进程把自己的 `RLIMIT_NPROC` 软、硬限额均降为零，禁止 fork/posix_spawn；不改变宿主或其他 App 的限制。宿主环境变量不直接继承。App Sandbox 还允许自身隔离容器和系统基线访问，不能承诺操作系统层面只允许写 `output/`；业务产物仍要求写显式产物目录。
- 产品空间入口不调用 `sandbox-exec`，也不在 App Sandbox 内嵌套 Seatbelt；macOS 会拒绝这种嵌套。SPM 的显式受控测试入口仍可单独验证旧 Seatbelt 策略，空间产品入口始终要求完整签名 App。
- `skill_run_script` 只执行技能包内通过校验的 Python 文件。执行前冻结包目录，保留相对资源和导入布局；只把本轮修改的 `scratch/` 常规文件通过安全写入器发布回技能库。包内符号链接、不可读资源和摘要变化均失败关闭。本轮授权绑定整个输入包和环境修订号，不写持久池。
- SQL 在绑定库上预编译并校验参数后按实际语句判定读写；任何未能证明只读的调用保持确认，只读查询也要限制结果行数和输出大小。
- 子进程标准输出与错误输出应持续抽取，避免管道写满造成死锁。
- `ChildProcessRunner` 用独立串行队列拥有非阻塞读取和最终快照；进程退出后先停新事件，再收齐在途读取，避免短命令已经读到的数据尚未追加就被遗漏。单次排空有上限，持有管道的后台后代不能阻塞收尾。

## 副作用分类与守护恢复

每个工具声明副作用分类（`readOnly` / `idempotentWrite` / `nonIdempotentWrite`，默认取最保守的非幂等写；只读工具显式声明）。

守护进程为每个接管任务建立执行日志：非只读工具执行前落 intent、执行后落回执（原子替换，脱敏保存）。恢复规则：

- 有回执：复用保存结果，不重新执行。
- 只有 intent：结果不确定，该任务进入「需人工恢复」，不自动重放。
- 顶层纯只读调用不入副作用日志；恢复仍须有完整工具调用检查点、原预算和当前权限。嵌套子代理目前没有独立持久日志，不能仅凭内层工具声明为只读就自动续跑。

`AgentTool` 外层调用先写 intent。直接委派与通过 `tools_invoke` 发起的委派使用相同的结构化结果。子代理运行中，每个工具批的内层检查点随父记录原子保存。子运行正常结束后若父回执或消息尚待写回，Daemon 核对原始调用、实际工具参数、空间、会话和子运行身份，再补齐这次委派的结果。其余未决操作保留现场，交人工核实。后续阶段见[子代理恢复设计](design/2026-daemon-nested-agent-recovery.md)。

守护进程只挂载自己确实支持的能力：浏览器（依赖 WebKit 会话与用户登录态）、屏幕捕获与麦克风转写等依赖前台授权的能力被显式排除，避免系统提示公布的工具在实际执行时失败。

## 浏览器工具

浏览器区分任务授权和单次执行身份。普通顶层链接由宿主按已读取的真实 URL 原生导航，不派发页面点击处理程序；用户可选择本任务内复用同一空间、标签和准确来源（协议、主机、端口）的导航授权。同源导航或重读不撤销该授权，但每次操作仍要求新的页面观察；跨来源访问、关闭标签和 WebContent 终止撤销相关授权，返回旧来源也不能恢复。

宿主另外识别两类结构化交互候选：绑定现有区域的 ARIA 菜单/页签控件，以及同源、无敏感字段、无覆盖目的地的 GET 搜索表单。菜单控件可以获得本任务内的同源控件授权；查询授权绑定表单的目的地址、方法、页面路径及字段结构。它们保留外部副作用分类，网页标签、角色及事件处理器不构成只读证明。已知危险目标、POST、跨源查询、脚本链接、普通未知按钮和业务提交逐次硬确认，不继承上述授权。候选可进入无工具模型审核，核对原始用户请求、目的地址、实际表单条件及冻结执行身份；证据缺失、截断、审核失败或不确定转人工。任意脚本及填表不进入自动审核。当前为通用结构适配，没有声明已验证某个真实 OA 站点。

`browser_fill` 一次批准同一表单、同一 frame 的完整顺序填写计划，展示字段名与实际值。普通步骤使用已观察的 `element_id`；依赖选项或启用状态的步骤可声明 `wait_for_ready=true`；之后才出现的字段使用精确 `field_name`、`wait_for_ready=true` 和已观察的 `form_element_id` 锚点。后续字段只在该表单中按精确名称唯一定位，敏感、歧义或越界字段拒绝。每步等待有界、可取消，整体计划也有截止时间。输入事件可能远端保存，因此计划只消费一次，不提供整站写权限或自动重放；成功后重新读取，部分失败明确已完成字段及当前步骤的派发状态。提交始终另行确认。

页面校验使用操作相关属性、真实表单目的地和业务值，而非整个表单的 HTML；class、style 等装饰变化不撤销操作，业务值、目的地或对象改变则停止。敏感值和完整签名只留在隔离脚本环境。引擎在权限复核前冻结执行身份，复用任务授权也不能在检查结束后换成新页面动作。确认后表单值变化不能提交。点击回执区分已派发与结果核验；等待失败不能据此自动重放。网站自身对话框仍需明确处理。

`browser_read` 提供普通链接 URL、字段值、勾选状态、下拉选项与可选 `element_id` 定向表单检查，减少任意脚本读取；不额外披露动作链接或带凭据的 URL。页面内容始终是不可信参考资料。

浏览器专用确认卡按 Core 的结构化事实展示站点、页面、目标、目的 URL 或完整填写计划；候选授权类型和自动审核转人工原因使用三语文案。授权选项仍只由统一审批器提供，旧快照缺少结构化事实时沿用原有展示。普通重读只更新执行身份，不自动重授任务权限。

浏览器工具实现于 UI 层，因为它们操作 WKWebView。它们通过 `DispatcherTool` 接口注入 Core 引擎，包括标签管理、打开、读取、点击、填表、截图、滚动和 JavaScript 执行。

网页内容是不可信外部输入。读取页面后进入模型时保留数据边界；点击、填表和脚本执行仍遵守确认与用户可见性策略。标签和 WebContent 进程需要资源上限，不能无限增长。

## 技能对工具面的影响

技能 frontmatter 中的 `allowed-tools` 只能收窄当前运行可见的工具集合。引擎同时在暴露工具定义和实际执行处检查，避免模型通过构造未暴露调用绕过限制。空声明或解析异常不得自动扩大权限。

## 设计原生桥接能力

网页、脚本和 AI 生成代码无法自行获得 EventKit、通知、麦克风、屏幕采集等宿主权限。新增桥接时：

1. 先由原生服务持有权限和生命周期。
2. 暴露最小、结构化的工具接口。
3. 在接口层定义确认、作用域、超时和错误语义。
4. 不向脚本下放通用宿主控制或隐式权限。

## 修改检查

新增或修改工具时至少检查：Schema 与解析一致、无效 JSON、确认分级、空间归属、路径穿越、输出上限、取消与超时、日志脱敏、子代理可见范围，以及工具调用与结果消息的 ID 配对。


## 产品侧展示边界

确认摘要仅解释工具的实际参数，不能成为另一套执行或授权入口。每次工具调用使用独立的 `ToolArtifactCapture`：文件写入、编辑、复制、重命名和移动从实际发布位置登记，批量编辑在整组成功应用后登记，团队写在审批与写入回执完成后登记；Python 和技能脚本从本次独立输出目录发现常规文件；Shell 标准流只登记成功发布的实际目标。不从模型自然语言或打印的路径猜测成果，子代理转发完整的多成果与知识来源元数据。批量编辑的成果保存失败不会隐式回滚已经成功应用的文件，团队写也不会因此把已应用快照改成写入失败。

可写 Shell 在已批准工作目录内比较执行前后的文件身份、大小及修改时间，仅保留新建或变化的普通文件。该记录明确是运行期间观察到的变化，不能证明没有其他同时发生的编辑。`artifact_paths` 可把发现限定到预期输出文件或目录，不赋予任何新增读取、写入或执行授权；省略时检查整个工作目录。预检超出条目数或深度上限时在执行前失败，提示缩小发现范围；执行后发现失败则保留已经完成的操作并提示检查现有输出，不自动重放。链接、特殊文件和另一空间私有目录排除。静态只读命令不扫描普通文件变化，显式标准流输出仍按发布回执保存。

已确认进程结束的 Python、技能脚本和 Shell 即使非零退出，也登记已经产生的部分文件；结果不确定时不把仍可能变化的文件当作完成快照。每份可保留内容与来源在所属空间事务中落盘，单文件和单次操作总内容均有上限，超限保留来源并明确标识没有历史内容。版本保存失败说明真实产物位置和不得重做，不能宣称操作未执行。日志回放从同一运行与工具调用的已保存版本恢复元数据，不重新执行。不可把版本预览目录作为模型文件权限的入口。

邮件 `mail_read` 仍只返回正文和附件元数据。附件二进制下载是用户在邮件详情显式选择的独立操作，不在正文读取或同步时隐式下载；沿用同空间账号租约、连接超时及缓存服务，不扩大智体工具的读写范围。

## Shell 持久授权（结构化规则）

Shell 在确认前校验执行模式、单命令结构、工作目录、程序解析及标准流字段类型。缺少程序、不支持的管道/复合语法与工作区内不可用的宿主入口直接返回失败，不让用户先批准再发现调用无效；此阶段不创建目录或启动执行器。实际执行重用同一校验，文件流、目录身份与权限守卫仍在执行阶段复核。

静态只读规则支持 `rg --files`、字面 glob/type/regexp 和有界计数/上下文选项，以及 Git 常见的 `--stat`、`--name-only`、`--oneline` 等展示形态。`rg` 强制关闭配置，不放行预处理、解压、跟随链接、额外配置/模式文件或未知选项。Git 保留仓库围栏、fsmonitor/pager 硬化和外部 diff/textconv 禁用；使用 `--` 路径分隔符时，安全选项插在分隔符之前。固定系统 `sed` 只接受 `-n Np FILE` 或 `-n N,Mp FILE`。系统 `grep` 支持受限递归、正则和 `--include` 文件名过滤，递归时跳过符号链接。未能核验的检索或按行读取参数返回工具错误，模型可改用 `repo_search` 或 `files_read_range`。

识别、执行与授权共用可执行文件解析。仅 `rg` 增加已知 Homebrew/MacPorts 安装位置，不继承或扩大用户 PATH；安装链接解析为实际程序后核对身份，同名替身不能获得只读资格。安装升级后重新解析，不能继续使用旧路径身份。

- 持久规则不再是“只看程序名前缀”。规则绑定可复用白名单内的可执行身份、完整 argv、实际工作目录、空间/工作区、固定 PATH、策略版本和有效期；解释器及项目脚本不生成复用规则，单次批准仍检查入口身份。
- `source`、`env`、`command`、`nohup`、`cd`、环境赋值、命令替换、反引号、转义、未闭合引号和未知语法都不会生成或匹配持久规则；无法完整解释的调用转人工。
- 旧规则保留展示并标记“需要重新授权”，不自动转换。
- 规则命中后直接执行解析后的绝对路径与 argv，并固定 PATH；首次人工批准的同类单条调用使用同一执行方式。
- 规则文件读写使用独立串行队列，并在稳定的 `.lock` 文件上用 `flock` 跨实例保护，避免多实例覆盖。
- 只读快速通道拒绝 `find -L`，并在执行 git 前检查 `.git` 文件指向的 gitdir / commondir 是否仍在工作区内；只读命令使用最小环境，不继承无关宿主配置。

## 原生应用生成入口

`apps_schema` 与 `apps_prepare` 由 UI 层仅在前台聊天组装时注入。前者按 core / python / example / current 章节按需返回 DSL、范例与当前定义，长内容通过 offset / next_offset 完整读取，模型在当前对话内生成完整 JSON；后者接收 `definition_json` 与可选 `app_id`，确定性校验后交给所属空间应用库预览和显式安装，不再发起嵌套模型请求。`apps_schema` 是只读；`apps_prepare` 将校验通过的定义保存为所属空间的内部待安装草稿，按内容和来源身份幂等去重。它与编码任务笔记采用相同的内部状态分级（`permissionClass = readOnly`、`sideEffectClass = idempotentWrite`），不授予业务写入、安装或执行权限；安装仍需预览中的用户显式操作。Daemon、定时任务没有这两个工具。小应用知识发布、私有记录写入与应用文件变更经 `DispatcherEngine.executeCommand` 使用共用确认与执行路径，不能直接调用工具的 `execute` 绕过确认。工作区命令捕获固定安装身份、内容、修订号或文件摘要；不提供自由 SQL、工具名或外部路径能力。当前支持面和扩展约束见 [11-原生小应用](11-原生小应用设计.md)。

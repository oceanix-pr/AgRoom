# 目标执行

目标执行将一份用户认可的目标关联到多段普通调度运行。当前实现 App 内的持续执行、用量统计、检查点、人工逐项验收、执行检查门槛、暂停结束及重启核对；独立语义验证和退出后的目标级续跑仍是后续阶段。

## 用户流程

聊天输入区常驻「目标」开关。选中后直接在原输入框填写文字，按发送或回车即可将这段文字设为目标并开始，不再要求弹窗；发送前显示目标状态，发送成功后清空已提交的原草稿并恢复普通对话，失败时保留输入。待设定状态不跨会话继承，离开聊天页时也退出；迟到的创建回执不能清空另一会话或后来编辑的草稿。目标模式目前只提交文字，有待发附件时提示先处理附件并阻止提交，不丢弃附件。

「更多选项 → 目标高级设置」仍可打开原生编辑器。默认只需描述预期结果，名称从目标首行自动生成，不配置目标预算。名称、自定义逐行验收标准、执行检查和补充约束收进「高级设置」；未填写独立标准时，以「达到上述目标并核对实际成果」作为人工验收项，不缩减原始目标内容。查看当前空间、工作区和权限后开始；恢复目标时自动展开高级设置供核对原始要求，目标定义保持只读。开始后允许持续执行，具体工具继续遵守原有权限与审批。从高级编辑器开始时，未发送的聊天草稿和附件保留。

普通前台主对话可通过 `goal_draft` 返回绑定来源空间、会话和工作区的草稿卡；它不写目标表、不执行、不授予权限。用户预览并明确开始才创建目标。同一草稿不能重复创建目标，旧会话或另一空间的回执不可用。

会话顶部的目标卡显示状态、已记录用量和通过标准数；进入待验收时自动展开详情，核对每条标准、执行摘要和后续步骤，并逐项保存人工验收。「查看本段成果」定位最新执行段的回答。暂停、结束、保存重试和核对后继续都在此处操作。任务中心的「目标」入口按空间分页列出目标并打开来源会话；各次实际执行继续保留在原有运行历史和成果入口。

## 执行与验收

目标按钮从后台监控快照读取当前会话的占用状态。创建目标和启动下一段时，宿主会在后台重新读取持久交接记录，回来后核对发起空间与会话。已交接、归属不明或需要人工恢复的运行继续阻止启动。

`GoalCoordinator` 是 Core actor，只决定持久状态与下一段是否可执行。App 聊天宿主复用原有引擎组装、流式展示、工具确认和提问恢复，不增加第二条执行工具的通道。

- 每段有新运行 ID，目标 ID 保持不变；确认或提问后的原地恢复仍沿用该段 ID。
- 每个会话同时只有一条执行链。人工排队消息优先于自动续跑；普通用户轮会暂停未结束目标并使旧验收失效。
- 执行范围冻结空间、工作区及引用目录身份、项目/知识/记忆选择、权限与自动审核设置。自动续跑前重新核对，变化后暂停；明确继续时重新查看当前范围。
- 原始目标、约束和标准用于构造执行授权；模型生成的检查点只作为数据进入模型上下文，不可充当用户授权。
- `goal_checkpoint` 仅记录有界候选进度与后续步骤，或请求验收。它不修改目标定义、权限或完成状态，保留为技能限制下的内部记账能力。
- 各段直接发布 `goal_checkpoint`、`ask_user` 及本次任务常用的已注册工具。其余工具通过 `tools_search` 查定义、`tools_invoke` 调用，仍需经过当前空间、权限范围和逐次确认检查。
- 引擎通过结构化结束原因区分自然结束、步骤上限、预算、截止时间、连续失败与恢复异常；`.finished` 本身不代表目标完成。

人工标准必须由用户检查实际成果后逐项勾选。可选的执行检查门槛只在已有 `TaskCompletionAssessment.completed` 时通过，表示记录的代码检查或技能产物契约通过，不能代替语义验收。缺少证据、未评估、未验证和检查失败均不算通过。开始新执行段会撤销上段的验收票，验收回执绑定最新运行；所有标准通过后才标记成功。

## 用量与停止

目标不设累计 Token、工具调用、执行段数或总时限预算，单个执行段也不设置截止时间，不套用普通对话的一小时默认截止时间；普通委派的子代理继承该段无截止时间的上下文。新执行段使用既有引擎按模型容量与步数计算的独立执行保护，不继承普通对话的可选任务预算，也不把目标历史用量恢复为新段的已消费额度。单段达到内部 Token、工具或步数边界时，仍需根据检查点与新证据决定是否继续；模型容量、单次网络请求和工具超时、审批、取消和无进展保护继续生效。

每段只提交实际执行账本的用量，目标将其累计为统计，不据此决定可否运行。新目标和新回执不再写预算字段；旧目标 JSON 中的预算字段仅兼容读取，旧累计回执按原口径合并，避免重复累计。旧预留在恢复时计入历史估计量；新运行没有目标级预留。中断或服务未报告用量时明确标记统计不完整，不伪造精确费用。

执行历史按页读取，不以记录数限制续跑；重复回执按运行 ID 精确核对，不依赖某一页历史。计数使用防溢出的非负累加，数据校验不沿用旧版本的累计用量和执行段数上限。

连续段没有新的真实工具证据会达到无进展边界；模型改写摘要或重复提交检查点不算新证据。拒绝审批、取消提问、执行失败或缺少有效检查点会阻塞自动续跑。结束请求优先于迟到的模型完成，旧回调不能复活目标。

准备阶段也有目标身份：在引擎或执行段领取前取消，仍需提交暂停/结束状态。取消收尾的保存任务独立于被取消的执行任务，避免取消同时打断用量记录或让目标停留在待开始状态。

聊天结果成功保存后才提交目标终态并派发下一段。保存进行中显示准备状态并阻止发送、验收和并发重试；只有保存实际失败后才显示「重试保存」。任一保存失败时停止续跑，保留内存中的精确回执，提供「重试保存」；补存不调用模型、不重新执行工具。退出前未补存的内存回执不保证恢复，重启按用量不完整和人工核对处理。

流式进度按已加载页的持久消息序号定位，使用带运行身份、恢复版本及终态保护的原子单消息更新，不扫描整个会话，也不用较早的整会话快照覆盖最终回答。普通聊天与目标段共享此路径，延迟进度不能使已结束运行回到进行中。

## 数据与生命周期

`execution_goals`、`goal_attempts` 和 `goal_events` 位于所属空间数据库，关联会话删除级联清理。定义、当前验收和用量记录在目标记录中；执行段保留来源修订、运行 ID 与终态回执，正文、轨迹及文件版本复用既有任务和成果存储。多表变更使用事务和修订校验。

`Hub.makeGoalStore(for:)` 从指定空间连接现建服务，不缓存空间服务。聊天模型可以持有固定空间的协调器，迟到回调不能改用可变的当前空间。

完整备份包含目标及历史，便携数据移除目录身份和执行授权，恢复时重绑工作区、清除活动执行并暂停；目标中的历史消耗保留。旧包缺少目标表时继续兼容。恢复后的继续要求重新核对当前设备范围，不从备份恢复审批。

当前目标段不参与 Daemon 移交。关闭窗口但 App 仍驻留时可以执行；退出进程后不会派发下一段，重启只核对状态。现有普通对话单次运行的 Daemon 能力不等于目标级后台执行服务。

## 验证

`GoalTests` 使用隔离空间数据库、真实聊天宿主和模型协议夹具验证输入区目标模式提交、重复发送保护、会话切换、附件保留、仅填写目标时的创建与续跑、默认人工验收、无目标预算续跑、分段用量累计、逐项验收、旧票失效、单次领取、失败事务、重复回执、旧预留恢复、空间隔离、备份回退、审批拒绝及保存失败只补存。原生目标视图可通过 `AGROOM_GOAL_SNAPSHOT_DIR` 输出三语设置、恢复和进度卡窗口截图；不调用真实模型、不读取用户资料。

改动检查方式见 [构建、运行与测试](08-构建运行与测试.md)。协议夹具不能证明远端模型的真实成功率；独立语义验收、目标级后台执行与其故障恢复尚未实现。
